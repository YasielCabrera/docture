Opt-in field citations for text extraction. `llm({ model, citations: true })`, `createLlmExtractor({ llm: { citations: true } })` and `new LLM(model, { extraction: { citations: true } })` show the document to the model as lines with canonical `p<page>-line-<n>` IDs and ask for `{ data, citations }`. Each present leaf of `result.data` then gets one `FieldCitation` in `result.citations`: `verified` when the value was found in the cited lines (with `ids` narrowed to exactly the lines the match spans), `cited-unverified` when the lines exist but do not show the value, or the caller's schema changed it, and `uncited` otherwise. `result.citationSources` lists the cited `SourceLine`s with their boxes. Verification is exact: strings after NFKC and whitespace collapsing, numbers after currency, grouping and parentheses, and ISO dates against unambiguous printed dates only, so `05/03/2024` stays `cited-unverified`. An ID the request never showed is not evidence. Array indexes are rebased across `paginate` and `concatenate` merges, caller refinements and transforms still run, and a cached answer is validated and verified again on every hit. Citations add prompt and output tokens, and long tables can make an answer truncate. Vision extraction and documents without positioned lines are never cited, and with citations off every request is unchanged. New types: `FieldCitation`, `CitationStatus`, and, for custom strategies, `OutcomeCitation` on `StrategyOutcome.citations` and the `data` variant of `RepairInput`.

`docture extract --citations --full` adds `citations` and `citationSources` to each result record, and `--full` now also adds `validation` and, when present, `conflicts`. `--citations` without `--full` is a usage error, and it warns when config strategies replace the model's.
