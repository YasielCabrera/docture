`@docture/synthetic/node` writes a corpus directory that `jsonlDataset` from `@docture/eval/node` reads. It needs the engines of the templates and renditions in the plan. The [corpus guide](/docs/synthetic/corpora) shows it in use.

## `@docture/synthetic/node`

### `writeCorpus`

```ts
writeCorpus<T>(directory: string, plan: CorpusPlan<T>): Promise<CorpusReport>
```

Renders every seed, scenario, and template once, verifies the digital rendering, derives each rendition, and writes the cases. Returns a `CorpusReport`. Throws `RangeError` when the plan produces duplicate case ids or `concurrency` is not a positive integer. When `signal` aborts, no further rendering starts and the call rejects with the signal's reason.

The directory holds `cases/<id>/` with the document, `expected.json`, `labels.json`, `sample.json`, and `case.json`. The root holds `manifest.jsonl`, `coverage.json` with case counts per scenario, template, family, rendition, and severity, `failures.jsonl`, and `corpus.json` with the plan, engine versions, dependency hashes, and file hashes. A rendering that fails verification fails its cases, not the batch.

Rerunning converges. Each case is keyed by its seed, scenario, template, rendition, `createdAt`, package version, observed peer versions, declared dependency hashes, and a fingerprint of schema, template, and scenario source. A case whose key and file hashes match is skipped. Each case lands by renaming a finished temporary folder. Changes to freshness inputs preserve case IDs.

### Dependency provenance

`dependencies` on the model and corpus accept named [`DependencyInputs`](/docs/synthetic/reference/models#dependencyinputs-and-dependencyvalue). The writer validates and snapshots them before changing corpus files. Record key order has no effect. Array order, byte content, and value types affect identity. Unsupported inputs throw `TypeError` before filesystem mutation.

`corpus.json.dependencies` contains `model` and `corpus` records of SHA-256 digests by input name, plus a combined `hash`. It stores no raw dependency values. The combined hash enters every case freshness key. Captured pool contents, catalogues, helper revisions, and asset bytes can therefore invalidate unchanged case IDs.

Observed engine versions come from the package's peer list, including Faker and AI. The writer resolves and reads package metadata without importing engine code. Missing peers appear as `null`. Caller-declared renderer aliases or pins stay in dependency inputs and cannot replace observed versions.

Function source fingerprints do not inspect closure values or imported helpers. Inputs omitted from `dependencies` remain invisible unless their source fingerprint changes.

### `digital`

```ts
digital(): RenditionSpec
```

The digital PDF as rendered.

### `scan`

```ts
scan(options: { readonly severity: number; readonly dpi?: number }): RenditionSpec
```

A flatbed scan rendition. `scanLq`, `photo`, and `fax` take the same options for the other built-in [degradation profiles](/docs/synthetic/reference/degrade#profiles).

### `scanLq`

A low-quality scan rendition.

### `photo`

A phone photo rendition with perspective, shadow, and motion blur.

### `fax`

A bilevel fax rendition.

## Types

### `CorpusPlan`

{/* options: CorpusPlan */}
| Field | Default | Meaning |
| --- | --- | --- |
| `model` | required | The `Model` to sample. |
| `dependencies` | none | External input values hashed into freshness and recorded as provenance. |
| `templates` | required | PDFKit, React, or other rendering templates. |
| `seeds` | required | Numbers or strings to sample with. |
| `scenarios` | `[]` | Scenarios to sample in addition to the base case. |
| `includeBase` | `true` | Include unvaried samples as scenario `base`. |
| `renditions` | `[digital()]` | `RenditionSpec` values to write for each rendering. |
| `concurrency` | `4` | Renderings in flight at once. |
| `verify` | `true` | Verify each digital rendering before writing it. |
| `createdAt` | fixed date | Written into every PDF and part of each case key. |
| `signal` | none | An `AbortSignal` that cancels the run. |

### `CorpusReport`

{/* options: CorpusReport */}
| Field | Type | Meaning |
| --- | --- | --- |
| `written` | `number` | Cases written in this run. |
| `skipped` | `number` | Cases whose key and file hashes already matched. |
| `failed` | `readonly { id: string; message: string }[]` | Cases that failed, with the reason. |
| `manifest` | `string` | Absolute path of `manifest.jsonl`. |

### `RenditionSpec`

```ts
type RenditionSpec =
	| { readonly kind: "digital" }
	| {
			readonly kind: "degrade";
			readonly profile: ProfileKey | Profile;
			readonly severity: number;
			readonly dpi?: number;
			readonly output?: "pdf" | "png" | "jpeg";
		};
```

One way to present each rendering. Build it with the helpers above, or write a `degrade` spec to use a custom `Profile` or image output.
