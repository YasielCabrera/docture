---
title: Synthetic data API reference
description: Public entry points for generation, rendering, verification, and corpora.
---

`@docture/synthetic` generates labeled documents from your extraction schema. Each document carries ground truth that is correct by construction: the value of every printed field, and the page and box where it is printed. Boxes use Docture's `LayoutBox` convention: PDF points, top-left origin, y down.

The root entry is portable and engine-free. Every other entry loads its engine on first use and throws `MissingEngineError` naming the package and range when it is absent. The [synthetic corpus guide](/docs/synthetic/quick-start) walks through a complete corpus.

| Entry | Purpose | Engines |
| --- | --- | --- |
| `@docture/synthetic` | Models, generators, constraints, scenarios, printed masks, templates, tables, formatting, `toEvalCase` | none |
| `@docture/synthetic/pdfkit` | Render a template to PDF with field boxes | `pdfkit` |
| `@docture/synthetic/verify` | Read a digital PDF back and confirm every label | `pdfjs-dist` |
| `@docture/synthetic/measure` | Measure the text lines of a PDF and how far a template's text drifts from a reference PDF | `pdfjs-dist` |
| `@docture/synthetic/degrade` | Scan, low-quality scan, photo and fax renditions with transformed boxes | `sharp`, `pdfjs-dist`, `@napi-rs/canvas`, `pdfkit` for PDF output |
| `@docture/synthetic/node` | Write a resumable corpus that `jsonlDataset` reads | the engines of the renditions in the plan |
| `@docture/synthetic/faker` | Seeded, locale-aware values from Faker | `@faker-js/faker` |
| `@docture/synthetic/html` | HTML and CSS templates printed by Chromium | `playwright-core` and a Chromium build |
| `@docture/synthetic/llm` | Model-written text pools, cached for offline rebuilds | `ai` |
