`writeCorpus` renders many seeds, scenarios, and templates into a directory of verified cases that `@docture/eval` reads. Install the [degradation engines](/docs/synthetic/degradation) for scanned renditions.

For the CLI commands on this page, complete the [CLI quick start](/docs/cli/quick-start) to install the executable in your project.

## Write cases

This example imports `model` and `template` from `bill.mts`, which the [quick start](/docs/synthetic/quick-start#define-the-model-and-template) defines.

```ts
import { digital, scan, writeCorpus } from "@docture/synthetic/node";
import { model, template } from "./bill.mjs";

const report = await writeCorpus("corpus", {
	model,
	templates: [template],
	seeds: [1, 2],
	renditions: [digital(), scan({ severity: 0.4, dpi: 150 })],
	createdAt: "2025-11-01T00:00:00Z",
});
console.log(report.written, report.skipped, report.failed);
```

`templates` can mix [PDF](/docs/synthetic/pdf-templates) and [React templates](/docs/synthetic/react-templates). A fresh run writes four cases. Each seed, scenario, and template renders once; verification precedes derivation of its renditions. `includeBase` defaults to true, renditions to digital only, concurrency to 4, and verification to true. `signal` cancels work.

Each `cases/<id>/` contains its document, `expected.json`, `labels.json`, `sample.json`, and `case.json`. The root contains `manifest.jsonl`, `coverage.json`, `failures.jsonl`, and `corpus.json` with plan, engine versions, dependency hashes, and file hashes. Verification failure fails that rendering's cases rather than stopping the entire batch.

## Declare external inputs

Pass captured values through `dependencies` so a change invalidates saved cases. Use model dependencies for generation tables, pool contents, and rule revisions. Use corpus dependencies for assets and renderer inputs.

```ts
const report = await writeCorpus("corpus", {
	model,
	templates: [template],
	seeds: [1, 2],
	dependencies: {
		customers: customerPool,
		logo: logoBytes,
		renderer: "invoice-renderer-v2",
		rules: "billing-policy-2",
	},
	createdAt: "2025-11-01T00:00:00Z",
});
```

Supply JSON values or `Uint8Array` bytes. The writer validates and snapshots declared inputs before changing corpus files. It sorts record keys, preserves array order, and distinguishes bytes from numeric arrays. Equivalent declarations skip existing cases. Changed values rewrite the same case IDs. `corpus.json` stores per-input hashes and a combined hash, rather than raw dependency values.

Keep helper revisions explicit when imported code changes without changing a generator's function text. The writer cannot discover arbitrary closure inputs.

## Reproduce a corpus

Cases whose key and file hashes match are skipped. An interrupted run can complete missing cases. Keys include seed, scenario, template, rendition, date, package version, source fingerprints, declared dependency hashes, and observed peer versions. The writer records installed peer versions, including Faker and AI, through package metadata without importing their engines. Missing peers appear as `null`. Record aliased renderer pins in `dependencies`; those declarations do not overwrite observed versions.

Persist structured and text pools for offline rebuilds. Use explicit cache-only sources to prohibit new structured generation. Undeclared external inputs remain invisible to freshness checks, so declare them or rebuild into a fresh directory after changing them.

## Use the CLI

Define `docture.synth.ts` with `defineSynthConfig`. It accepts model, templates, scenarios, seeds, renditions, output directory, `createdAt`, and corpus `dependencies`. The CLI forwards dependencies to the writer.

| Command | Result |
| --- | --- |
| `npx docture synth list` | Lists templates, scenarios, and rendition profiles |
| `npx docture synth gen --seed 7` | Prints sampled values as JSON |
| `npx docture synth render --seed 7 --out bill.pdf` | Writes a PDF and `bill.pdf.labels.json` |
| `npx docture synth corpus --seeds 1-40 --renditions digital,scan:0.3,photo:0.6` | Writes the corpus and manifest |
| `npx docture synth verify corpus` | Verifies digital cases |

`render` and `corpus` accept template and scenario selectors and `--no-verify`. Rendition selectors are `digital` or `scan`, `scan-lq`, `photo`, and `fax` with a severity, such as `photo:0.6`. Commands exit 0 on success, 1 for a failed rendering or verification, and 2 for a usage error. See [command reference](/docs/cli/commands).
