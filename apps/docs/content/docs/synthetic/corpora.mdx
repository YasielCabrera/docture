`writeCorpus` renders many seeds, scenarios, and templates into a directory of verified cases that `@docture/eval` reads. Install the [degradation engines](/docs/synthetic/degradation) for scanned renditions.

## Write cases

This example imports `model` and `template` from `bill.mts`, which the [quick start](/docs/synthetic/quick-start#define-the-model-and-template) defines.

```ts
import { digital, scan, writeCorpus } from "@docture/synthetic/node";
import { model, template } from "./bill.mjs";

const report = await writeCorpus("corpus", {
	model,
	templates: [template],
	seeds: [1, 2],
	renditions: [digital(), scan({ severity: 0.4, dpi: 150 })],
	createdAt: "2025-11-01T00:00:00Z",
});
console.log(report.written, report.skipped, report.failed);
```

`templates` can mix [PDF](/docs/synthetic/pdf-templates) and [React templates](/docs/synthetic/react-templates). A fresh run writes four cases. Each seed, scenario, and template renders once; verification precedes derivation of its renditions. `includeBase` defaults to true, renditions to digital only, concurrency to 4, and verification to true. `signal` cancels work.

Each `cases/<id>/` contains its document, `expected.json`, `labels.json`, `sample.json`, and `case.json`. The root contains `manifest.jsonl`, `coverage.json`, `failures.jsonl`, and `corpus.json` with plan, engine versions, and file hashes. Verification failure fails that rendering's cases rather than stopping the entire batch.

## Reproduce a corpus

Cases whose key and file hashes match are skipped. An interrupted run can complete missing cases. Keys include seed, scenario, template, rendition, date, package version, and source fingerprints. Function source fingerprints cannot detect changes to captured constants or external assets. Change `createdAt` or rebuild into a new directory after editing those inputs. Persist model text pools for offline rebuilds.

## Use the CLI

Define `docture.synth.ts` with `defineSynthConfig`. It accepts model, templates, scenarios, seeds, renditions, output directory, and `createdAt`.

| Command | Result |
| --- | --- |
| `docture synth list` | Lists templates, scenarios, and rendition profiles |
| `docture synth gen --seed 7` | Prints sampled values as JSON |
| `docture synth render --seed 7 --out bill.pdf` | Writes a PDF and `bill.pdf.labels.json` |
| `docture synth corpus --seeds 1-40 --renditions digital,scan:0.3,photo:0.6` | Writes the corpus and manifest |
| `docture synth verify corpus` | Verifies digital cases |

`render` and `corpus` accept template and scenario selectors and `--no-verify`. Rendition selectors are `digital` or `scan`, `scan-lq`, `photo`, and `fax` with a severity, such as `photo:0.6`. Commands exit 0 on success, 1 for a failed rendering or verification, and 2 for a usage error. See [command reference](/docs/cli/commands).

Next, [evaluate the corpus](/docs/synthetic/evaluation). See [corpus API options](/docs/synthetic/reference/node).
