---
title: Migrate to the two-package release
description: Replace scoped integration packages and move model imports out of the root.
---

This release consolidates the library into `docture`, with `@docture/cli` as the second
published package. It changes import paths and engine installation. Extraction,
conversion, classification, splitting, OCR, evaluation, and testing APIs remain available.

## Replace the removed scoped packages

Remove the old integration dependencies:

```sh
npm uninstall @docture/core @docture/llm @docture/loader-pdfjs @docture/loader-mupdf @docture/loader-tesseract @docture/loader-paddleocr @docture/raster-canvas @docture/eval @docture/testing
```

For a PDF.js and OpenAI application, install:

```sh
npm install docture pdfjs-dist@6.2.108 ai@^7 @ai-sdk/openai zod@^4
```

Use the [installation recipes](/docs/guides/installation) for other adapters or testing
peers. The old scoped package paths are not aliases supplied by the new `docture` package.

Replace imports according to this mapping:

| Previous import | Replacement |
| --- | --- |
| `@docture/core` | `docture` |
| `@docture/llm` | `docture/llm`, or a narrow entry such as `docture/llm/text` |
| `@docture/loader-pdfjs` | `docture/loaders/pdfjs` |
| `@docture/loader-mupdf` | `docture/loaders/mupdf` |
| `@docture/loader-tesseract` | `docture/loaders/tesseract` |
| `@docture/loader-paddleocr` | `docture/loaders/paddleocr` |
| `@docture/raster-canvas` | `docture/raster/canvas` |
| `@docture/eval` | `docture/eval` |
| `@docture/testing` for doubles | `docture/testing/doubles` |
| `@docture/testing` for conformance | `docture/testing/conformance` |
| `@docture/testing` for PDF fixtures | `docture/testing/fixtures` |
| `@docture/cli` | `@docture/cli` |

## Move model imports out of the root

The root `docture` entry now exports core only. Move `LLM`, `model`, strategies, splitters,
and model utilities to their documented subpaths.

Replace the previous combined root import with:

```ts
import { contract } from "docture";
import { Extractor } from "docture/node";
import { LLM } from "docture/llm";
import { DocumentLoaderPdfJs } from "docture/loaders/pdfjs";
```

For text extraction without the convenience backend:

```ts
import { Extractor } from "docture/node";
import { llm } from "docture/llm/text";
import { fileCache } from "docture/llm/cache";
import { DocumentLoaderPdfJs } from "docture/loaders/pdfjs";
import { openai } from "@ai-sdk/openai";

const extractor = new Extractor({
	loaders: [new DocumentLoaderPdfJs()],
	strategies: [llm({ model: openai("gpt-5"), cache: fileCache(".docture-cache") })],
});
```

The [package reference](/docs/reference/packages#public-entry-points) lists every narrow
entry, including vision, classifier, layout, split, extractor, prompt, pricing, merge,
and schema relaxation.

## Install selected engines explicitly

An adapter's third-party engine is now an optional peer. Importing the adapter still
requires that peer at runtime, and TypeScript consumers can need its declarations.
Install a version in each engine's [supported range](/docs/reference/packages#engine-versions).
If an adapter's engine is missing, its first use throws `MissingEngineError` (`MISSING_ENGINE`)
with the package and range to install. Model integrations need `ai@^7` and Zod 3.25.76 or
later 3.x, or Zod 4.1.8 or later, plus the provider you construct.
Installing `docture` alone requests no engine. Installing `@docture/cli` still brings its
required AI SDK and PDF.js dependencies and attempts its optional canvas dependency.

The OCR engines are exact peers: `tesseract.js@7.0.0`, `ppu-paddle-ocr@6.3.0`, and
`onnxruntime-node@1.27.0`. The previous OCR packages kept these engines as their own
dependencies. If your application already depends on another release of one of them, npm
now refuses to install `docture`, even when you use only core APIs. If it depends only on
`@docture/cli`, npm instead installs the pinned release as a second copy under
`@docture/cli`, about 270 MB for `onnxruntime-node`. For core and non-OCR entries, one npm
override fixes both cases. Add an entry for each such package:

```json
{
  "overrides": {
    "docture": {
      "onnxruntime-node": "$onnxruntime-node"
    }
  }
}
```

The OCR adapters stay supported only at the pinned versions. See
[applications with their own OCR engine](/docs/guides/installation#applications-with-their-own-ocr-engine).

Separate the testing imports so test doubles do not load PDFKit or Vitest:

```ts
import { fixedStrategy, inMemoryLoader } from "docture/testing/doubles";
import { describeLoaderConformance } from "docture/testing/conformance";
import { makeInvoicePdf } from "docture/testing/fixtures";
```

The conformance entry needs Vitest 3 or newer and PDFKit. The fixtures entry needs PDFKit.

## Check CLI invocations and bundle assumptions

Install the CLI before using its binary:

```sh
npm install --save-dev @docture/cli
npx docture --help
```

For a one-off run, use
`npx --package @docture/cli docture` so npm selects the package that owns the executable. Update imports in
`docture.config.ts` using the same mapping as application code.

All Docture wrappers now arrive in one tarball. Optional peers isolate engine installs;
narrow ESM imports let a production bundler remove unrelated modules. A used `LLM` class
can retain the implementations its methods reference. Unbundled Node dependencies are
not pruned. See [bundling and download size](/docs/reference/packages#bundling-and-download-size)
for the limits of tree shaking.

## Update loader names and constructed records

Loader entries now expose one class and one matching options type. Replace the old
aliases and `Config` names with these canonical exports:

| Entry | Removed names | Class | Options type |
| --- | --- | --- | --- |
| `docture/loaders/pdfjs` | `PdfJsLoader`, `PdfJsConfig`, `PdfJsLoaderOptions` | `DocumentLoaderPdfJs` | `DocumentLoaderPdfJsOptions` |
| `docture/loaders/mupdf` | `MuPdfLoader`, `MuPdfConfig`, `MuPdfLoaderOptions` | `DocumentLoaderMuPdf` | `DocumentLoaderMuPdfOptions` |
| `docture/loaders/tesseract` | `TesseractJsLoader`, `TesseractConfig`, `TesseractJsLoaderOptions` | `DocumentLoaderTesseract` | `DocumentLoaderTesseractOptions` |
| `docture/loaders/paddleocr` | `PaddleOcrLoader`, `PaddleOcrConfig`, `PaddleOcrLoaderOptions` | `DocumentLoaderPaddleOcr` | `DocumentLoaderPaddleOcrOptions` |

The root export `loadDocument` is now `readDocument`. It takes the same arguments.

| Entry | Removed name | Replacement |
| --- | --- | --- |
| `docture` | `loadDocument` | `readDocument` |

Custom code that constructs `Attempt` records must supply `stage`: `load`, `classify`,
`extract`, `repair`, or `layout`. Keep `strategy` as the component name.

Custom CLI `Io` implementations must supply `stdoutColor` separately from `color`.
Use the stdout terminal capability for `stdoutColor` and the stderr capability for
`color`. `NO_COLOR` and `--no-color` disable both streams.

For custom OCR rasterizers, `maxPages` caps source page numbers, rather than the number
of returned rasters. With `maxPages: 3`, a sparse response containing pages 2 and 5
runs OCR only on page 2. Selected pages remain unique and in document order.

## Move local files to the Node entry

The root now loads in browsers and workers. Code that passes a path or file URL imports its constructors from `docture/node`, or passes `sourceResolver: resolveNodeSource` from that entry. Raw bytes, HTTP URLs and loaded sources keep their portable root imports. The Node entry reuses core modules and error identities. It performs no resolver registration at import time.
