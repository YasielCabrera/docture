---
title: Chunk documents for retrieval
description: Split converted documents into chunks that cite their pages and boxes.
---

`chunkDocument()` from `docture/chunk` splits a converted document into retrieval chunks.
Each chunk keeps the page number, bounding box, and source IDs of the elements it holds,
so an answer built from a chunk can point back to the PDF region it came from.

## Choose a budget

The budget counts `characters` or `estimatedTokens`. One estimated token is four
characters, with the count rounded up. It is not a tokenizer's count. Pick a `max` below
your embedding model's limit to leave room for that difference. The budget is soft in one
case only. A chunk exceeds `max` when it holds a single unit larger than `max`: one
element, or one table row group with its header rows, plus the heading path when
`headingPath` is set. Elements are never cut.

```ts
import { chunkDocument } from "docture/chunk";

const chunks = chunkDocument(result, { budget: { unit: "characters", max: 2000 } });
console.log(chunks[0]?.text, chunks[0]?.provenance[0]?.pageNumber);
```

## How elements are packed

- Chunks hold whole elements in reading order, and each heading starts a new chunk. A
  heading that does not fit with the element after it becomes a chunk of its own.
- A table larger than the budget splits between rows. Every piece repeats the header rows,
  and rows joined by a row span stay together. Pieces are sized with the heading path in
  front when `headingPath` is set. Each piece cites only the pages of its rows. A table
  without `rowProvenance`, such as one in a saved version 1 document, cites the whole
  table in every piece.
- A table or paragraph that [continues across pages](/docs/guides/document-conversion#tables-and-paragraphs-across-pages)
  cites every page it covers.
- Figures, page breaks, and running headers and footers add no chunk text.

Body text appears in one chunk only. `overlapElements: 1` repeats the last element of the
previous chunk at the start of the next when both fit the budget, and drops the repeat
when they do not. `headingPath: true` starts each chunk with the
headings it sits under, one per level, outermost first. A heading replaces every heading at
its level or deeper, so an earlier sibling section never appears in the path. Repeated header rows and heading paths are context and do not add
provenance.

## Stable IDs

Chunk IDs come from the element IDs, table row ranges, and options. Converting the same
file with the same loader and options gives the same IDs, so you can update an index in
place. A saved JSON document read with `parseDoctureDocument()` chunks to the same IDs as
the conversion result it came from.

Element IDs come from each element's content and position, as described in
[Element IDs](/docs/reference/api/core-conversion#element-ids). Inserting an unrelated
element keeps the ID of every chunk whose elements and table row ranges stay the same. An
insertion can still move elements between chunks when it changes what fits in a budget.

The [chunk reference](/docs/reference/api/chunk) lists every option and rule.
