---
title: Generate a synthetic evaluation corpus
description: Turn an extraction schema into labeled PDFs, scans and photos, then score a processor on them with no manual labeling.
---

A real corpus needs documents and hand-checked ground truth, and both are slow to collect.
`@docture/synthetic` makes a second kind of corpus from the schema you already extract with.
Each document carries ground truth that is correct by construction: the value of every
printed field, and the page and box where it is printed. `@docture/eval` scores a processor
on that corpus the same way it scores a real one.

This guide builds a utility-bill corpus with two layouts and three renditions, then scores
a processor that reads the PDF text layer. The complete program is
[`apps/examples/24-synthetic-corpus`](https://github.com/YasielCabrera/docture/tree/main/apps/examples/24-synthetic-corpus).
A shorter version runs at the end of this page.

## Install

```sh
npm install --save-dev @docture/synthetic @docture/eval docture zod@^4
npm install --save-dev pdfkit@0.19.1 pdfjs-dist@6.2.108 @napi-rs/canvas@1.0.10 sharp@0.35.5
```

`pdfkit` renders, `pdfjs-dist` reads each digital PDF back to verify the labels, and `sharp`
with `@napi-rs/canvas` makes scans and photos. The [installation recipes](/docs/guides/installation#synthetic-documents)
cover Faker, the HTML renderer and model-written text.

## 1. Start from your schema

The model reads the schema of whatever you extract with: a Docture contract, a Zod schema,
another Standard Schema library, an AI SDK schema, or plain JSON Schema.

```ts
import { z } from "zod";

export const UtilityBill = z.object({
  accountNumber: z.string().describe("12 digits, the last a Luhn check digit"),
  customerName: z.string(),
  serviceAddress: z.object({ street: z.string(), postalCode: z.string(), city: z.string() }),
  servicePeriod: z.object({ from: z.string(), to: z.string() }),
  meter: z.object({ id: z.string(), previousReading: z.number().int(), currentReading: z.number().int() }),
  tariff: z.enum(["standard", "green", "night-saver"]),
  usage: z.array(z.object({ description: z.string(), kwh: z.number().int(), rateCents: z.number().int(), amountCents: z.number().int() })).min(1),
  previousBalanceCents: z.number().int(),
  currentChargesCents: z.number().int(),
  amountDueCents: z.number().int(),
  dueDate: z.string(),
});
export type UtilityBill = z.infer<typeof UtilityBill>;
```

## 2. Define a model whose values add up

`defineModel` fills every position from the schema. Override a position with a generator
keyed by its path, using `[]` for array items. Every draw comes from a stream keyed by the
seed and the path, so adding a field never changes the values of the others.

```ts
import { before, constraint, defineModel, gen, sumOf, validLuhn } from "@docture/synthetic";

export const billModel = defineModel(UtilityBill, {
  fields: {
    accountNumber: gen.luhn("71", 12),
    "servicePeriod.from": gen.date({ from: "2025-01-01", to: "2025-10-31" }),
    "servicePeriod.to": gen.dateAfter("servicePeriod.from", { days: [28, 31] }),
    dueDate: gen.dateAfter("servicePeriod.to", { days: [14, 21] }),
    "meter.id": gen.pattern("M-#######"),
    usage: gen.array({ length: [2, 5] }),
    "usage[].kwh": gen.int(20, 600),
    "usage[].rateCents": gen.int(12, 45),
    previousBalanceCents: gen.from(({ stream }) => (stream.chance(0.7) ? 0 : stream.int(500, 9_000))),
  },
  derive(bill) {
    const usage = bill.usage.map((line) => ({ ...line, amountCents: line.kwh * line.rateCents }));
    const kwh = usage.reduce((sum, line) => sum + line.kwh, 0);
    const currentChargesCents = usage.reduce((sum, line) => sum + line.amountCents, 0);
    return {
      ...bill,
      usage,
      meter: { ...bill.meter, currentReading: bill.meter.previousReading + kwh },
      currentChargesCents,
      amountDueCents: bill.previousBalanceCents + currentChargesCents,
    };
  },
  constraints: [
    validLuhn("accountNumber"),
    sumOf("usage[].amountCents", "currentChargesCents"),
    before("servicePeriod.from", "servicePeriod.to"),
    constraint<UtilityBill>("meter delta", (bill) =>
      bill.meter.currentReading - bill.meter.previousReading === bill.usage.reduce((sum, line) => sum + line.kwh, 0)
        ? undefined
        : "the meter delta differs from the billed kWh"),
  ],
});

const { value } = await billModel.sample({ seed: 1 });
```

`derive` recomputes every total from its inputs. It runs after sampling and again after a
scenario's `shape`, so it must give the same result when run twice. The constraints then
check the sample, and the schema validates it. A failure throws `SynthesisError` with every
problem, so a broken generator never becomes a wrong label.

## 3. Add scenarios for the cases that break processors

A scenario replaces some generators, can rewrite the sample with `shape`, and states what it
promises with `expect`. `derive` and the constraints still run.

```ts
import { scenario } from "@docture/synthetic";

export const manyLines = scenario<UtilityBill>({
  name: "many-lines",
  tags: ["pagination"],
  fields: { usage: gen.array({ length: [40, 55] }) },
});
export const creditBalance = scenario<UtilityBill>({
  name: "credit-balance",
  fields: { previousBalanceCents: gen.int(-40_000, -15_000) },
  expect: (bill) => bill.previousBalanceCents < 0 || "the previous balance is not a credit",
});
```

## 4. Write templates with a printed mask

A template draws a value on a surface in PDF points with a top-left origin. `page.field`
draws text for a field and labels it with the drawn box. `page.text` draws everything else.
`drawTable` paginates rows by their measured height and labels each keyed cell as
`usage[3].kwh`.

`printed` is the template's answer key, and it must name every schema field. A new field
fails to compile until each template decides whether it prints it. Mark a field `false`
when the page does not show it, and its ground truth becomes `null`. Use `prints()` when the
page shows something other than the value, and the ground truth becomes what a reader can
recover. In this example the US bill never shows the meter id, and both tariffs `standard`
and `green` print as `Flat rate`:

```ts
import { defineTemplate, drawTable, locales, prints } from "@docture/synthetic";

export const compactUs = defineTemplate<UtilityBill>()({
  key: "compact-us",
  family: "utility-bill",
  tags: { layout: "one-column" },
  page: { size: { width: 612, height: 792 }, margin: 40 },
  locale: locales["en-US"],
  printed: {
    accountNumber: true,
    customerName: true,
    serviceAddress: { street: true, postalCode: true, city: true },
    servicePeriod: { from: true, to: true },
    meter: { id: false, previousReading: true, currentReading: true },
    tariff: prints((tariff: UtilityBill["tariff"]) => (tariff === "night-saver" ? "Time of use" : "Flat rate")),
    usage: { items: { description: true, kwh: true, rateCents: true, amountCents: true } },
    previousBalanceCents: true,
    currentChargesCents: true,
    amountDueCents: true,
    dueDate: true,
  },
  draw(page, bill, f) {
    page.text("Account number", { x: 380, y: 92, size: 9 });
    page.field("accountNumber", bill.accountNumber.replace(/(\d{4})(?=\d)/g, "$1 "), { x: 572, y: 92, size: 9, align: "right" });
    page.text("Service from", { x: 380, y: 106, size: 9 });
    page.field("servicePeriod.from", f.date(bill.servicePeriod.from), { x: 572, y: 106, size: 9, align: "right" });
    // ... the other fields
    const y = drawTable(page, {
      path: "usage", items: bill.usage, x: 40, y: 200, bottom: 752, continueAt: 40, reserveAfter: 60,
      style: { size: 9 }, headerStyle: { font: "bold" },
      columns: [
        { header: "Charge", width: 260, key: "description", text: (line) => line.description },
        { header: "kWh", width: 80, key: "kwh", align: "right", text: (line) => f.number(line.kwh) },
        { header: "Rate", width: 80, key: "rateCents", align: "right", text: (line) => f.money(line.rateCents) },
        { header: "Amount", width: 112, key: "amountCents", align: "right", text: (line) => f.money(line.amountCents) },
      ],
    });
    page.text("Amount due", { x: 380, y: y + 40, size: 11, font: "bold" });
    page.field("amountDueCents", f.money(bill.amountDueCents), { x: 572, y: y + 40, size: 11, font: "bold", align: "right" });
  },
});
```

The second template in the example, `zweispaltig-de`, is a two-column A4 bill in `de-DE`.
Its mask differs where its page differs: it prints the meter id, never prints the due date
because the bill is paid by direct debit, and prints each usage line's German name, so its
ground truth holds that name.

```ts
printed: {
  // ...
  meter: { id: true, previousReading: true, currentReading: true },
  usage: { items: { description: prints((description: string) => GERMAN[description] ?? description), kwh: true, rateCents: true, amountCents: true } },
  dueDate: false,
},
```

The formatter `f` comes from the template's locale. It formats money from integer minor
units, numbers and dates with explicit patterns rather than `Intl`, so the bytes do not
change with the runtime's ICU data. `f.money(-5951)` prints `-$59.51` in `en-US` and
`-59,51 €` in `de-DE`.

Rendering fails with `TemplateError` when the drawing and the mask disagree: a field drawn
without a declaration, a declared field never drawn, or a character the font cannot draw.

## 5. Render and verify one document

```ts
import { renderPdf } from "@docture/synthetic/pdfkit";
import { assertVerified } from "@docture/synthetic/verify";

const document = await renderPdf(compactUs, await billModel.sample({ seed: 1, scenario: manyLines }));
document.pages.length;  // 2
document.labels[0];     // { path, value, text, pageNumber, box: { x, y, width, height } }
document.expected;      // the sample with meter.id null and tariff "Flat rate" or "Time of use"
await assertVerified(document);
```

`verifyLabels` reads the PDF back through PDF.js and checks that each label's text lies
inside its box, with a 2-point tolerance, and that every box lies on its page.
`assertVerified` throws `LabelVerificationError` with every failure.

## 6. Write the corpus

```ts
import { digital, photo, scan, writeCorpus } from "@docture/synthetic/node";

const report = await writeCorpus("corpus", {
  model: billModel,
  templates: [compactUs, zweispaltigDe],
  seeds: [1, 2],
  scenarios: [manyLines, creditBalance],
  renditions: [digital(), scan({ severity: 0.4, dpi: 150 }), photo({ severity: 0.5, dpi: 150 })],
  createdAt: "2025-11-01T00:00:00Z",
});
// { written: 36, skipped: 0, failed: [], manifest: ".../corpus/manifest.jsonl" }
```

Each seed, scenario and template is sampled and rendered once and verified, then each
rendition is derived from that one rendering. Two seeds, three scenarios (base included),
two templates and three renditions make 36 cases. On the machine that wrote this guide,
example 24 wrote them in 8.6 seconds (measured once, Apple silicon).

A scan or photo rasterizes each page, ages the paper, warps it by one homography, adds
capture noise and encodes it. Every label box goes through the same homography, so the
boxes of a photo still point at its warped text. `severity` runs from 0 to 1 and moves every
knob of the profile together. The profiles are `scan`, `scanLq`, `photo` and `fax`.

The folder holds one directory per case with the document, `expected.json`, `labels.json`
and `sample.json`, plus `manifest.jsonl`, `coverage.json`, `failures.jsonl` and
`corpus.json`. A rendering that fails verification is listed in `failures.jsonl` and the
rest of the corpus is still written.

Rerunning converges. A case whose inputs and file hashes match is skipped, so a second run
of the same plan reports `written: 0, skipped: 36`, and an interrupted run finishes only the
missing cases. The case key includes the source text of the template and scenario
functions, but not the values those functions read from outside, such as a module-level
constant or an image file. Change `createdAt`, or delete the corpus, after editing those.

## 7. Score a processor on it

`jsonlDataset` reads the manifest. Each row carries `tags` for `template`, `family`,
`scenario`, `rendition`, `severity` and `locale`, a `group` shared by every rendition of
one rendering, and `locations` with the box of every label. Score the fields your processor
returns by projecting the truth with `toExpected`:

```ts
import { date, defineEval, exact, number } from "@docture/eval";
import { groundingSection } from "@docture/eval/grounding";
import { jsonlDataset } from "@docture/eval/node";
import { runEval } from "@docture/eval/runner";

const ScoredBill = z.object({
  accountNumber: z.string().nullable(),
  servicePeriod: z.object({ from: z.string().nullable(), to: z.string().nullable() }),
  currentChargesCents: z.number().int().nullable(),
  amountDueCents: z.number().int().nullable(),
});

const result = await runEval({
  dataset: jsonlDataset(report.manifest, { toExpected: (json) => ScoredBill.parse(json) }),
  spec: defineEval(ScoredBill, {
    fields: {
      accountNumber: { compare: exact(), critical: true },
      "servicePeriod.from": date(),
      "servicePeriod.to": date(),
      currentChargesCents: number(),
      amountDueCents: number(),
    },
  }),
  experiments: textLayerProcessor(),
  slices: { rendition: "tags.rendition", template: "tags.template", scenario: "tags.scenario" },
  sections: [groundingSection()],
});
```

The processor in example 24 loads each document with `DocumentLoaderPdfJs`, matches five
`label value` patterns in the text layer, and returns the box of each matching span as
evidence. Its measured result:

| Slice | Cases | F1 |
| --- | --- | --- |
| `rendition=digital` | 12 | 1.000 |
| `rendition=scan` | 12 | 0.000 |
| `rendition=photo` | 12 | 0.000 |
| `template=compact-us` | 18 | 0.500 |
| `template=zweispaltig-de` | 18 | 0.500 |

The slices show what one overall F1 of 0.5 hides. The parser handles both layouts and both
locales, and it has no answer for a document without a text layer. Grounding checks the
cited boxes against the synthetic `locations`: each of the five fields is grounded in all
12 digital cases, with no evidence outside its labeled box.

## Fonts and glyphs

A template draws with the 14 standard PDF fonts unless it declares its own. `regular`,
`bold`, `italic` and `mono` map to Helvetica and Courier. The standard fonts cover the
Windows-1252 character set: Western European letters, `€` and `£`, but not `ł`, `ą`,
Cyrillic, Greek or U+2212. For other scripts, pass the bytes of a TrueType or OpenType font:

```ts
import { readFileSync } from "node:fs";

defineTemplate<UtilityBill>()({
  // ...
  fonts: { regular: readFileSync("fonts/NotoSans-Regular.ttf"), bold: readFileSync("fonts/NotoSans-Bold.ttf") },
});
```

The renderer checks every character it draws against the font. A character the font has no
glyph for fails the render with `TemplateError` and the code `missing-glyph`, naming the
field and the character. Without the check, PDFKit would print a wrong or missing character
without an error, and the label would claim text the page does not show.

## Values from Faker or a model

`@docture/synthetic/faker` turns Faker into generators that reseed from each position's
stream, so values stay reproducible:

```ts
import { fakerFor } from "@docture/synthetic/faker";

const de = await fakerFor("de");
const fields = { customerName: de((faker) => faker.person.fullName()) };
```

`@docture/synthetic/llm` asks a model once for a pool of realistic strings and caches it, so
a corpus rebuilds offline. Sample from the pool with `gen.pick(pool)`; the ground truth is
still the sampled value and every label is still verified.

## HTML templates

`@docture/synthetic/html` prints HTML and CSS with Chromium through `playwright-core`.
Mark each printed element with `data-field="<path>"`; the renderer labels it with its box.
Use it for layout variety that is slow to write as coordinates. Install a Chromium build
with `npx playwright-core install chromium`.

## From the command line

`docture synth`, in `@docture/cli`, runs the same steps from a `docture.synth.ts` file:

```ts
import { defineSynthConfig } from "@docture/synthetic";
import { digital, scan } from "@docture/synthetic/node";

export default defineSynthConfig({
  model: billModel,
  templates: [compactUs, zweispaltigDe],
  scenarios: [manyLines, creditBalance],
  seeds: [1, 2, 3],
  renditions: [digital(), scan({ severity: 0.3 })],
  out: "corpus",
  createdAt: "2025-11-01T00:00:00Z",
});
```

| Command | Job |
| --- | --- |
| `docture synth list` | List the config's templates, scenarios and the rendition profiles |
| `docture synth gen --seed 7` | Print one sampled value as JSON |
| `docture synth render --seed 7 --out bill.pdf` | Render one document; labels go to `bill.pdf.labels.json` |
| `docture synth corpus --seeds 1-40 --renditions digital,scan:0.3,photo:0.6` | Write a corpus that `jsonlDataset` reads |
| `docture synth verify corpus` | Read every digital case back and confirm its labels |

`render` and `corpus` take `--template`, `--scenario` or `--scenarios`, and `--no-verify`.
A rendition is `digital`, or `scan`, `scan-lq`, `photo` or `fax` with a severity such as
`photo:0.6`. The commands exit 0 when done, 1 when a case failed to render or verify, and 2
on a usage error. Run `docture synth <command> --help` for every flag.
