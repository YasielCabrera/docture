`@docture/eval` compares extracted data with known output one field at a time.

```ts
import { formatFailures, scoreExtraction } from "@docture/eval";

const result = await extractor.extract("invoice.pdf", Invoice);
const score = scoreExtraction(expected, result.data);

console.log(score.f1);
console.log(formatFailures(score));
```

## Field results

Each leaf field has one status:

| Status | Meaning |
|---|---|
| `match` | Both values are present and equal under the comparator |
| `mismatch` | Both values are present but differ |
| `omission` | Expected data is present and extracted data is absent |
| `hallucination` | Extracted data is present and expected data is absent |

A mismatch reduces precision and recall. An omission reduces recall. A hallucination
reduces precision.

## Comparators

The default numeric tolerance is `0.01`. Dates compare by UTC calendar day. Strings use a
normalized Levenshtein similarity floor of `0.9`.

```ts
scoreExtraction(expected, actual, {
  numericTolerance: 0,
  stringSimilarity: 1,
  alignArraysBy: "id",
});
```

Arrays align by index unless `alignArraysBy` names a key field.

## Use a test assertion

```ts
const score = scoreExtraction(expected, result.data);
expect(score.f1, formatFailures(score)).toBe(1);
```

`formatFailures()` names each wrong field, expected value, actual value, and status.

## Generate a fixture

`@docture/testing` can create an invoice PDF and its expected data from the same seed:

```ts
import { makeInvoicePdf } from "@docture/testing";

const fixture = await makeInvoicePdf({
  seed: 301,
  lineItemCount: 12,
});

const result = await extractor.extract(fixture.bytes, Invoice);
const score = scoreExtraction(fixture.expected, result.data);
```

The seed makes the document reproducible. The generated expected data cannot drift from
the values used to render the PDF.

## Test routing without a document library

Use test doubles for routing, fallback, and validation tests:

```ts
const extractor = createExtractor({
  loaders: [inMemoryLoader(loadedDocument([sampleText]))],
  strategies: [
    failingStrategy("known-layout"),
    fixedStrategy("fallback", {
      invoiceNumber: "INV-1",
      issuedAt: "2026-01-15",
      total: 10,
      lineItems: [],
    }),
  ],
});
```

These doubles do not measure extraction quality. Use real documents or generated fixtures
for accuracy tests.

## Score a corpus

`recordRun()` combines a score with method, loader, usage, and attempts. `aggregate()` and
`formatScoreboard()` summarize several records.

```ts
const records = results.map(({ name, score, result }) =>
  recordRun(name, score, result),
);

console.log(formatScoreboard(records));
```

Watch `byMethod` when a deterministic parser should handle known layouts. A change from
the parser to an LLM fallback may keep accuracy stable while increasing cost.
