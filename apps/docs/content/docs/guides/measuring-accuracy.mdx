---
title: Measure extraction accuracy
description: Score a schema, run a project-owned corpus, compare runs, and gate regressions.
---

Install `@docture/eval` beside `docture`. The root needs no model engine. Your project owns documents and ground truth; eval owns the versioned result.

## Declare the comparable view

```ts
import { defineEval, exact, number } from "@docture/eval";
import { z } from "zod";

const Inventory = z.object({ title: z.string(), count: z.number() });
const spec = defineEval(Inventory, {
  strings: exact({ normalize: "case" }),
  fields: { count: number({ abs: 0 }) },
});
console.log(spec.validate({ title: "Screws", count: 12 }));
console.log(spec.score({ title: "Screws", count: 12 }, { title: "Screws", count: 11 }).metrics);
```

`defineEval` fails with every unresolved field or array rule. Supply `byIndex`, `ordered`, or `hungarian` for row arrays. `ordered` reports `ordered-greedy` when its cost-matrix budget forces a fallback. Use `looseEval()` for exploratory JSON comparisons. Explicit rules take precedence over schema `x-docture-eval` annotations. Empty metric denominators produce `null`.

## Adapt a dataset and processor

A `Dataset` has an `id` and an async `cases()` method. Each case has `id`, `documents`, and `expected`, with optional `tags`, `group`, and expected `locations`. Each document exposes lazy `bytes()`. No folder layout is required. `folderDataset` and `jsonlDataset` from `@docture/eval/node` are conveniences; `inMemoryDataset` lives at the root.

```ts
import { inMemoryDataset } from "@docture/eval";
import { runEval } from "@docture/eval/runner";
import { renderScoreboard } from "@docture/eval/reporters/terminal";
import { renderHtml } from "@docture/eval/reporters/html";

const dataset = inMemoryDataset("inventory", [{
  id: "one", documents: [], expected: { title: "Screws", count: 12 },
}]);
const result = await runEval({
  dataset, spec,
  experiments: { parser: {
    id: "parser",
    async extract() { return { raw: { title: "Screws", count: 12 } }; },
  } },
});
console.log(renderScoreboard(result));
const html = renderHtml(result);
```

An `EvalExtractor` returns `{ raw, usage?, evidence?, confidence? }`. Its optional `project(raw)` converts raw output into the same view as expected truth. `fromDocture` in `@docture/eval/docture` adapts an existing Docture extractor. Expected truth is validated before any processor runs. `OutOfScopeError` skips a case; processor failures remain visible as errors and omissions. The runner disposes processors on success, failure, and cancellation.

## Save and report

Use `fileRunStore` for history, resume and raw output storage. `writeEvalResult` and `readEvalResult` store `result.json` and `cases.jsonl`. Root `buildResult` supports a custom processing loop. Every reporter reads only `EvalResult`, so saved runs render without another extraction.

Import one reporter entry: `@docture/eval/reporters/terminal`, `/json`, `/markdown`, `/html`, `/csv`, `/junit`, or `/template`. HTML embeds its client and works offline. Use `defineColumn` for project columns, Markdown sections for report composition, HTML panels for data-driven additions, and `templateReporter` for a replacement format.

## Compare and gate

```ts
import { gate } from "@docture/eval";
import { compareRuns } from "@docture/eval/compare";

const comparison = compareRuns(baseline, result, { seed: "ci" });
const verdict = gate({ ...result, comparison }, {
  thresholds: [{ metric: "f1", min: 0.95 }],
});
console.log(verdict.pass);
```

Comparison pairs cases per experiment. It uses a seeded cluster bootstrap for continuous metrics and exact McNemar for binary outcomes. Set `group` on related renditions to avoid treating them as independent ground truths. The seven verdicts are `improved`, `regressed`, `unchanged`, `inconclusive`, `insufficient`, `not-tested`, and `incomparable` as recorded in the result contract. Root `resolveBaseline` selects compatible history; missing provenance fails closed for automatic selection.

## Confidence and evidence

`calibrate(result)` from `@docture/eval/calibration` measures reliability from labelled field confidence; `mergeCalibration` combines compatible reports. Missing confidence is counted as uncovered rather than invented. `grounding(result)` from `@docture/eval/grounding` compares evidence against expected locations. Unlabelled fields are excluded from grounding denominators.

For semantic string leaves, use `judge({ model, rubric })` from `@docture/eval/judge` and `spec.scoreAsync`. Install `ai@^7`. Verdicts use a fixed structured schema and temperature zero, with an injectable hash-keyed cache. An aligned row array must still contain a weighted synchronous comparator to pair rows; a judge-only row fails closed.
