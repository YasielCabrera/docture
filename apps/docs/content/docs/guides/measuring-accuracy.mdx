`docture/eval` compares extracted data with known output one field at a time.

```ts
import { formatFailures, scoreExtraction } from "docture/eval";

const result = await extractor.extract("invoice.pdf", Invoice);
const score = scoreExtraction(expected, result.data);

console.log(score.f1);
console.log(formatFailures(score));
```

## Field results

Each leaf field has one status:

| Status | Meaning |
|---|---|
| `match` | Both values are present and equal under the comparator |
| `mismatch` | Both values are present but differ |
| `omission` | Expected data is present and extracted data is absent |
| `hallucination` | Extracted data is present and expected data is absent |

A mismatch reduces precision and recall. An omission reduces recall. A hallucination
reduces precision.

## Comparators

The default numeric tolerance is `0.01`. Dates compare by their written calendar day without time-zone conversion.
The parser accepts `YYYY-MM-DD`. A date can include a time separated by `T` or a space.
The time requires hours and minutes, with optional seconds. Seconds may include a
fractional part. Offsets can be `Z`, `±HH:mm`, `±HHmm`, or `±HH`.

English month formats include `Jan 15 2026`, `January 15, 2026`, and `15 January 2026`.
Month names accept their full name or three-letter abbreviation, without regard to case.
Abbreviations may end in a period, as in `Jan. 15, 2026`. Day-first forms may use a comma,
as in `15 Jan, 2026`. Calendar dates must be valid, including leap days. Numeric forms
such as `01/02/2026` are not parsed as dates.

The date comparator applies when the expected value is ISO-shaped or the final path
segment contains a date word (`date`, `dates`, `issued`, or `due`) or ends in the word `at`.
The aliases `birthdate`, `startdate`, and `enddate` also qualify. Camel case, `_`, and `-`
separate words, as in `issuedAt` and `invoice_date`. Parent segments and names such as
`candidate`, `format`, and `vat` do not select it.

Other strings use a normalized Levenshtein similarity floor of `0.9`.
Their digits must be identical and in the same order before similarity applies.
An OCR letter slip such as `Main Streat 12` against `Main Street 12` can match. An invoice
number or IBAN with a changed digit is a mismatch.

```ts
scoreExtraction(expected, actual, {
  numericTolerance: 0,
  stringSimilarity: 1,
  alignArraysBy: "id",
});
```

Arrays align by index unless `alignArraysBy` names a key field.

## Use a test assertion

```ts
const score = scoreExtraction(expected, result.data);
expect(score.f1, formatFailures(score)).toBe(1);
```

`formatFailures()` names each wrong field, expected value, actual value, and status.

## Generate a fixture

`docture/testing/fixtures` can create an invoice PDF and its expected data from the same seed:

```ts
import { makeInvoicePdf } from "docture/testing/fixtures";
import { Invoice, InvoiceSchema } from "./invoice.js";

const fixture = await makeInvoicePdf({
  seed: 301,
  lineItemCount: 12,
});

const result = await extractor.extract(fixture.bytes, Invoice);
const expected = InvoiceSchema.parse(fixture.expected);
const score = scoreExtraction(expected, result.data);
```

The seed makes the document reproducible. The generated expected data cannot drift from
the values used to render the PDF. Project it through the extraction schema before
scoring so fields outside that schema are not reported as omissions.

## Test routing without a document library

Use test doubles for routing, fallback, and validation tests. They need no PDFKit or Vitest
peer at runtime:

```ts
import { failingStrategy, fixedStrategy, inMemoryLoader, loadedDocument } from "docture/testing/doubles";
```

```ts
const extractor = createExtractor({
  loaders: [inMemoryLoader(loadedDocument([sampleText]))],
  strategies: [
    failingStrategy("known-layout"),
    fixedStrategy("fallback", {
      invoiceNumber: "INV-1",
      issuedAt: "2026-01-15",
      total: 10,
      lineItems: [],
    }),
  ],
});
```

These doubles do not measure extraction quality. Use real documents or generated fixtures
for accuracy tests.

## Score a corpus

`recordRun()` combines a score with method, loader, usage, and attempts. `aggregate()` and
`formatScoreboard()` summarize several records.

```ts
const records = results.map(({ name, score, result }) =>
  recordRun(name, score, result),
);

console.log(formatScoreboard(records));
```

Watch `byMethod` when a deterministic parser should handle known layouts. A change from
the parser to an LLM fallback may keep accuracy stable while increasing cost.
