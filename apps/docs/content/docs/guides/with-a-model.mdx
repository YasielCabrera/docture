docture accepts the AI SDK `LanguageModel` type. Use a provider instance or an AI Gateway
model string.

```ts
import { llm } from "docture/llm/text";
import { openai } from "@ai-sdk/openai";

llm({ model: openai("gpt-5") });
llm({ model: "openai/gpt-5" });
```

The `ai` and `zod` packages are optional peers. Model integrations use AI SDK 7 and
Zod 3.25.76 or later 3.x, or Zod 4.1.8 or later. Also install the provider package used by
the application.

## Install

```sh
npm install docture pdfjs-dist@6.2.108 ai@^7 @ai-sdk/openai zod@^4
```

See [installation recipes](/docs/guides/installation) for other engines and providers.

## Use the model backend

`LLM` can create a text strategy, vision strategy, classifier, and splitter from one
model configuration.

```ts
import { Extractor } from "docture";
import { LLM } from "docture/llm";
import { DocumentLoaderPdfJs } from "docture/loaders/pdfjs";

const extractor = new Extractor()
  .loadDocumentLoader(new DocumentLoaderPdfJs())
  .loadLlm(new LLM(openai("gpt-5")));
```

Register other model components at the same time:

```ts
const backend = new LLM(openai("gpt-5"), {
  instructions: "Dates must use YYYY-MM-DD.",
  cache: fileCache(".docture-cache"),
  pricing: {
    "gpt-5": {
      inputPerMillion: 2,
      outputPerMillion: 10,
      cacheReadPerMillion: 0.2,
      cacheWritePerMillion: 2.5,
    },
  },
});

extractor.loadLlm(backend, {
  vision: true,
  classify: true,
});
```

`vision: true` adds a vision strategy. The selected loader must produce renderable pages
at runtime. `classify: true` adds an LLM classifier.

## Build strategies directly

Use direct strategies when each model component needs different settings:

```ts
import { llm } from "docture/llm/text";
import { vision } from "docture/llm/vision";

const extractor = new Extractor({
  loaders: [renderableLoader],
  strategies: [
    llm({ model: openai("gpt-5-mini"), name: "text" }),
    vision({ model: openai("gpt-5"), name: "scan", maxPages: 3 }),
  ],
});
```

`llm()` requires `TEXT_LAYER`. `vision()` requires `RENDERABLE_PAGES`. The pipeline checks
these facts after loading each document.

## Use the convenience factory

`createLlmExtractor()` builds the usual text strategy and can add a vision strategy or
classifier.

```ts
import { createLlmExtractor } from "docture/llm/extractor";

const extractor = createLlmExtractor({
  loaders: [new DocumentLoaderPdfJs()],
  model: openai("gpt-5"),
  before: [knownInvoiceParser],
  vision: false,
  classifyWithModel: true,
});
```

Strategies in `before` run before the model.

## Guide the extraction

Start with clear field names and schema descriptions. Add `instructions` for rules that
apply to every document. Use `hints` for rules tied to a classification name.

```ts
llm({
  model: openai("gpt-5"),
  instructions: "Amounts in parentheses are negative.",
  hints: {
    invoice: "Use the amount labelled Grand total.",
  },
});
```

`system` replaces the default system prompt. `instructions` appends to it. The default
temperature is `0` and the default retry count is `2`.

## Cache responses

```ts
import { fileCache, memoryCache } from "docture/llm/cache";

llm({ model, cache: memoryCache(500) });
llm({ model, cache: fileCache(".docture-cache") });
```

The cache key includes the model id, prompts, JSON Schema, and request variant. A cache hit
returns the saved token counts with no `costUsd` because no new request ran.

## Report cost

Providers report token counts but not a stable price. Supply a pricing table when you need
`usage.costUsd`:

```ts
llm({
  model,
  pricing: {
    "gpt-5": { inputPerMillion: 2, outputPerMillion: 10 },
  },
});
```

Without a matching price, `costUsd` is absent. It is not reported as zero.

Cache reads and writes use their optional rates. A missing cache rate falls back to
`inputPerMillion`. Provider-reported cache counts appear as `cacheReadTokens` and
`cacheWriteTokens` in usage, included in `inputTokens`.

See [long documents](/docs/guides/long-documents) for multi-request extraction and
[scanned documents](/docs/guides/scanned-documents) for vision setup.
