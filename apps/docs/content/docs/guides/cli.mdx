title: Command line

The `@docture/cli` package supplies the `docture` executable.

Install it in a project:

```sh
npm install --save-dev @docture/cli
npx docture --help
```

Run it once without installing:

```sh
npx --package @docture/cli docture --help
```

The CLI requires `ai` and `pdfjs-dist`. For a Zod schema and a local OpenAI provider:

```sh
npm install --save-dev @docture/cli @ai-sdk/openai zod@^4
```

## Commands

| Command | Job |
|---|---|
| `extract <file...>` | Extract data that matches a schema |
| `convert <file...>` | Convert PDFs to TXT, Markdown, or HTML |
| `classify <file...>` | Choose a document classification without extracting it |
| `inspect <file...>` | Show loaded text, geometry, and document facts without a model |
| `eval <file...>` | Extract and compare results with ground truth |

Run `docture <command> --help` for the flags accepted by that command.

## Convert

```sh
docture convert reports/*.pdf --out converted/
```

`--out <directory>` is required. Markdown and referenced assets are the defaults. Use
`--format md|html|txt` and `--assets referenced|embedded|omit` to change them.
Referenced images are written to `<out>/<stem>.assets/`. The document is written as
`<out>/<stem>.md`, `.html`, or `.txt`.

```sh
docture convert report.pdf \
  --out converted/ \
  --assist-layout \
  --model openai/gpt-5
```

Layout assistance can classify and reorder known elements but cannot return text. The
default PDF.js loader reads digital PDFs. Configure an OCR loader for scanned PDFs.
One failed batch input leaves successful outputs in place and returns exit code `1`.

## Extract

```sh
docture extract invoice.pdf \
  --schema ./invoice.ts \
  --model openai/gpt-5
```

The schema module may export `default`, `schema`, or one named value. Select an explicit
export with `--schema ./schemas.ts#Invoice`.

JSON Schema files can guide a model but do not provide a runtime validator. Export a Zod,
Valibot, ArkType, or other Standard Schema value when validation is required.

## Output streams

Extracted data goes to stdout. Diagnostics go to stderr. This keeps pipelines valid:

```sh
docture extract invoice.pdf -s ./invoice.ts -m openai/gpt-5 | jq .total
```

Use `--full` to include method, loader, attempts, usage, features, and classification in
the output. The CLI does not include the redundant successful `validation` object. Use
`--format ndjson` to stream one batch result per line.

## Models and vision

`--model` accepts `provider/model-id`. The CLI uses a provider package installed in the
current project when it can resolve one. Otherwise it uses the AI Gateway. `--gateway`
forces the gateway path.

```sh
docture extract scan.pdf \
  -s ./invoice.ts \
  -m openai/gpt-5 \
  --vision \
  --dpi 200
```

The CLI uses `docture/raster/canvas` with its optional default dependency
`@napi-rs/canvas`. A normal install attempts the native prebuild. If optional dependencies
were omitted, install it explicitly:

```sh
npm install --save-dev @docture/cli @napi-rs/canvas@1.0.10
```

## Batches

```sh
docture extract 'invoices/*.pdf' \
  -s ./invoice.ts \
  -m openai/gpt-5 \
  --out out/ \
  --cache .docture-cache \
  --concurrency 8
```

With several inputs, `--out <dir>` writes one JSON file per input. With one input,
`--out <file>` writes that result to one file. A trailing slash forces directory output.
One document failure does not stop the remaining files.

## Inspect

`inspect` needs no schema, model, or API key:

```sh
docture inspect scan.pdf --text --lines
```

Use it to check the selected loader, media type, page count, form, text length, geometry,
and rendering support.

## Configuration file

Declare the dependencies imported by this config directly:

```sh
npm install --save-dev @docture/cli docture pdfjs-dist@6.2.108 ai@^7 @ai-sdk/openai zod@^4
```

<SourceExample file="docture.config.ts" title="docture.config.ts" />

The CLI finds the nearest `docture.config.ts`, `.mts`, `.js`, or `.mjs` while walking up
from the working directory. Command flags override configuration defaults.

If a configured integration's engine is not installed, the command reports
`MISSING_ENGINE` with the package and range to install rather than a damaged file.
Errors raised by the configuration's copy of `docture` keep their codes, hints, and
usage even when the package manager installed a separate copy for the CLI. A typed
config's `extractor` and `converter` also type-check against either copy, because the CLI
types them by the methods it calls.

With pnpm, an application whose `pdfjs-dist` differs from the CLI's `6.2.108` gets its own
copy of `docture`. Combining `--vision` with a PDF.js loader built in the config then loads
both PDF.js versions into one process, and PDF.js rejects the second with
`The API version ... does not match the Worker version ...`. Omit `loaders` to use the
CLI's PDF.js loader, or install `pdfjs-dist@6.2.108` in the application.

Node 22.18 or newer can import erasable TypeScript config and schema modules directly.
Earlier Node 22 releases need `--experimental-strip-types`, or compiled `.js` or `.mjs`
files. JSON Schema files do not require TypeScript support.

## Evaluate in CI

```sh
docture eval 'corpus/*.pdf' \
  -s ./invoice.ts \
  -m openai/gpt-5 \
  --truth corpus/truth \
  --min-f1 0.95 \
  --report score.md
```

Exit code `0` means success. Exit code `1` means a document failed or an accuracy gate was
not met. Exit code `2` means the invocation was invalid.

The complete flag and library API reference is under
[`@docture/cli`](/docs/reference/api/cli).
