Every extraction starts with a `DocumentSource`.

## Install

```sh
npm install docture zod@^4
```

See [installation recipes](/docs/getting-started/installation) for other engines and providers.

## Paths and URLs

```ts
await extractor.extract("./invoice.pdf", Invoice);
await extractor.extract(new URL("file:///data/invoice.pdf"), Invoice);
await extractor.extract(new URL("https://example.com/invoice.pdf"), Invoice);
```

A string without a URL protocol is a filesystem path. `file:`, `http:`, and `https:` URLs
are supported. HTTP errors raise `UnsupportedSourceError`. So does a path or `file:` URL
that cannot be read, such as a missing file, a directory, or a file without read
permission. Its message names the path and the fix, and `cause` keeps the file-system
error with its `code`, such as `ENOENT` or `EACCES`.

## Bytes

```ts
await extractor.extract(uint8Array, Invoice);
await extractor.extract(arrayBuffer, Invoice);
```

docture checks known file signatures. If the bytes do not identify the format, the media
type is `application/octet-stream` and a loader must accept it.

## Raw documents

Use `RawDocument` when you know the media type or want to keep a file name:

```ts
await extractor.extract(
  {
    bytes,
    mimeType: "application/pdf",
    fileName: "invoice.pdf",
  },
  Invoice,
);
```

Specific magic bytes override a generic or conflicting known `mimeType`. A custom
declared type keeps its routing choice. ZIP bytes and formats without a known signature
keep the declared type.

## Text and data files

`DocumentLoaderData` decodes text without another document library.

```ts
import { DocumentLoaderData, Extractor } from "docture";

const extractor = new Extractor()
  .loadDocumentLoader(new DocumentLoaderData())
  .loadStrategy(parser);
```

It accepts plain text, Markdown, CSV, HTML, XHTML, JSON, and XML. Text inputs split pages
on form feed by default and provide neither geometry nor page images.

HTML and XHTML produce one page of visible text. The loader removes markup, head
content, scripts, styles, templates, noscript, and comments. It decodes character
entities and preserves document order with heading markers, list markers, block line
breaks, and tabs between table cells. HTML follows omitted-tag and textarea rules;
XHTML preserves CDATA and self-closing tags. Syntax parsers load on the first HTML or
XHTML call. They do not fetch resources or expand external DTD declarations.

```ts
new DocumentLoaderData({
  encoding: "utf-8",
  pageDelimiter: "\f",
  mimeTypes: ["application/x-acme"],
});
```

## Loaded documents

A `LoadedSource` skips source resolution and loader selection:

```ts
await extractor.extract(
  {
    loaded: document,
    mimeType: "application/pdf",
    facts: ["ACME_LAYOUT"],
  },
  Invoice,
);
```

Text and geometry facts come from the loaded pages. The optional `facts` list adds custom
document facts. `Process` uses this input form so it can read a bundle once and extract
several page groups without loading the file again.

## Media type detection

`resolveSource()` applies this order:

1. Specific magic bytes, when the declared type is missing, generic, or known to the library.
2. Declared media type, including custom routing types and ZIP-based formats.
3. File extension.
4. `application/octet-stream`.

ZIP-based Office formats keep a declared type, then use the extension, then fall back to
`application/zip`. The shared ZIP header cannot identify DOCX, XLSX, or PPTX. With no known
signature, the declared type wins. WEBP detection requires both `RIFF` and `WEBP` markers.

The low-level `sniffMimeType()` and `resolveSource()` functions are documented in the
[core documents API](/docs/getting-started/reference/documents).

## Select a runtime entry

The root `docture` and `docture/chunk` support portable byte, HTTP and preloaded workflows. Import local-file constructors or `resolveNodeSource` from `docture/node`. Node wrappers use the same core modules and errors. They do not register a process-wide resolver. Existing path-based applications must change the import or pass `sourceResolver: resolveNodeSource` explicitly.

DOCX text is isolated at `docture/loaders/mammoth`, MIME expansion at `docture/inputs/email`, Azure Read at `docture/loaders/azure-di`, and stored Paperless sources at `docture/sources/paperless`. Docling JSON enters through `docture/import/docling`; the service adapter is `docture/loaders/docling`. Service adapters use fetch and require no npm service SDK. Select and install optional local engines explicitly.
