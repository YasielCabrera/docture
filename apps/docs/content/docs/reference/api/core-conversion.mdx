Import these APIs from `docture`.

## DocumentConverter

```ts
new DocumentConverter(options?: DocumentConverterOptions)
createDocumentConverter(options: DocumentConverterOptions): DocumentConverter
```

`DocumentConverterOptions` accepts loaders in first-success order, one optional
`layoutAnalyzer`, a logger, and a per-stage timeout. The factory requires at least one
loader. A fluent converter may be created empty before `loadDocumentLoader()` is called.

The wiring methods are `loadDocumentLoader()`, `loadLayoutAnalyzer()`, `loadLlm()`, and
`loadLogger()`. `components` returns the registered loaders and optional analyzer.
Duplicate loader names or a second analyzer throw `DuplicateComponentError`.

## Conversion calls

```ts
convert(source: DocumentSource, options?: ConvertOptions): Promise<ConversionResult>
safeConvert(source: DocumentSource, options?: ConvertOptions): Promise<SafeConversion>
convertBatch(
  sources: readonly DocumentSource[],
  options?: ConversionBatchOptions,
): AsyncGenerator<ConversionBatchItem>
```

`ConvertOptions` has `format`, `assets`, `signal`, `logger`, and `stageTimeoutMs`.
`ConversionFormat` is `"text" | "markdown" | "html" | "json"`; Markdown is the default.
`ConversionAssetMode` is `"referenced" | "embedded" | "omit"`; referenced is the
default.

`SafeConversion` is `{ ok: true, result } | { ok: false, error }`.
`ConversionBatchOptions` adds `concurrency`, default `4`. A `ConversionBatchItem` contains
the original source, input index, and safe outcome. Items are yielded as they finish.
Leaving the generator early aborts in-flight jobs and waits for them to settle.

`dispose()` settles every disposable loader and analyzer once. Multiple teardown failures
reject with `AggregateError`.

## Result

`ConversionResult` contains:

| Field | Meaning |
| --- | --- |
| `content` | Whole-document output. |
| `format`, `mimeType` | Selected format and output media type. |
| `pages` | `ConvertedPage` fragments and semantic elements. |
| `assets` | In-memory `ConversionAsset` values. Empty in omit mode. |
| `loader`, `method` | Selected loader and deterministic or assisted method. |
| `attempts`, `warnings` | Loader and analyzer history plus degraded-layout warnings. |
| `features` | Runtime document facts. |
| `usage` | Model tokens, optional cost, and complete wall time. |

`ConversionWarning` has a `ConversionWarningCode`, message, and optional page number.
Codes cover degraded or ambiguous layout, unsupported assets, unsafe links, analyzer
failure, and invalid analyzer output.

## Semantic layout

`LayoutDocument` contains `LayoutPage` values. Each page contains `DocumentElement`
values. The union includes `HeadingElement`, `ParagraphElement`, `ListElement`,
`TableElement`, `CodeElement`, `FigureElement`, `PageBreakElement`, `PageHeaderElement`,
and `PageFooterElement`. A switch over `DocumentElement["kind"]` must handle the two
page furniture kinds.

`PageHeaderElement` and `PageFooterElement` hold running headers and footers with `text`,
`runs`, and a `FurnitureEvidence` value. `tagged` means the loader's structure tag marked
the line. `repeated` means core inferred it. A page lists its headers first and its
footers last, before the page break. Markdown and HTML omit both kinds. TXT and JSON keep
them.

Inference is a heuristic, not a measured accuracy claim. A line is eligible when it lies
wholly in the top or bottom 10% of the page. It qualifies when the same text appears on
at least three pages and on at least 60% of all pages, of odd pages, or of even pages,
within 2% of the page height of its median position. A digit run matches across pages
only when it follows the page number, as in `Page 2 of 9`. Heading-size text, table rows,
text-only pages, and pages without dimensions are never inferred. A tagged `header` or
`footer` hint inside the bands counts on a single page.

`TableElement` holds `rows`, `headerRows`, optional `spans`, and the source lines in
`sourceText`. A `TableCellSpan` anchors a merged cell at zero-based `row` and `col` and
covers `rowSpan` rows and `colSpan` columns. Its text is in the anchor slot, and each
covered slot holds `""`. Spans are sorted by row and then column. They stay inside the
grid, do not overlap, cover more than one cell, and never cross the `headerRows`
boundary. Rows have equal length when spans are present. `parseDoctureDocument()`
rejects a saved table that breaks these rules. Markdown flattens header rows into one
row whose labels join with ` / `, and leaves covered body cells blank. HTML writes
`colspan` and `rowspan`.

Table detection is a heuristic. Rows with the same cell count at matching positions form
a plain table without spans, `headerRows: 1`. When counts differ, the first two or more
matching rows set column bands from their horizontal extent. A following row with no more
cells joins when each cell overlaps a band and no two cells claim one band. Under both
rules, an untagged row joins only when it starts within three times the median row
spacing of the table's rows so far, measured from the row above. Every
neighbouring pair of cells in such a row is at least one line height apart. A cell gets
`colSpan: k` when it covers more than half of each of `k` bands that hold no other cell of
its row. The first row is a header. The next row is also a header while the row above it
holds a column span and its cells sit under that span or under empty slots. Rows above
the band rows join only as those header rows. `rowSpan` grows when the cell's box covers
at least half the height of the next row's line and that row's slot is empty. It never
crosses the header rows.

Every element has an ID and `ElementProvenance`, which extends `ProvenanceSegment`. A
segment contains the page number, `LayoutBox`, loader `sourceIds`, and `lineIds` when the
page has positioned lines. The segment fields describe the page where the element starts.
A table or paragraph that continues across a page break also has `continuations`, one
segment for each later page in page order, starting with the next page. A table built from
positioned lines has `rowProvenance`, one segment per row with that row's page, line box,
source IDs, and line ID. Text elements use `InlineText` runs for link annotations. A
`ConvertedPage` contains format-specific content, page `width` and `height`, and the same
elements. Its content holds every element that starts on the page, including the rest of
an element that continues onto later pages.

```ts
provenanceSegments(provenance: ElementProvenance): readonly ProvenanceSegment[]
```

`provenanceSegments()` returns the starting page's segment followed by the
`continuations`. A table or paragraph joins only when it ends in the bottom quarter of its
page and the next page's first element starts in that page's top quarter. A table
continues with rows of the table's cell count, cells of at most 40 characters, a font size
within 10% of the table body, the body's font weight, each cell overlapping its column, and
no letters in a column whose body cells hold numbers without letters. A copy of the header
rows is dropped from `rows` and kept in `sourceText`. After a continued row, a row with
fewer cells joins when the band rule places it. Each row after the first starts within
three times the table's row spacing on the earlier page, measured from the row above. A
paragraph continues when it does not end with `.`, `!`, `?`, `:`, or `;`, closing quotes and
brackets included, and the next page's first element is a paragraph starting with a
lowercase letter. Page furniture and top or bottom band lines set apart from the
body by blank space are skipped. Pages without dimensions never join.
`parseDoctureDocument()` rejects continuations on other element kinds, continuations
that do not name the following pages in order, and `rowProvenance` whose length differs
from `rows` or whose pages go back or fall outside the table's pages.

## Source lines

```ts
sourceLines(page: Pick<LoadedPage, "pageNumber" | "lines">): readonly SourceLine[]
isLineSourceId(id: string): id is LineSourceId
```

A `LineSourceId` names one positioned loader line as `p<page>-line-<I>`, where `I` is the
1-based index into `page.lines`. `sourceLines()` returns each line's `SourceLine` with ID,
page number, box, and verbatim text. Pages without positioned lines return none.
`isLineSourceId()` accepts only the canonical form, without leading zeros.

The same loader with the same options yields the same IDs during extraction and
conversion. A line split into two columns contributes its ID to both halves, so an ID
resolves to the whole physical line.

`ConversionAsset` extends the loader's `LoadedAsset` with its stable relative `reference`.

## Layout analyzer contract

```ts
defineLayoutAnalyzer(analyzer: LayoutAnalyzer): LayoutAnalyzer
```

`LayoutAnalyzer.analyze(context)` receives a `LayoutDocument` without page headers and
footers, a signal, and a logger. Core ignores annotations that name furniture, and
furniture keeps its place. A table or paragraph with `continuations` stays last in its
page's text after reordering, and annotations that retype or group it are ignored. `LayoutElementRole` excludes the furniture kinds. It
returns `LayoutAnalysis` with `LayoutAnnotation` values, warnings, and optional usage.
An annotation can contain an existing element ID, `LayoutElementRole`, heading level,
group label, and page-local order. The contract has no text property.

Core validates IDs and order before applying an analysis. `LayoutAnalyzerContext` and
`LayoutAnalysis` are public for custom analyzers.

## Versioned JSON

`ConversionFormat` also accepts `"json"`. Its MIME type is `application/json`.
`DoctureDocument` has `schemaVersion: 2`, loader, method, normalized layout pages, assets,
and final warnings. Page dimensions, element IDs, boxes, source and line IDs, and ordering
match the in-process conversion result. The
[version 2 JSON Schema](/schemas/docture-document-v2.schema.json) is generated from the
TypeScript type. Breaking format changes require a new version. Version 2 added the page
furniture kinds and `lineIds`. The published
[version 1 JSON Schema](/schemas/docture-document-v1.schema.json) is frozen.

```ts
parseDoctureDocument(value: unknown): DoctureDocumentParse
```

Read saved JSON with `parseDoctureDocument()`. It validates version 1 and version 2
documents and returns `{ ok: true, document, sourceVersion }` or `{ ok: false, issues }`.
A valid version 1 document comes back as version 2, its structural superset. Each
`ValidationIssue` has a dotted path. Beyond the schema, the parser requires unique element
IDs, a provenance page equal to the holding page, and line IDs on that page.

`DoctureDocumentAsset` contains either `{ id, mimeType, reference }` for referenced assets
or `{ id, mimeType, data }` for embedded base64 bytes. Omitted assets produce an empty
array. Original link targets remain data; an HTML renderer must apply its own URL policy.

```ts
const result = await converter.convert(source, { format: "json", assets: "embedded" });
const parsed = parseDoctureDocument(JSON.parse(result.content));
if (parsed.ok) console.log(parsed.document.schemaVersion); // 2
```
