Import from `docture/chunk`. The entry needs no engine or model runtime.

## Chunk a converted document

```sh
npm install docture
```

```ts
chunkDocument(document: ChunkableDocument, options: ChunkOptions): readonly DocumentChunk[]
estimateTokens(text: string): number
```

`ChunkableDocument` is any value with `pages[].elements`, such as a `ConversionResult` or
the document that `parseDoctureDocument()` returns for saved JSON. Both give the same
chunks.

`ChunkOptions` contains:

| Field | Meaning |
| --- | --- |
| `budget` | A `ChunkBudget` with `unit` `characters` or `estimatedTokens` and a positive `max`. |
| `overlapElements` | Whole elements, or table pieces, repeated from the end of the previous chunk when they fit the budget with the chunk's first new unit. Default `0`. |
| `headingPath` | Start each chunk with the Markdown headings it sits under, one per level, outermost first. Default `false`. |

`estimatedTokens` counts `estimateTokens(text)`, which is `ceil(characters / 4)`. It is an
estimate, not a tokenizer's count. A chunk closes before the unit that would take it over
`max`. The budget is soft in one case only: a chunk exceeds `max` when it holds a single
unit larger than `max`, either one element or one table row group with its header rows,
plus the heading path when `headingPath` is set. `chunkDocument()` throws `RangeError` when `max` is not a positive finite number,
`unit` is unknown, or `overlapElements` is not a non-negative integer.

Each `DocumentChunk` contains:

| Field | Meaning |
| --- | --- |
| `id` | `chunk-` and 16 hex characters, hashed from the element IDs, table row ranges, and options. The same document and options give the same IDs. |
| `text` | Markdown of the chunk's elements, separated by blank lines. |
| `elementIds` | IDs of the elements the text comes from, in document order. |
| `provenance` | `ProvenanceSegment` values for the chunk's elements, in order. |

## Packing rules

- Chunks hold whole elements in document order. A heading starts a new chunk. Consecutive
  headings share a chunk with the element after them when all fit the budget; otherwise
  the headings form a chunk of their own.
- Figures, page breaks, and running headers and footers add no text and no provenance.
- A table larger than the budget splits between rows. Rows that a row span joins stay
  together, and every piece repeats the table's header rows. Pieces are sized with the
  heading path in front when `headingPath` is set. A piece's provenance has one
  segment per page for its rows from `rowProvenance`. The first piece also covers the
  header rows. A table without `rowProvenance` uses its element provenance in every piece.
- A table or paragraph that continues across pages keeps all its segments, so a chunk can
  cite two pages.
- Body text appears in one chunk only, unless `overlapElements` asks for repeats. Repeated
  table header rows and heading paths are the only other repeated text. They are context
  and add no provenance.
