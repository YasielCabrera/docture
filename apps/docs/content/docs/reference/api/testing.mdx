Import from `@docture/testing`. Install Vitest 3 or newer when using the conformance
suites.

## Generated invoices

```ts
buildInvoiceData(options?: InvoiceOptions): SyntheticInvoice
makeInvoicePdf(options?: InvoiceOptions): Promise<SyntheticDocument<SyntheticInvoice>>
formatMoney(value: number): string
makeRichDocumentPdf(): Promise<SyntheticDocument<RichDocumentExpected>>
richDocumentExpected(): RichDocumentExpected
```

`InvoiceOptions` has `seed`, `lineItemCount`, and `textless`. Defaults are seed `1`, five
line items, and a normal text-layer PDF. A seed reproduces the same values. `textless`
creates a PDF without text for scan behavior tests.

`SyntheticDocument<T>` contains PDF `bytes`, `expected` data, and actual `pageCount`.
`SyntheticInvoice` contains invoice number, dates, currency, seller, buyer, line items,
subtotal, tax rate, tax, and total. `SyntheticLineItem` contains description, quantity,
unit price, and amount.

`formatMoney()` returns a two-decimal, US-formatted string. `buildInvoiceData()` and
`formatMoney()` are synchronous. `makeInvoicePdf()` is asynchronous and rejects if PDF
generation fails.

`makeRichDocumentPdf()` produces a deterministic two-page fixture with multiple columns,
typography, a list, table, link, code block, and embedded raster image.
`RichDocumentExpected` contains each source string and structural expectation.

## Test doubles

```ts
loadedDocument(
  pageTexts: readonly string[],
  options?: { loader?: string; geometry?: boolean },
): LoadedDocument

inMemoryLoader(document: LoadedDocument): DocumentLoader
fixedStrategy(name: string, data: unknown): ExtractionStrategy
failingStrategy(name: string, message = "strategy failed"): ExtractionStrategy
```

`loadedDocument()` creates A4-sized pages and geometry by default. The default loader name
is `in-memory`. `inMemoryLoader()` accepts every media type and returns the supplied
document. `fixedStrategy()` returns fixed data after checking the abort signal.
`failingStrategy()` always throws the configured message.

## Conformance suites

```ts
describeLoaderConformance(options: LoaderConformanceOptions): void
describeRasterizerConformance(options: RasterizerConformanceOptions): void
```

`LoaderConformanceOptions` requires a suite `name` and a fresh loader `create` function.
The suite is specific to PDF loaders. It asserts `application/pdf` acceptance and reads
generated invoice PDFs. Its optional `skip` object can skip geometry, images, multi-page,
or scanned checks when a PDF loader does not claim that behavior.

`RasterizerConformanceOptions` requires a suite `name` and fresh rasterizer `create`
function. The suite renders generated PDFs.

The functions register Vitest suites and return `void`. Test failures are reported by
Vitest. Create functions may return a component or a promise.
