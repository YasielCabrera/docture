Import these APIs from `docture`.

## Sources

`DocumentSource` accepts a path string, `URL`, `Uint8Array`, `ArrayBuffer`, `RawDocument`,
or `LoadedSource`.

`RawDocument` contains `bytes` and optional `mimeType` and `fileName`. `LoadedSource`
contains `loaded` and optional `mimeType`, `fileName`, and custom `facts`. A loaded source
skips source resolution and loading.

```ts
resolveSource(source: DocumentSource, signal?: AbortSignal): Promise<RawDocument>
sniffMimeType(bytes: Uint8Array): string | undefined
isLoadedSource(source: DocumentSource): source is LoadedSource
```

`resolveSource()` reads file paths and `file:` URLs, fetches HTTP and HTTPS URLs, and
normalizes byte inputs. It throws `UnsupportedSourceError` for unsupported protocols,
failed HTTP responses, empty input, a file that cannot be read, or a `LoadedSource` passed
directly to this low-level function. A file read failure keeps the file-system error as
`cause`. Network errors propagate from `fetch()`.
`sniffMimeType()` recognizes supported byte signatures without reading the full document.

## Document data loader

```ts
new DocumentLoaderData(config?: DataLoaderConfig)
documentLoaderData(config?: DataLoaderConfig): DocumentLoaderData
```

`DataLoaderConfig` has `name`, `encoding`, `pageDelimiter`, and additional `mimeTypes`.
Defaults are `DocumentLoaderData`, UTF-8, form feed, and the built-in plain text,
Markdown, CSV, HTML, JSON, and XML media types.

The loader returns text without geometry or images. Page width and height are `0` because
the input has no physical page size. `TextDecoder` errors and invalid encoding names
reject the load.

## Loader contract

`LoaderCapabilities<Text, Geometry, Images>` contains the three literal capability
booleans, accepted `mimeTypes`, and optional custom `facts`.

`DocumentLoader<C>` has a stable `name`, `capabilities`, `load(document, context)`, and
optional `dispose()`. `LoadContext` contains `signal`, `logger`, and optional
`LoadRequest`. A conversion request can set `layout` and `assets`; extraction leaves the
request absent so custom loaders do not pay conversion-only costs.

```ts
defineLoader<const C extends LoaderCapabilities>(
  loader: DocumentLoader<C>,
): DocumentLoader<C>

loaderAccepts(loader: DocumentLoader, mimeType: string): boolean
```

`defineLoader()` preserves literal capability types. `loaderAccepts()` supports exact
media types, type wildcards such as `image/*`, and `*/*`.

`TextLoader`, `GeometryLoader`, and `ImageLoader` are capability-specific aliases. They
produce a compile error only when an API explicitly asks for one of those aliases. Normal
pipeline eligibility still checks the loaded document at runtime.

## Loaded documents and geometry

`LoadedDocument` contains ordered `pages`, whole-document `text`, inferred `form`, loader
name, and optional metadata. Pages in `document.text` are joined with a form feed.

`LoadedPage` contains a 1-based `pageNumber`, dimensions in PDF points, page `text`,
optional positioned `lines`, optional `LayoutBlock` and `LoadedAsset` values, and optional
lazy `image(options)`. `TextLayoutBlock` and `ImageLayoutBlock` share a `LayoutBox`.
`LayoutRoleHint` carries tagged semantics when a loader can recover them.

`TextLine` contains its vertical box, joined text, and left-to-right `spans`. `TextSpan`
contains text, a top-left-origin box, and optional confidence, `TextStyle`, direction, and
link target. `TextStyle` can carry family, size, weight, slant, monospace, and color facts.
Coordinates use PDF points, with `y` increasing downward.

`LoadedDocument.metadata` uses `DocumentMetadata` for title, author, subject, keywords,
language, and other loader facts. `LoadedAsset` contains stable identity, page and box
provenance, media type, bytes, and optional pixel dimensions and alt text.

`DocumentForm` is `"digital" | "scanned" | "mixed" | "unknown"`.
`DocumentFeatures` contains media type, page and text counts, text, geometry, and rendering
facts, form, and optional custom facts.

`KnownDocumentFact` is `TEXT_LAYER`, `GEOMETRY`, or `RENDERABLE_PAGES`. `DocumentFact`
also accepts custom string facts.

| Helper | Signature | Behavior |
| --- | --- | --- |
| `inferForm` | `(pageTextLengths: readonly number[]) => DocumentForm` | Infers digital, scanned, mixed, or unknown from per-page text lengths. |
| `preloadedFeatures` | `(source: LoadedSource) => DocumentFeatures` | Computes features for a source that skipped loading. |
| `hasFact` | `(features: DocumentFeatures, fact: DocumentFact) => boolean` | Reads a built-in or custom runtime fact. |

`MIN_TEXT_LAYER_CHARS` is `50`, the whole-document trimmed text threshold used for
`TEXT_LAYER`.

Page selection recomputes these features from the selected document and uses the same
50-character threshold. A short digital selection can therefore have `form: "digital"`
and `hasTextLayer: false`. A `Process` group below the threshold needs a strategy that
does not require `TEXT_LAYER`; otherwise extraction fails with `NO_ELIGIBLE_STRATEGY`.

## Geometry helpers

`PositionedWord` contains text, `[xMin, yMin, xMax, yMax]`, and optional confidence,
direction, style, and link target.

```ts
linesFromWords(
  words: readonly PositionedWord[],
  options?: LinesFromWordsOptions,
): TextLine[]
```

`LinesFromWordsOptions.scale` defaults to `1`. `lineTolerance` defaults to `0.5` median
word height. Blank words are removed; output lines and spans are sorted in reading order.

```ts
textFromLines(lines: readonly TextLine[]): string
imageSize(bytes: Uint8Array): ImageSize | undefined
tiffPages(bytes: Uint8Array): readonly TiffPage[] | undefined
```

`textFromLines()` joins line text with newlines. `imageSize()` returns `ImageSize` with
`widthPx` and `heightPx` for readable PNG, JPEG, and classic TIFF headers, otherwise
`undefined`. For a TIFF it reports the first page.

`tiffPages()` reads the image file directory (IFD) chain of a classic TIFF in either byte
order. Each `TiffPage` adds `pageNumber` (1-based, in IFD order), `ifdOffset`,
`littleEndian`, and the TIFF `compression` code to `widthPx` and `heightPx`. It returns
`undefined` when any page is malformed: a looping IFD chain, an IFD or strip outside the
bytes, or a page without a size. BigTIFF is not recognized.

## Rasterizers

`Rasterizer` has a stable `name`, supported `formats`, `rasterize()`, and optional
`dispose()`. `RasterizeContext` contains `signal` and `logger`.

```ts
defineRasterizer(rasterizer: Rasterizer): Rasterizer
```

`defineRasterizer()` is an identity helper. Rasterizer implementations reject on decode,
render, unsupported format, or abort failures.

`RasterFormat` is `"png" | "jpeg"`. `RasterOptions` contains optional `dpi`, `format`,
JPEG `quality`, `maxEdge`, and 1-based `pages`. `DEFAULT_RASTER_OPTIONS` is 300 DPI PNG.

`RasterPage` contains page number, bytes, pixel dimensions, format, and point-per-pixel
`scale`.

## Loader and rasterizer composition

```ts
withRasterizer<C extends LoaderCapabilities>(
  loader: DocumentLoader<C>,
  rasterizer: Rasterizer,
  options?: WithRasterizerOptions,
): DocumentLoader<WithImages<C>>
```

`WithImages<C>` preserves the loader's text and geometry capability types and sets images
to `true`. `WithRasterizerOptions.defaults` sets default raster options.

The composed loader adds a lazy `image()` function to each page. Calls are memoized by
page and effective options. Per-call options override composition defaults. Disposal
settles both components and reports failures with `AggregateError`.

## Logging

`Logger` defines `debug`, `info`, `warn`, `error`, and `child`. `silentLogger` discards
all messages and is the default. `consoleLogger(bindings?)` writes structured fields to
the matching console method and returns child loggers with merged bindings.

## Requested loading

`LoadRequest.pages` is an optional list of original one-based page numbers. PDF loaders
read only those pages, and OCR loaders pass the selection to rasterization before
recognition. Numbers are deduplicated and results stay in document order. Constructor
`maxPages` remains a cap on the original source prefix. Invalid or unavailable
selections raise `PAGE_OUT_OF_RANGE`. A custom loader may ignore the optimization;
the pipeline still projects and validates the selected pages.

`DocumentFeatures.pageCount` describes the selected loaded pages. PDF loader metadata
can also report the physical source count. Selected OCR loads omit that physical count
when the rasterizer cannot provide it.
