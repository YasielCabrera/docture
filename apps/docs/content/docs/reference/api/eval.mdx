Install `@docture/eval` beside its required `docture` peer. The root is portable and engine-free. Node file access lives in `@docture/eval/node`. Only the judge needs the optional `ai` peer.

See the [accuracy guide](/docs/guides/measuring-accuracy) for the complete pipeline. Specs expose `validate`, `score`, `scoreAsync` and `explain`. Metrics use null for empty denominators. Saved results use format `docture-eval-result`, version 1, described by `@docture/eval/result-v1.schema.json`.

## `@docture/eval`

`defineEval` defaults to absent null handling and weight 1. Strings require a comparator and row arrays require alignment rules. `exact` defaults to no normalization. `number` defaults to zero absolute and relative tolerance and two minor-unit digits. `date` defaults to day granularity. `identifier` removes whitespace and ` -./`. `text` requires minimum similarity. It defaults to Levenshtein similarity, ANLS cutoff 0.5 and digits in order. `ordered` and `hungarian` default to minimum similarity 0.5 and 250,000 matrix cells. `looseEval` uses exploratory defaults without a schema. `gate` fails incomplete runs and ungraded required metrics.

`spec.validate(expected)` returns validation issues. `spec.score(expected, actual, extras?)` returns `CaseScore`; `scoreAsync` supports async comparators. `spec.explain(path)` describes the resolved rules. Empty metric denominators are null. A zero-weight field still affects the unweighted `exact` metric.

### `toJsonValue`

```ts
toJsonValue(value: unknown): JsonValue
```

Convert any value to its JSON form the way `JSON.stringify` would, so a result holds exactly what a saved copy holds. `undefined`, functions, symbols and non-finite numbers become `null`; dates become ISO strings.

### `canonicalJson`

```ts
canonicalJson(value: unknown): string
```

`JSON.stringify` with object keys sorted, so equal values always produce equal text.

### `fingerprintOf`

```ts
fingerprintOf(value: unknown): string
```

A stable 64-bit FNV-1a fingerprint of a value's canonical JSON, as 16 hex digits. Equal values hash equally across processes and platforms, so specs, datasets and experiment configs can be compared between saved runs.

### `compareCodeUnits`

```ts
compareCodeUnits(a: string, b: string): number
```

Order strings by UTF-16 code unit, the same on every host. Use it wherever order reaches a fingerprint, a seed or written output; `localeCompare` depends on the host locale.

### `formatPath`

```ts
formatPath(segments: readonly PathSegment[]): string
```

Format path segments as a concrete path: `formatPath(["lineItems", 3, "amount"])` is `lineItems[3].amount`.

### `patternOf`

```ts
patternOf(path: string): string
```

Turn a concrete path into its pattern: `lineItems[3].amount` becomes `lineItems[].amount`. Returns the text unchanged when it does not parse.

### `inMemoryDataset`

```ts
inMemoryDataset<T>(id: string, cases: readonly EvalCase<T>[]): Dataset<T>
```

A dataset over cases already in memory, for tests and generated corpora.

Declare a custom reporter. Identity at runtime; it pins the type.

### `resolveBaseline`

```ts
resolveBaseline(store: Pick<RunStore, "listRuns">, query?: BaselineQuery): Promise<string | undefined>
```

The id of the most recently started `complete` run on `branch`, then on `fallbackBranch`, or `undefined` when none qualifies. Throws `EvalSpecError` when `requireSameDataset` has no `datasetFingerprint` to compare against.

### `defineComparator`

```ts
defineComparator<E>(comparator: Comparator<E>): Comparator<E>
```

Declare a custom comparator. Identity at runtime; it pins the type.

### `describeComparator`

```ts
describeComparator(comparator: Pick<Comparator, "id" | "options">): string
```

Render a comparator for `spec.explain`, such as `number(abs 0.01)`.

### `exact`

```ts
exact(options?: { readonly normalize?: ExactNormalization; }): Comparator
```

Equal JSON values, optionally ignoring case or spacing in strings. A mismatch that only differs in case or spacing gets a hint.

### `number`

```ts
number(options?: NumberOptions): Comparator
```

Numbers within an absolute or relative tolerance. Mismatches carry sign, minor-unit, scale and transposition hints.

### `date`

```ts
date(options?: DateOptions): Comparator
```

Calendar dates at a granularity. Mismatches that are the right date in another layout, or with day and month swapped, get a `date-format` hint.

### `identifier`

```ts
identifier(options?: { readonly strip?: string; }): Comparator
```

Identifiers such as IBANs, references and plates: equal after removing spacing and separators and ignoring case.

### `text`

```ts
text(options: TextOptions): Comparator
```

Strings by similarity after lowercasing and collapsing whitespace.

### `oneOf`

```ts
oneOf(values: readonly Primitive[], options?: { readonly normalize?: "none" | "case"; }): Comparator
```

A closed vocabulary: the actual value must equal the expected one, and ground truth must be one of `values`.

### `setOf`

```ts
setOf(element: Comparator, options?: { readonly minSimilarity?: number; }): Comparator
```

An unordered collection compared as a whole. Elements pair by the best total similarity; the collection matches when every element pairs with a match and neither side has extras. Similarity is the share of matched elements.

### `boxIoU`

```ts
boxIoU(options: { readonly min: number; }): Comparator
```

Boxes that overlap by at least `min` intersection over union. Boxes on different pages never match.

### `intersectionOverUnion`

```ts
intersectionOverUnion(a: Box, b: Box): number
```

Intersection over union of two boxes. 0 when they do not overlap or have no area.

### `byIndex`

```ts
byIndex(): ArrayRule
```

Pair row i with row i. Right for tables whose order is part of the data.

### `hungarian`

```ts
hungarian(options?: { readonly key?: readonly string[]; readonly minSimilarity?: number; readonly weights?: Readonly<Record<string, number>>; readonly maxCells?: number; }): ArrayRule
```

Order-free pairing: rows with equal `key` values pair first, the rest by an optimal assignment on row similarity. Rows below `minSimilarity` stay unpaired.

### `ordered`

```ts
ordered(options?: { readonly minSimilarity?: number; readonly maxCells?: number; }): ArrayRule
```

Order-preserving pairing that maximizes total row similarity, like a diff. Rows below `minSimilarity` stay unpaired.

### `defineEval`

```ts
defineEval<C extends ContractLike>(schema: C, rules?: EvalRules): EvalSpec<InferContract<C>>
defineEval<T = unknown>(schema: JsonSchemaObject, rules?: EvalRules): EvalSpec<T>
```

Build a spec from a schema and rules. Every leaf gets its comparator from, in order: the most specific `fields` rule, an `x-docture-eval` annotation, an unambiguous type default, or `strings` for strings. Unresolved fields, unused rules and unsegmented leaves throw one `EvalSpecError` listing them all.

### `looseEval`

```ts
looseEval(options?: LooseEvalOptions): EvalSpec<unknown>
```

A spec with no schema that reproduces the defaults of Docture's previous `scoreExtraction`: numbers within 0.01, strings at similarity 0.9 once their digits agree, date-like strings by calendar day, arrays by index. It is the one spec that does not fail closed; use it for quick checks.

### `prf`

```ts
prf(counts: StatusCounts): Prf
```

Precision, recall and F1 from counts. F1 is 2·match / (2·match + 2·mismatch + omission + hallucination), so it is 0, not null, when nothing was predicted.

### `groundingRule`

```ts
groundingRule(rule?: GroundingRule): ResolvedGroundingRule
```

Apply defaults and check the rule. Throws `EvalSpecError` when `iou` is outside (0, 1] or `level` is unknown.

### `isGrounded`

```ts
isGrounded(field: Pick<FieldResult, "status" | "evidence">, locations: readonly ExpectedLocation[], rule?: GroundingRule): boolean
```

Whether a field is grounded: it matched and its evidence supports one of its expected locations. The scorer sets `FieldResult.grounded` with the default rule, and `@docture/eval/grounding` uses the rule it was given.

### `supportsLocation`

```ts
supportsLocation(evidence: readonly EvidenceRef[], locations: readonly ExpectedLocation[], options?: GroundingRule): boolean
```

Whether any evidence reference supports any expected location under the rule.

### `defineAssertion`

```ts
defineAssertion(assertion: Assertion): Assertion
```

Declare a custom assertion. Identity at runtime; it pins the type.

### `sumOf`

```ts
sumOf(path: string): { equals(target: string, options?: { readonly abs?: number; }): Assertion; }
```

`sumOf("lineItems[].amount").equals("totals.total", { abs: 0.01 })`: the values at one path sum to the value at another.

### `defineMetric`

```ts
defineMetric(metric: MetricDefinition): MetricDefinition
```

Declare a custom metric. `aggregate` turns an experiment's rows into one value; `perCase`, when given, lets run comparison test the change for significance.

### `builtinMetrics`

```ts
builtinMetrics(): readonly MetricDefinition[]
```

The metrics every result carries. Custom metrics from `defineMetric` are added after these.

### `omittedOf`

```ts
omittedOf(score: CaseScore): OmittedLeaves
```

What `omitted` an errored case records, computed from a score against an absent output.

### `runScopeOmissions`

```ts
runScopeOmissions(row: CaseResult, scope?: string): OmittedLeaves | undefined
```

The omitted leaves an errored row adds to precision, recall and F1. They count only at `run` scope, the default, so the result is `undefined` for a scored or skipped row and for another scope.

### `percentile`

```ts
percentile(values: readonly number[], p: number): number | null
```

Linear interpolation between closest ranks.

### `prfMetricId`

```ts
prfMetricId(metric: "precision" | "recall" | "f1", scope?: PrfScope): string
```

The metric id of precision, recall or F1 in a scope: `f1` for run scope, `f1.micro`, `f1.macro`.

### `prfOf`

```ts
prfOf(rows: readonly CaseResult[], scope: PrfScope, segment?: string): Prf
```

Precision, recall and F1 of rows in one scope, optionally restricted to a segment.

### `buildResult`

```ts
buildResult(input: BuildResultInput): EvalResult
```

Assemble a complete result from case rows: per experiment, the overall metrics, segment, slice, path and field-type summaries, and epoch variance. A project that runs its own loop can build rows itself and still use every reporter.

### `parseCaseResult`

```ts
parseCaseResult(json: unknown): CaseResult
```

Validate one line of `cases.jsonl` against `result-v1.schema.json`. Throws `RunStoreError` with reason `format` naming the first bad path.

### `parseEvalResult`

```ts
parseEvalResult(json: unknown): EvalResult
```

Validate a parsed `result.json` against `result-v1.schema.json`, every nested member included, and return it as an `EvalResult`. Throws `RunStoreError` with reason `version` for another format version, or `format` naming the first path that does not fit version 1.

### `parseRunInfo`

```ts
parseRunInfo(json: unknown): RunInfo
```

Validate run metadata, such as a stored `run.json`, against the run definition in `result-v1.schema.json`. Throws `RunStoreError` with reason `format` naming the first bad path.

### `gate`

```ts
gate(result: EvalResult, options: GateOptions): GateResult
```

Check a result against thresholds and regression budgets. Equality passes. A run that is not `complete` fails. A missing value fails unless `onNull` is `pass`. Invalid options throw one `EvalSpecError` listing every problem.

## `@docture/eval/runner`

`runEval` defaults to concurrency 1 and one epoch. Baseline, store, reporters and sections are opt-in. `resume: "latest"` selects an unfinished compatible run. `rescore` reads stored raw output and applies the current spec without extraction. Processors preflight before work and dispose after success, error or cancellation.

- `EvalExtractor`
- `ExtractContext`
- `ExtractOutput`
- `RescoreOptions`
- `ResultOptions`
- `ResultSection`
- `RunEvalOptions`

### `runEval`

```ts
runEval<T>(options: RunEvalOptions<T>): Promise<EvalResult>
```

Run every case through every experiment with bounded concurrency and return the stored result. Lanes share one cursor, and the first lane failure aborts the others. Rows interrupted by an abort are dropped so a resume extracts them again. `dispose` runs once on success, failure and abort: on success its failures become warnings; on failure the original error is thrown with `disposalErrors` attached. Reporter failures become warnings, persisted after every hook ran.

When `extract` throws a value with a `usage` member, such as Docture's `ExtractionFailedError.usage`, the errored row keeps that usage. Failed paid calls therefore count toward `costUsd` and the token metrics. A `usage` member that is not valid usage is dropped, and the row's error message says why.

### `memoryRunStore`

```ts
memoryRunStore(): RunStore
```

Create an isolated in-memory store, including raw outputs for re-scoring.

### `rescore`

```ts
rescore<T>(store: RunStore, runId: string, spec: EvalSpec<T>, options?: RescoreOptions<T>): Promise<EvalResult>
```

Score a stored run again from its raw outputs, without calling `extract`, and store the outcome as a new run whose `run.rescoredFrom` names the source run. The source run is never changed. Warnings, comparison and gate describe the new run, so they come from `options`, not from the source.

## `@docture/eval/node`

`folderDataset` ignores dot folders, hashes documents and rejects unsigned drafts by default. `include` selects explicit case ids. `jsonlDataset` resolves documents relative to its manifest unless `base` is set. `readEvalResult` and `writeEvalResult` use `result.json` with `cases.jsonl`.

- `FolderDatasetOptions`
- `LiveArtifact`

### `gitInfo`

```ts
gitInfo(cwd: string): Promise<RunInfo["git"]>
```

Read repository provenance on demand, returning undefined outside a Git repository. A detached HEAD reports the branch `detached@<first 12 hex digits of the sha>`, which never matches another commit's runs.

### `fileDocument`

```ts
fileDocument(path: string, mimeType?: string): CaseDocument
```

Make a lazy filesystem document; an explicit MIME type overrides extension inference.

### `folderDataset`

```ts
folderDataset<T = unknown>(root: string, options: FolderDatasetOptions<T>): DraftableDataset<T>
```

Discover one case per subfolder of `root`; folders whose name starts with `.` are ignored. Documents load lazily, but each listed document's content is hashed while listing, because the resume key and the dataset fingerprint must survive a fresh checkout, which resets modification times. Fails on a missing root, document or expected file, a draft without sign-off unless `drafts` allows it, and an unknown `include` id.

### `jsonlDataset`

```ts
jsonlDataset<T = unknown>(manifest: string, options?: { readonly id?: string; readonly base?: string; readonly toExpected?: (json: unknown, id: string) => T; }): Dataset<T>
```

Load a JSONL manifest with `id`, `documents` (paths relative to `base`, default the manifest's folder) and `expected` on each line, plus optional `tags`, `params` and `group`. Errors name the manifest line and case.

### `fileRunStore`

```ts
fileRunStore(dir: string): RunStore
```

A run store in a directory. `index.jsonl` is an append-only list of run events, and `runs/<runId>/` holds `run.json`, `cases.jsonl`, `result.json` and `raw/<experiment>/<caseId>.<epoch>.json`. Each id in a raw path is `x-` plus its UTF-8 bytes in lowercase hex, or `h-` plus their SHA-256 when longer than 60 bytes, so ids that differ only in letter case never share a file. A crash can tear the last line of a log; readers ignore it and the next append cuts it.

### `runDirectory`

## `@docture/eval/docture`

- `FromDoctureOptions`

### `fromDocture`

```ts
fromDocture<C extends ContractLike>(extractor: DoctureExtractor, contract: C, options?: FromDoctureOptions): EvalExtractor<ExtractionResult<InferContract<C>>, InferContract<C>>
fromDocture<C extends ContractLike, T>(extractor: DoctureExtractor, contract: C, options: FromDoctureProjection<C, T>): EvalExtractor<ExtractionResult<InferContract<C>>, T>
```

Adapt a structural Docture extractor; each case must contain one non-empty document. Every Docture failure, including `UnsupportedSourceError`, becomes an errored row: Docture has no signal for a document outside the project's scope. Usage has no `calls`, because one Docture attempt can make several model calls and the result does not count them. When a failed extraction carries usage without a price, `fromDocture` prices it as it prices a successful result, so the errored row records what the failed attempts cost.

## `@docture/eval/compare`

Defaults: test `auto`, 10,000 resamples, seed `docture-eval`, alpha 0.05 and clustering by `group`. Each common experiment is compared separately unless `experiment` selects an id or pair. Unsupported comparisons fail closed.

- `CompareOptions`

### `compareRuns`

```ts
compareRuns(baseline: EvalResult, candidate: EvalResult, options?: CompareOptions): RunComparison
```

Compare every experiment both runs have, or the selected pair, over paired case and epoch rows with exact McNemar or a seeded, group-clustered bootstrap (FNV-1a/Mulberry32). Small samples (at most 20 clusters) use exact sign-flip p-values; subgroup families use Holm correction. Throws `IncomparableRunsError` listing every reason the runs cannot be paired.

## `@docture/eval/calibration`

## Framework adapter wiring

Adapters use structural contracts and import no host framework. The Vitest matcher is async. Every assertion must be awaited. `minF1` defaults to 1; an ungraded F1 fails.

Importing the adapter does not change Vitest's types. Opt in to the matcher's type once, for example in a `vitest.d.ts`:

```ts
import type { ExtractionMatchers } from "@docture/eval/vitest";

declare module "vitest" {
  interface Matchers<T = any> extends ExtractionMatchers {}
}
```

Then register the matcher and await every assertion:

```ts
import { afterAll, beforeAll, expect, it, test } from "vitest";
import { extractionMatchers, describeEval } from "@docture/eval/vitest";

expect.extend(extractionMatchers());

test("invoice", async () => {
  await expect(actual).toMatchExtraction(expected, spec, { minF1: 0.95 });
});

await describeEval(dataset, spec, processor, { test: it, beforeAll, afterAll, minF1: 0.95 });
```

`describeEval` registers one test per case with the `test` function you pass. It runs the processor's `preflight` once in `beforeAll` and `dispose` once in `afterAll`.

```ts
import { extractionScorer } from "@docture/eval/evalite";
import { extractionAssertion } from "@docture/eval/promptfoo";
import { ExtractionF1 } from "@docture/eval/autoevals";

const scorer = extractionScorer(spec, { metric: "f1" });
const evaliteConfig = { scorers: [scorer] };
const assertion = extractionAssertion(spec, { threshold: 0.95 });
const promptfooResult = await assertion(JSON.stringify(actual), {
  vars: { expected },
});
const autoevalsScore = await ExtractionF1(spec)({ output: actual, expected });
```

Evalite's default metric is `f1`; `precision`, `recall` and `anls` are also supported. Ungraded values score zero. Promptfoo reads truth from `context.vars.expected`; its default threshold is 0.95. String output that is not JSON fails with score 0 and a reason. Autoevals returns `{ name, score, metadata }`, including counts and an ungraded flag.
