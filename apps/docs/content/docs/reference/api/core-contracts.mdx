Import these APIs from `docture`.

## Contracts

```ts
contract<S extends FlexibleSchema>(
  definition: ContractDefinition<S>,
): Contract<InferSchema<S>>
```

`ContractDefinition<S>` has a required `name` and schema `S`, plus optional `description`,
`hints` and `examples`. `Contract<T>` stores a `FlexibleSchema<T>` with the same metadata. Contracts
are structural and are not branded.

```ts
const Invoice = contract({
  name: "invoice",
  description: "A supplier invoice.",
  hints: "Use the amount labelled Total due.",
  schema: z.object({ invoiceNumber: z.string(), total: z.number() }),
});
```

### Examples

```ts
interface ContractExample<T = unknown> {
  readonly text: string;
  readonly output: T;
}
```

`examples` are worked examples: document text and the data it should yield. `output` is
typed by the schema's output type, so a wrong field or type does not compile, and the
examples never widen the type that `contract()` infers.

```ts
const Invoice = contract({
  name: "invoice",
  schema: z.object({ invoiceNumber: z.string(), total: z.number() }),
  examples: [
    { text: "Invoice INV-7. Total due: 1.234,50 EUR", output: { invoiceNumber: "INV-7", total: 1234.5 } },
  ],
});
```

Every text and vision extraction prompt for the contract carries its examples, including
repairs. A vision prompt gets the text examples only; it sends no example images. They go
in the system prompt after the hints, each as `<example>` holding `<input>` and `<output>`.
An opening or closing `example`, `input` or `output` tag inside the text or the JSON is
escaped with a backslash. That keeps the blocks intact, but it does not stop an example
from reading as an instruction, so only use examples you trust. Each example adds its
text and JSON to every request, so it costs input tokens on every page or chunk. A
changed example changes the request, so it gets its own cache entry.

`output` is sent as JSON. Plain objects, arrays, strings, booleans, `null`, finite
numbers and a valid `Date`, sent as its ISO string, are allowed, and an `undefined`
property is left out. Any other value, such as `NaN`, a function, a `Map` or an object that
contains itself, makes
`contract()` throw a `TypeError` that names the example and the path. `contract()` copies
the examples, so later edits do not reach it.

When an extraction starts, each example's JSON is checked against the schema as a model
answer is: the check runs the schema, discards the transformed value, and sends exactly the
JSON. An example that fails rejects the extraction with a `TypeError` before any request.
A schema whose transform changes a value's type, such as a `string` to a `Date`, takes an
example output of the transformed type, and its JSON must still be a valid input:
`new Date("2024-03-05")` is sent as `"2024-03-05T00:00:00.000Z"`.

`ContractLike` is a `Contract` or a bare supported schema. `InferContract<C>` resolves
the data type produced by either form.

| Helper | Signature | Return and failure behavior |
| --- | --- | --- |
| `isContract` | `(value: unknown) => value is Contract` | Checks for a string `name` and a `schema`. It does not validate the schema. |
| `schemaOf` | `(value: ContractLike) => FlexibleSchema` | Returns a contract's schema or the bare schema unchanged. |
| `contractName` | `(value: ContractLike) => string \| undefined` | Returns the contract name when present. |

These helpers do not throw for a bare supported schema.

## Schema types

`FlexibleSchema<T>` and `InferSchema<S>` are re-exported from
`@ai-sdk/provider-utils`. They cover the schema forms supported by the AI SDK, including
Zod, Valibot, ArkType, lazy schemas, and AI SDK `Schema` objects. A raw JSON Schema object
must first be wrapped with `jsonSchema()` from `ai`.

`JsonSchemaObject` is the object form stored in a resolved schema. `ValidateResult<T>` is
either `{ ok: true, data: T }` or `{ ok: false, issues }`.

`ResolvedSchema<T>` contains:

| Field | Meaning |
| --- | --- |
| `flexible` | Original `FlexibleSchema<T>`, kept for consumers that accept it directly. |
| `jsonSchema` | JSON Schema representation used in prompts and model calls. |
| `validate(value)` | Validates unknown data and returns `ValidateResult<T>`. |

```ts
resolveSchema<T>(schema: FlexibleSchema<T>): Promise<ResolvedSchema<T>>
```

`resolveSchema()` performs any asynchronous schema conversion once before extraction.
It rejects when a schema adapter cannot produce JSON Schema. A schema without a validator,
including a plain JSON Schema wrapped by the AI SDK, accepts the returned value unchanged.

## Validation in the pipeline

Strategies receive `ResolvedSchema` and return unknown data. The pipeline calls its
validator after each strategy returns. A validation failure records a failed attempt and
allows the next strategy to run.

The first strategy whose output validates becomes the result. If no strategy succeeds,
the first validation failure takes precedence and extraction rejects with
`ContractViolationError` and its `ValidationIssue` values. If every strategy threw before
validation, extraction rejects with `ExtractionFailedError`.
