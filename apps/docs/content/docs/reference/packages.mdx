All published packages require Node.js 22 or newer. The Docture packages are MIT
licensed. Some wrapped libraries use a different licence or ship platform-specific
artifacts, as noted below.

## Choose packages

| Package | Use it for | Main imports |
| --- | --- | --- |
| `docture` | Core and model-based extraction from one entry point | `Extractor`, `contract`, `llm`, `vision` |
| `@docture/core` | The pipeline, contracts, deterministic components, and `Process` | `Extractor`, `DocumentLoaderData`, `defineStrategy` |
| `@docture/llm` | Text, vision, classification, and splitting with AI SDK models | `LLM`, `llm`, `vision`, `createLlmExtractor` |
| `@docture/loader-pdfjs` | PDF text and geometry with PDF.js | `DocumentLoaderPdfJs` |
| `@docture/loader-mupdf` | PDF text, geometry, and rendering with MuPDF | `DocumentLoaderMuPdf`, `MuPdfRasterizer` |
| `@docture/loader-tesseract` | OCR through Tesseract.js | `DocumentLoaderTesseract` |
| `@docture/loader-paddleocr` | OCR through PaddleOCR and ONNX Runtime | `DocumentLoaderPaddleOcr` |
| `@docture/raster-canvas` | PDF rendering through PDF.js and canvas | `NapiCanvasRasterizer` |
| `@docture/eval` | Field scoring and run reports | `scoreExtraction`, `recordRun` |
| `@docture/testing` | Generated PDFs, test doubles, and conformance suites | `makeInvoicePdf`, `fixedStrategy` |
| `@docture/cli` | The `docture` terminal command | `defineConfig` |

The facade re-exports the public APIs of `@docture/core` and `@docture/llm`. Adapter,
evaluation, testing, and CLI exports stay in their own packages.

## Common installs

Text extraction with a model:

```package-install
docture @docture/loader-pdfjs ai zod
```

Deterministic extraction without a model:

```package-install
@docture/core @docture/loader-pdfjs zod
```

Scanned PDFs with a vision model:

```package-install
docture @docture/loader-pdfjs @docture/raster-canvas ai zod
```

The command-line tool:

```package-install
@docture/cli
```

## Runtime dependencies

| Package | Relevant dependency | Licence | Runtime note |
| --- | --- | --- | --- |
| `@docture/core` | `@ai-sdk/provider-utils` | Apache-2.0 | Schema utilities only. It does not install `ai` or a document parser. |
| `docture`, `@docture/llm` | `ai` peer dependency | Apache-2.0 | Install a compatible AI SDK 7 release in the application. |
| `@docture/loader-pdfjs` | `pdfjs-dist` | Apache-2.0 | JavaScript and WASM assets. |
| `@docture/loader-mupdf` | `mupdf` | AGPL-3.0-or-later | MuPDF runs through WASM. Review AGPL obligations before distribution. |
| `@docture/loader-tesseract` | `tesseract.js` | Apache-2.0 | OCR runs through WASM and loads language data. |
| `@docture/loader-paddleocr` | `ppu-paddle-ocr`, `onnxruntime-node` | MIT | ONNX Runtime uses prebuilt native dependencies for the current platform. |
| `@docture/raster-canvas` | `pdfjs-dist`, `@napi-rs/canvas` | Apache-2.0, MIT | Canvas uses prebuilt native dependencies for the current platform. |
| `@docture/testing` | `pdfkit`, Vitest peer | MIT | Vitest 3 or newer is required for conformance suites. |

The package boundary controls what is installed. Installing `@docture/core` does not
install PDF.js, MuPDF, OCR engines, canvas, ONNX Runtime, or the AI SDK runtime.

## Import conventions

Use the facade when an application needs both core and LLM features:

```ts
import { Extractor, contract, llm } from "docture";
```

Use package imports for adapters and for applications that do not need the facade:

```ts
import { Extractor, defineStrategy } from "@docture/core";
import { DocumentLoaderPdfJs } from "@docture/loader-pdfjs";
```

All supported exports come from a package root. Internal `src` and `dist` paths are not
public entry points.

See the [API reference](/docs/reference/api) for each public export.
