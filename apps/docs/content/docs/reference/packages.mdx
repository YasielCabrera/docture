Docture publishes two packages: `docture` and `@docture/cli`. Both require Node.js 22 or
newer. `docture` contains core, model integrations, adapters, evaluation, and testing.
Its root exports core only. The CLI supplies the `docture` executable.

## Public entry points

| Import | Purpose | Optional peers used by that entry |
| --- | --- | --- |
| `docture` | Contracts, extraction, deterministic conversion, errors, classification, and `Process` | Zod through its schema helper |
| `docture/llm` | All model components, including the `LLM` convenience class and `model()` | `ai@^7`, `zod@^3.25.76` or `zod@^4.1.8` |
| `docture/llm/text` | `LlmStrategy`, `LlmStrategyOptions`, `llm`, and `modelIdOf` | `ai@^7`, `zod@^3.25.76` or `zod@^4.1.8` |
| `docture/llm/vision` | `VisionStrategy`, `VisionStrategyOptions`, and `vision` | `ai@^7`, `zod@^3.25.76` or `zod@^4.1.8` |
| `docture/llm/classifier` | `LlmClassifier`, its options, and `llmClassifier` | `ai@^7`, `zod@^3.25.76` or `zod@^4.1.8` |
| `docture/llm/layout` | `LlmLayoutAnalyzer`, its options, and `llmLayout` | `ai@^7`, `zod@^3.25.76` or `zod@^4.1.8` |
| `docture/llm/split` | Text and image splitters and their options | `ai@^7`, `zod@^3.25.76` or `zod@^4.1.8` |

| `@docture/cli` | CLI configuration, IO, errors, and `run` | See CLI dependencies below |

Files under `src` and `dist` are internal. The [API reference](/docs/reference/api)
documents the named exports of each supported entry point. The
[migration guide](/docs/guides/migration) maps the removed scoped packages.

## Install recipes

The [installation recipes](/docs/guides/installation) give a complete command for every
integration, including model providers, OCR, rendering, testing, and the CLI.

Every engine listed above is an optional peer of `docture`. Install the engine explicitly
when selecting its adapter. If an adapter's engine is missing, its first use throws
`MissingEngineError` with the package and range to install.

## Engine versions

Each peer declares the versions this release supports. The packed-package gate installs a
range's lowest version and the newest release that existed when the range was chosen. For
the PDF and rendering engines it runs the shipped loader and rasterizer conformance suites.
For Zod it runs model classification and extraction against a mocked model.

| Peer | Supported versions | Versions run by the release gate |
| --- | --- | --- |
| `pdfjs-dist` | `^6.2.108` | 6.2.108, 6.3.289, 6.4.299 |
| `@napi-rs/canvas` | `^1.0.10` | 1.0.10, 1.0.13 |
| `mupdf` | `~1.28.0` | 1.28.0, 1.28.1 |
| `pdfkit` | `>=0.17.2 <0.21.0` | 0.17.2, 0.19.1, 0.20.2 |
| `zod` | `^3.25.76` or `^4.1.8` | 3.25.76, 4.1.8, 4.4.3, 4.6.7 |
| `ai` | `^7.0.0` | 7.0.51, 7.0.149 |
| `vitest` | `>=3` | 4.1.10 |
| `tesseract.js` | `7.0.0` | None; recognition runs only in the opt-in OCR tests |
| `ppu-paddle-ocr` | `6.3.0` | Installed without ONNX Runtime to check the missing-runtime error; recognition runs only in the opt-in OCR tests |
| `onnxruntime-node` | `1.27.0` | None; recognition runs only in the opt-in OCR tests |

The gate installs these engine versions with npm and pnpm. PDF.js loads canvas itself, so
the gate also runs the lowest PDF.js with the newest canvas and the newest PDF.js with the
lowest canvas. Each of these engine installs must contain a single canvas.

Tesseract.js, PaddleOCR, and ONNX Runtime stay at exact versions. Their recognition is
tested only with downloaded models, which the release gate does not fetch. The gate
installs `tesseract.js@6.0.1`, `ppu-paddle-ocr@6.6.1`, and `onnxruntime-node@1.30.0` only
to check that npm rejects them beside `docture`, that npm adds a second copy of each pinned
engine beside them when a project depends only on `@docture/cli`, and that the
[documented override](/docs/guides/installation#applications-with-their-own-ocr-engine)
fixes both. It does not run OCR with them. The `ai` and `vitest` ranges predate this
release; the gate runs the listed versions only.

An installed peer must satisfy its range even when the application does not import that
adapter. With npm, an engine version outside the range in the same project fails the
install with `ERESOLVE`. pnpm installs it and prints an unmet-peer warning; Docture does not
support that combination. A new major version, a new `mupdf` minor version, or a new
`pdfkit` minor version is unsupported until a release verifies it.

Core's normal dependencies are `@ai-sdk/provider-utils` for schema utilities and
`@types/json-schema@7.0.15` for JSON Schema declarations. Consumers do not need to install
those declarations separately. The schema helper has a Zod peer. Zod 3.25.76 or later 3.x,
or Zod 4.1.8 or later, satisfies that helper and the model classification, layout, and
splitting integrations, which import `zod/v4`. Installing
`docture` alone does not request the AI SDK runtime, a PDF engine, OCR, canvas, ONNX
Runtime, PDFKit, or Vitest.

## CLI dependencies

`@docture/cli` requires `docture`, `ai`, and `pdfjs-dist`. Its default canvas renderer uses
`@napi-rs/canvas` as an optional dependency. A normal CLI install attempts that native
prebuild. Text extraction still works when canvas is unavailable. If optional dependencies
were omitted, install `@napi-rs/canvas@1.0.10` to use `--vision` or raster assets.

A config that imports Docture components or a provider declares those dependencies in the
application too. See [the CLI guide](/docs/guides/cli).

## Bundling and download size

All Docture wrappers ship in one npm tarball, whichever subpath you import. Optional peers
control engine installation separately from that download.

The library emits ESM modules and declares `sideEffects: false`. A production bundler can
remove unused modules. Narrow entries expose the capabilities you select:

```ts
import { Extractor } from "docture";
import { llm } from "docture/llm/text";
import { fileCache } from "docture/llm/cache";
```

A used convenience class keeps the implementations its methods reference. In particular,
`LLM` creates text, vision, classification, layout, and split components. There is no
universal guarantee that unused class methods or runtime branches disappear. Prefer
`llm()` from `docture/llm/text` when only text extraction is needed.

Unbundled Node.js execution and dependencies externalized by an application build are not
tree-shaken. Actual bundle contents depend on the bundler, configuration, and imports.
