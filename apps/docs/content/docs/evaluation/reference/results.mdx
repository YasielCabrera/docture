Import result building and parsing from `@docture/eval` to create or read the versioned `EvalResult`. [Save, resume, and re-score evaluation runs](/docs/evaluation/run-history) shows stored results in use.

## `@docture/eval`

Saved results use format `docture-eval-result`, version 1. The public JSON Schema is available at `@docture/eval/result-v1.schema.json`. `result.json` holds metadata and `cases.jsonl` holds case rows.

### `buildResult`

```ts
buildResult(input: BuildResultInput): EvalResult
```

Takes [`BuildResultInput`](/docs/evaluation/reference/results#buildresultinput). Returns [`EvalResult`](/docs/evaluation/reference/types#evalresult).

Assemble a complete result from case rows: per experiment, the overall metrics, segment, slice, path and field-type summaries, and epoch variance. A project that runs its own loop can build rows itself and still use every reporter.

### `parseCaseResult`

```ts
parseCaseResult(json: unknown): CaseResult
```

Returns [`CaseResult`](/docs/evaluation/reference/types#caseresult).

Validate one line of `cases.jsonl` against `result-v1.schema.json`. Throws `RunStoreError` with reason `format` naming the first bad path.

### `parseEvalResult`

```ts
parseEvalResult(json: unknown): EvalResult
```

Returns [`EvalResult`](/docs/evaluation/reference/types#evalresult).

Validate a complete parsed `EvalResult`, including its `cases` array, against `result-v1.schema.json`, every nested member included. A single-file result from `renderJson` parses directly. A stored `result.json` omits `cases`, so read the split `result.json` and `cases.jsonl` layout with [`readEvalResult`](/docs/evaluation/reference/storage#readevalresult) from `@docture/eval/node`, which assembles both files before validation. Throws `RunStoreError` with reason `version` for another format version, or `format` naming the first path that does not fit version 1.

### `parseRunInfo`

```ts
parseRunInfo(json: unknown): RunInfo
```

Returns [`RunInfo`](/docs/evaluation/reference/types#runinfo).

Validate run metadata, such as a stored `run.json`, against the run definition in `result-v1.schema.json`. Throws `RunStoreError` with reason `format` naming the first bad path.

## Types

### `BuildResultInput`

Everything `buildResult` assembles into an `EvalResult`.

```ts
interface BuildResultInput {
	readonly run: RunInfo;
	readonly cases: readonly CaseResult[];
	/** Added after the built-in metrics. An id that repeats a built-in or another metric is an error. */
	readonly metrics?: readonly MetricDefinition[];
	/** Slices computed from each row, merged over the slice values rows already carry. */
	readonly slices?: Readonly<Record<string, SliceSpec<CaseResult>>>;
	readonly calibration?: CalibrationReport;
	readonly grounding?: GroundingReport;
	readonly comparison?: RunComparison;
	readonly gate?: GateResult;
	readonly warnings?: readonly string[];
	readonly extensions?: Readonly<Record<string, JsonValue>>;
}
```
