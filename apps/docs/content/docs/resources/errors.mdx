Pipeline failures extend `DoctureError` and carry a literal `code`. Ordinary component
errors may also appear inside attempts. [How Docture works](/docs/getting-started/how-it-works)
describes the stages that raise them.

`DoctureErrorCode` is the union of every code in the table below.

Import the classes and helpers from `docture`.

```ts
import { isDoctureError } from "docture";

try {
  await extractor.extract("invoice.pdf", Invoice);
} catch (error) {
  if (isDoctureError(error, "TIMEOUT")) {
    console.error(`${error.stage} exceeded ${error.ms} ms`);
  } else if (isDoctureError(error)) {
    console.error(error.code, error.message, error.hint);
  }
}
```

Every `DoctureError` has a `hint` that names the next step, such as the option to raise
or the call to make.

## Error catalogue

| Code | Class | Fields | Meaning and recovery |
| --- | --- | --- | --- |
| `NO_ELIGIBLE_LOADER` | `NoEligibleLoaderError` | `mimeType`, `gaps` | No configured loader accepts the media type. Add or configure a loader. |
| `LOAD_FAILED` | `LoadFailedError` | `attempts` | Every eligible loader failed. Inspect its loader attempts for corrupt, encrypted, or unsupported input. |
| `NO_CONVERTIBLE_CONTENT` | `NoConvertibleContentError` | `features` | No eligible loader returned indexable text. For a scan, list an OCR loader after the text-layer loader. For a mixed document, wrap the text-layer loader with `withOcrFallback`. |
| `NO_ELIGIBLE_STRATEGY` | `NoEligibleStrategyError` | `features`, `gaps` | The document loaded, but no requested strategy satisfies its runtime requirements. Add a suitable strategy or rasterizer. |
| `EXTRACTION_FAILED` | `ExtractionFailedError` | `attempts`, `usage` when reported | Every eligible strategy failed. The attempts contain each strategy error and code. |
| `PAGE_OUT_OF_RANGE` | `PageSelectionError` | `missingPages`, `pageCount`, `maxPages?`, `loadedPages?` | The page selection is empty, names pages absent from the document, names pages past a `maxPages` limit (`maxPages` set), or names pages the loader did not return (`loadedPages` set, and `pageCount` counts those pages). Select existing 1-based pages. |
| `MODEL_OUTPUT_FAILED` | `ModelOutputError` | `usage`, `rawOutput`, `finishReason`, `issues` when reported, `cause` | A billed model response failed its requested schema. Inspect the schema and instructions. Failed extraction attempts retain the call's usage. |
| `CONTRACT_VIOLATION` | `ContractViolationError` | `strategy`, `issues`, `failedCheck`, `attempts`, `usage` when reported | Strategy output did not pass the requested schema (`failedCheck: "schema"`), or schema-valid output failed a validation rule in `"fail"` mode (`failedCheck: "rule"`). Adjust the schema, parser, or prompt for a schema failure. Check the document and the rule for a rule failure, or use `"report"` mode to keep the data with its issues. |
| `UNSUPPORTED_SOURCE` | `UnsupportedSourceError` | `cause` when supplied | The source uses an unsupported protocol, a file path or `file:` URL cannot be read, an HTTP request failed, the input is empty, or a loaded source was passed to `resolveSource()`. A file read failure keeps the file-system error, with its `code`, as `cause`. |
| `TIMEOUT` | `TimeoutError` | `stage`, `ms` | A library-owned deadline elapsed. For `stageTimeoutMs`, `stage` names the stage and component, and a later loader or strategy may still run. For a whole-call `timeoutMs`, `stage` is `"call"` and the call stops. |
| `DUPLICATE_COMPONENT` | `DuplicateComponentError` | `kind`, `componentName` | Two registered components share a name. Rename or remove one component. A second `loadLlm()` of the same model is a duplicate; register vision and classification in the first call. |
| `SPLIT_FAILED` | `SplitFailedError` | `reason`, `gaps`, `coverage` when groups do not cover the bundle | Splitting was not configured, the splitter requirements were not met, or the splitter's groups did not hold every page exactly once. `coverage`, a `SplitCoverage`, lists the `overlaps`, `missing` and `unknown` page numbers. |
| `UNCLASSIFIED_GROUP` | `UnclassifiedGroupError` | `pages`, `classification`, `candidates` | A split group did not match the allowed kinds. Add the kind or handle it explicitly. |
| `MISSING_COMPONENT` | `MissingComponentError` | `message` | Required wiring or call state is missing. Configure the named component or call loadFile first. |
| `DISPOSED` | `DisposedError` | `component` | A `DocumentConverter` was used after `dispose()`. Create a new converter. A conversion in flight when `dispose()` runs stops before its next loader or page. |
| `INVALID_OPTION` | `InvalidOptionError` | `option`, `expected`, `received` | An option or argument is outside the values it accepts, such as `concurrency: 0` or `maxRepairs: -1`. The hint names the option and the accepted values. The CLI exits with code 2. |
| `DOCLING_FAILED` | `DoclingServeError` from `docture/loaders/docling` | `reason`, `outcome`, `status`, `taskId` | Docling Serve rejected the request or returned no usable conversion. In a pipeline it is a loader attempt's `errorCode`. |
| `DOCX_FAILED` | `MammothDocumentError` from `docture/loaders/mammoth` | `cause` | Mammoth could not read the DOCX file. In a pipeline it is a loader attempt's `errorCode`. |
| `EMAIL_INVALID` | `EmailInputError` from `docture/inputs/email` | `cause` when supplied | The input is not a readable RFC email, or it exceeds a configured limit. |
| `MISSING_ENGINE` | `MissingEngineError` | `engine`, `range`, `entry`, `cause` | The selected integration could not initialize its engine because the optional peer is not installed. Install `engine` at a version in `range` beside `docture`. |
| `EVAL_SPEC_INVALID` | `EvalSpecError` from `@docture/eval` | `problems` | An eval spec, rule set or metric set cannot be resolved. Each problem names a schema path or rule. Add the missing rule, segment or alignment, or remove the rule that matches nothing. |
| `GROUND_TRUTH_INVALID` | `GroundTruthError` from `@docture/eval` | `caseIds`, `cases` (each with `caseId` and `issues`) | Expected values do not satisfy the eval spec. The error names every failing case. Correct the listed paths in the expected values, or change the spec. |
| `EVAL_DATASET_INVALID` | `DatasetError` from `@docture/eval` | `caseId` when known, `cause` when supplied | A dataset cannot produce its cases: a document or expected file is missing, a draft is not signed off, or a selected case id is unknown. |
| `EVAL_RUN_STORE_FAILED` | `RunStoreError` from `@docture/eval` | `reason`, `cause` when supplied | A stored run or result cannot be read or written. `reason` is `not-found`, `format`, `version`, `conflict` or `io`. |
| `OUT_OF_SCOPE` | `OutOfScopeError` from `@docture/eval` | `reason` | An eval processor declined a case. The runner records a skip, not a failure. |
| `MIGRATION_GUARD_FAILED` | `MigrationGuardError` from `@docture/eval` | `migration`, `paths`, `caseId` when a case failed | A ground-truth migration has invalid targets, changed paths outside its declared targets, or gave a different result when applied twice. |
| `EVAL_RUNS_INCOMPARABLE` | `IncomparableRunsError` from `@docture/eval` | `problems` | Two runs cannot be paired for comparison: no shared experiment, an unknown experiment, or a case and epoch recorded twice. Select the experiments explicitly or rerun the duplicated cases. |
| `EVAL_PREFLIGHT_FAILED` | `PreflightError` from `@docture/eval` | `experiment`, `cause` | An experiment's `preflight` check failed before any case ran. Fix the setup the cause names, such as a missing credential or engine. |
| `SYNTHESIS_FAILED` | `SynthesisError` from `@docture/synthetic` | `problems` | A model could not sample a value that satisfies its schema, constraints and scenario. Each problem names a path or constraint. Fix the generator, `derive` or constraint it names, or the scenario whose `expect` failed. |
| `TEMPLATE_INVALID` | `TemplateError` from `@docture/synthetic` | `template`, `problems` | A template drew a field its printed mask does not declare, never drew a declared field, used a glyph its font lacks, or threw while drawing. Each problem has a `code` and path. Declare the field, draw it, or embed a font that has the glyph. |
| `LABEL_VERIFICATION_FAILED` | `LabelVerificationError` from `@docture/synthetic` | `failures` | A rendered document does not show a labeled value inside its labeled box, or a box leaves the page. Each failure names the path, page and kind: `missing`, `outside-box` or `page-overflow`. Move or shrink the drawn text. |

## Constructors

```ts
abstract class DoctureError extends Error
new NoEligibleLoaderError(mimeType: string, gaps: readonly Ineligibility[])
new LoadFailedError(attempts: readonly Attempt[])
new NoConvertibleContentError(features: DocumentFeatures)
new NoEligibleStrategyError(features: DocumentFeatures, gaps: readonly Ineligibility[])
new ExtractionFailedError(attempts: readonly Attempt[], options?: { usage?: Usage })
new PageSelectionError(missingPages: readonly number[], pageCount: number, options?: {
  maxPages?: number; loadedPages?: readonly number[];
})
new ModelOutputError(message: string, options?: {
  cause?: unknown; usage?: Partial<Usage>; rawOutput?: string;
  finishReason?: string; issues?: readonly ValidationIssue[];
})
new ContractViolationError(strategy: string, issues: readonly ValidationIssue[], options?: {
  failedCheck?: "schema" | "rule"; attempts?: readonly Attempt[]; usage?: Usage;
})
new UnsupportedSourceError(message: string, options?: { cause?: unknown })
new TimeoutError(stage: string, ms: number)
new DuplicateComponentError(kind: string, componentName: string, fix?: string)
new SplitFailedError(reason: string, gaps?: readonly Ineligibility[])
new UnclassifiedGroupError(
  pages: readonly number[],
  classification: string,
  candidates: readonly string[],
)
new MissingComponentError(message: string)
new MissingEngineError(engine: string, range: string, entry: string, options?: { cause?: unknown })
```

`Ineligibility` has a component `name`, a human-readable `reason`, and optional
`missing` document facts.

## Missing optional engines

The PDF.js, MuPDF, Tesseract, PaddleOCR, and canvas integrations import their engines on
first use. If the engine package is not installed, the integration throws
`MissingEngineError`. Its message names the entry, the package, and the supported range,
for example `docture/loaders/mupdf needs the optional peer mupdf@~1.28.0, which is not
installed`. PaddleOCR also reports a missing `onnxruntime-node`, because the engine
imports ONNX Runtime itself. `cause` keeps the original module-resolution error.

Only a missing engine package produces this error. A damaged file, a missing file inside
an installed engine, a failed native binding, and a caller abort keep their own errors.

When every eligible loader fails because its engine is missing, extraction and
conversion throw that `MissingEngineError` instead of `LoadFailedError`. If another loader
is installed, loading falls back to it and records the missing engine in `attempts`.

## Errors from another installed copy

A package manager can install `docture` more than once, for example once for an
application and once for `@docture/cli` when their AI SDK versions differ. Each Docture
error class recognizes instances created by any installed copy, so `instanceof`,
`errorCodeOf()`, and `isAbortError()` give the same answer for all of them. Subclasses
that an application declares keep ordinary `instanceof` behavior.

## Loader and strategy attempts

`LoadFailedError.attempts` contains every eligible loader failure when loading never
succeeds. After loader fallback succeeds, `ExtractionResult.attempts` contains the failed
loaders followed by the strategy attempts. The successful loader is recorded only in
`result.loader`.

```ts
try {
  await extractor.extract("invoice.pdf", Invoice);
} catch (error) {
  if (error instanceof LoadFailedError) {
    for (const attempt of error.attempts) {
      console.error(attempt.strategy, attempt.error);
    }
  }
}
```

An `Attempt` has required `stage`, `strategy`, `status`, and elapsed `ms`. Optional
fields include `error`, `errorCode`, `usage`, `rawOutput`, `finishReason`, and `issues`.
`stage` is `load`, `classify`, `extract`, `repair`, or `layout`; `strategy` is the component
name. Model `rawOutput` keeps at most 10,000 JavaScript characters.

`ExtractionFailedError.attempts` contains strategy attempts. A final
`ContractViolationError` identifies the first invalid strategy and retains the full
strategy attempt history. Both exhausted errors carry total known usage, including
classification and unsuccessful strategies, so eval cost gates include paid failures.

A strategy that returns invalid data records a failed strategy attempt. Core continues
to the next strategy. If no strategy succeeds, the first validation failure is raised as
`ContractViolationError`. If every strategy threw before validation, core raises
`ExtractionFailedError`.

## Abort and timeout behavior

A caller abort is not wrapped in `DoctureError`. It propagates and stops fallback. This
includes an `AbortError`, a caller-provided `AbortSignal.timeout()` error, and any
custom reason passed to `AbortController.abort(reason)`. The pipeline preserves the
reason even when a component returns a value after cancellation.

A `TimeoutError` is created by `stageTimeoutMs` or `timeoutMs`. Loader and strategy
`stageTimeoutMs` deadlines record a failed attempt and allow fallback. A classifier
deadline is recorded as an abstaining signal so the remaining classifiers can run.

`timeoutMs` bounds the whole call. When it passes, every component's `signal` aborts with
the `TimeoutError`, no further fallback starts, and the call rejects with that error, whose
`stage` is `"call"`. The call rejects on time even when a component ignores its signal. A
caller's own abort keeps its reason.

`isAbortError(error)` recognizes standard abort and timeout errors by shape. The shape
does not say who aborted: a component's own `AbortSignal.timeout()` looks the same as a
caller's cancel. To decide whether to stop or to try the next component, use
`isCallerAbort(error, signal)`. It is true only when `signal` is aborted and `error` is its
reason or an abort-shaped error, so it also covers a custom reason. Use `errorCodeOf(error)` to read a
Docture code without an `instanceof` chain. `messageOf(error)` returns an error message
or converts a non-error value to text.

```ts
isAbortError(error: unknown): boolean
isCallerAbort(error: unknown, signal: AbortSignal | undefined): boolean
errorCodeOf(error: unknown): DoctureErrorCode | undefined
messageOf(error: unknown): string
```

## Non-throwing extraction

`safeExtract()` returns a discriminated result:

```ts
const outcome = await extractor.safeExtract("invoice.pdf", Invoice);

if (outcome.ok) {
  save(outcome.result.data);
} else {
  console.error(outcome.error);
}
```

`extractBatch()` also yields an outcome for each source. One failed source does not reject
the full batch.

For split groups, `Process.extract({ onUnclassified: "skip" })` drops unknown groups. The
default is `"throw"` because dropping pages changes the result set.

## Structured errors

`isDoctureError(value)` narrows unknown values through docture error identity, including
errors from another installed copy. Matching never relies on a class name or code alone.
`isDoctureError(value, code)` also checks the code and narrows to `DoctureErrorOf<code>`,
that code's class, so its fields need no cast. A typo in `code` is a compile error.
`safeExtract()` types its failure as `DoctureError | Error`.

```ts
isDoctureError(value: unknown): value is DoctureError
isDoctureError<C extends DoctureErrorCode>(value: unknown, code: C): value is DoctureErrorOf<C>
```

For a core code, the check matches only an instance of that code's class, from any
installed copy, so the narrowed fields exist at runtime. An error that copies another
error's code does not match. For example, a failure that `@docture/eval` prices keeps its
cause's code for `errorCodeOf()`, but `isDoctureError(failure, "EXTRACTION_FAILED")` is
false. Check `failure.cause` instead. `PaperlessError` and `DoclingImportError` extend
`UnsupportedSourceError`, so they match `"UNSUPPORTED_SOURCE"`.

`LOAD_FAILED` narrows to `LoadFailedError`, whose `attempts` is always present. A code
raised outside core, such as `DOCLING_FAILED` or an eval code, narrows to `DoctureError`
with that code, and the check compares the code.

`DoctureError.toJSON()` returns a `DoctureErrorJson`: `code`, `name`, `message`, `hint`,
every diagnostic field the error carries (such as `attempts`, `issues`, `usage`,
`features`, `gaps`, or `pages`), and `cause`. A nested error becomes
`{ code?, name, message }`, so the result is safe for `JSON.stringify`. Those fields can hold document text or the model's answer, so drop `rawOutput`, `issues`, and `attempts` before you send an error to a log service you do not control. `MissingComponentError` reports missing wiring and call order
with `MISSING_COMPONENT`.

Model errors and attempts can retain `rawOutput`, `finishReason`, and validation `issues`.
Raw output is capped at 10,000 JavaScript string characters.
