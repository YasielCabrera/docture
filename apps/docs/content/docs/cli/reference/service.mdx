---
title: HTTP service
description: Persistent convert, inspect and configured-schema extraction over Node HTTP.
---

`@docture/cli/service` exports `createHttpService`, `HttpService`, `HttpServiceOptions` and `HttpServiceAddress`. Import and construction do not bind a socket or load engines. `start()` creates persistent wiring and returns the bound address. Port 0 selects an ephemeral port. Repeated `start()` calls share readiness. A closed instance cannot restart.

`HttpServiceOptions` accepts `io`, optional loaded `config`, a `schemas` allowlist, startup wiring `flags`, `host`, `port`, `token`, `maxConcurrency`, `maxQueue`, `maxBodyBytes`, `bodyTimeoutMs` and `shutdownTimeoutMs`. Defaults are localhost, port 0, four active requests, sixteen queued requests, sixteen MiB of encoded JSON and thirty-second body and shutdown deadlines. `config.schema` is available as `default`. Explicit schema names override that default at startup. The allowlist and configuration arrays are snapshotted at startup.

`HttpService.address` is absent before startup. `pending` counts admitted active and queued requests. `close()` is idempotent and returns the same promise. It stops admission, drains accepted work, aborts it after the shutdown deadline, waits for actual operation settlement and then disposes shared resources. An engine that ignores cancellation can extend shutdown beyond the drain deadline. Resources are never disposed underneath an unsettled operation.

`HttpServiceAddress` contains `host`, `port` and `url`. An external host requires a bearer token from options or `DOCTURE_SERVE_TOKEN`. Tokens never enter request JSON or readiness output.

The [HTTP service guide](/docs/cli/http-service) defines request and response formats, limits and source access. The API uses Node `http` without a server framework. Persistent inspect wiring is separate from extraction wiring. Normal completed request bodies do not cancel operations; a real client disconnect does.
