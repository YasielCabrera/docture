`@docture/cli` runs the `docture` command as a function, types its configuration, and starts its MCP server. Import from `@docture/cli`, `@docture/cli/config`, and `@docture/cli/mcp`.

## Configuration

### `defineConfig`

Identity helper that types a `docture.config.ts` default export. Import it from `@docture/cli/config`.

```ts
defineConfig(config: DoctureConfig): DoctureConfig
```

Returns `config` unchanged. `@docture/cli/config` has no runtime imports, so a tool that reads a config loads neither the CLI nor `docture`. The root `@docture/cli` entry also exports `defineConfig` and `DoctureConfig`. See [Configure the CLI](/docs/cli/configuration).

### `DoctureConfig`

The shape of a `docture.config.ts` default export.

{/* options: DoctureConfig */}
| Field | Type | Meaning |
| --- | --- | --- |
| `extractor` | `CliExtractor` or a function returning one, directly or through a promise | A complete extractor. When present, the CLI ignores the component fields for extraction |
| `converter` | `CliConverter` or a function returning one, directly or through a promise | A complete converter used by `docture convert` |
| `loaders` | `readonly DocumentLoader[]` | Document loaders |
| `strategies` | `readonly ExtractionStrategy[]` | Extraction strategies. When present, the CLI builds no strategies and ignores `--model` |
| `classifiers` | `readonly Classifier[]` | Classifiers |
| `classifications` | `readonly Classification[]` | Classifications |
| `policy` | `RoutingPolicy` | Strategy routing policy |
| `stageTimeoutMs` | `number` | Per-stage deadline |
| `layoutAnalyzer` | `LayoutAnalyzer` | Deterministic conversion refinement, used unless `--assist-layout` supplies one |
| `model` | `LanguageModel` | A model instance or a `provider/id` string. Used when `strategies` is absent |
| `vision` | `boolean` | Also register a vision strategy. Used when `strategies` is absent |
| `pricing` | `PricingTable` | USD per million tokens by model id. Without it, cost is unknown |
| `instructions` | `string` | Text appended to the system prompt |
| `schema` | `FlexibleSchema` | Default schema when `--schema` is not passed. The MCP `extract` tool also uses it |
| `schemas` | `Readonly<Record<string, ContractLike>>` | Named contracts that MCP `extract` may select |
| `cacheDir` | `string` | Model response cache. A relative path resolves against the config file |
| `concurrency` | `number` | Extraction concurrency |
| `paperless` | `PaperlessCliConfig` | Paperless connection and mappings |

Command-line flags override config defaults. The CLI disposes what it composes. `docture review` renders pages with the configured `loaders` and disposes them when it finishes or fails, including when the input or schema cannot be read and when a complete `extractor` or `converter` is present. A loader that the config also passes to its own converter or extractor is disposed once. Invalid config fields and unknown keys are usage errors that name the field.

### `CliExtractor`

The extractor methods the CLI calls.

```ts
type CliExtractor = Pick<Extractor, "extract" | "extractBatch" | "classify" | "dispose">
```

An `Extractor` built by another installed copy of `docture` satisfies it. Import it from `@docture/cli/config`.

### `CliConverter`

The converter methods the CLI calls.

```ts
type CliConverter = Pick<DocumentConverter, "convertBatch" | "dispose">
```

A `DocumentConverter` built by another installed copy of `docture` satisfies it. Import it from `@docture/cli/config`.

## Run the CLI in process

### `run`

Runs one `docture` invocation without spawning a process.

```ts
run(argv: readonly string[], options: RunOptions): Promise<ExitCode>
```

`argv` excludes the executable, for example `["inspect", "invoice.pdf"]`. `run()` writes through `options.io` and resolves to an exit code. It reports user and document errors as exit codes instead of rejecting.

### `RunOptions`

| Field | Type | Meaning |
| --- | --- | --- |
| `io` | `Io` | Required. The streams, working directory, and environment of the run |
| `signal` | `AbortSignal` | Stops the pipeline between stages when aborted |

### `ExitCode`

```ts check
type ExitCode = 0 | 1 | 2
```

`0` is success, `1` is a command or document failure, and `2` is a usage or configuration failure. The `docture` executable exits with `130` on SIGINT.

## I/O

### `Io`

The streams, working directory, and environment that a run reads and writes.

{/* options: Io */}
| Member | Type | Meaning |
| --- | --- | --- |
| `write` | `(chunk: string) => void` | Machine-readable output for stdout |
| `diagnostic` | `(chunk: string) => void` | Progress, warnings, errors, and summaries for stderr |
| `readStdin` | `(signal?: AbortSignal) => Promise<Uint8Array>` | The bytes behind a `-` file argument. Called at most once per run, and never under `--dry-run` |
| `cwd` | `string` | Directory that relative paths resolve against |
| `env` | `Readonly<Record<string, string \| undefined>>` | Environment variables |
| `color` | `boolean` | Whether stderr takes ANSI color |
| `stdoutColor` | `boolean` | Whether stdout takes ANSI color |

A host without stdin returns an empty `Uint8Array` from `readStdin()`. Both color flags honor `NO_COLOR` and `--no-color`. JSON and NDJSON error messages and hints strip terminal control sequences.

### `processIo`

Binds an `Io` to the current Node process.

```ts
processIo(): Io
```

Honors `NO_COLOR`. Its `readStdin(signal)` rejects with the signal's reason as soon as the signal aborts, even while stdin is open and idle, and destroys stdin so the process can exit.

### `captureIo`

Creates an `Io` that collects both streams in memory, for tests and wrappers.

```ts
captureIo(overrides?: CaptureOptions): CapturedIo
```

Defaults to the current directory, an empty environment, no color, and empty stdin.

### `CaptureOptions`

{/* options: CaptureOptions */}
| Field | Type | Meaning |
| --- | --- | --- |
| `write` | `(chunk: string) => void` | Replaces the stdout collector |
| `diagnostic` | `(chunk: string) => void` | Replaces the stderr collector |
| `cwd` | `string` | Working directory. Default: `process.cwd()` |
| `env` | `Readonly<Record<string, string \| undefined>>` | Environment. Default: empty |
| `color` | `boolean` | stderr color. Default: `false` |
| `stdoutColor` | `boolean` | stdout color. Default: `false` |
| `stdin` | `Uint8Array` | The bytes `readStdin()` returns. Default: empty |

### `CapturedIo`

An `Io` with two extra read-only fields, `stdout` and `stderr`, holding everything written to each stream.

```ts
interface CapturedIo extends Io {
  readonly stdout: string;
  readonly stderr: string;
}
```

### `Style`

The text styling functions the CLI uses: `bold`, `dim`, `red`, `green`, `yellow`, and `cyan`, each `(text: string) => string`.

### `styleFor`

```ts
styleFor(color: boolean): Style
```

`styleFor(false)` returns functions that return text unchanged. `styleFor(true)` returns ANSI styling.

## Errors

### `UsageError`

An invalid invocation or configuration. `exitCode` is `2`.

```ts
new UsageError(message: string, hint?: string)
```

### `CliError`

A command failure. `exitCode` is `1`.

```ts
new CliError(message: string, hint?: string, options?: { cause?: unknown })
```

### `explain`

Turns any thrown value into a printable message, code, and hint.

```ts
explain(error: unknown): Explained
```

Core `DoctureError` codes are preserved, with recovery hints added. `UsageError` maps to `USAGE`, `CliError` to `CLI`, and any other value to `INTERNAL`.

### `Explained`

```ts check
interface Explained {
  readonly message: string;
  readonly code: string;
  readonly hint?: string;
}
```

## MCP server

### `createMcpServer`

Creates the MCP server that `docture mcp` serves, with the `convert`, `inspect`, `extract`, and configured Paperless tools. Import it from `@docture/cli/mcp`.

```ts
createMcpServer(options: McpServerOptions): Promise<McpServer>
```

Returns the SDK's `McpServer`. Connect it to any SDK transport:

```ts
import { processIo } from "@docture/cli";
import { createMcpServer } from "@docture/cli/mcp";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";

const server = await createMcpServer({ io: processIo() });
await server.connect(new StdioServerTransport());
```

The server owns the tool handlers, so register no further tools on it. It never calls `io.write()`. Configuration is fixed for the server's lifetime and pipelines stay loaded across calls. `server.close()` cancels active calls, waits for them to settle, and disposes shared configured resources once.

Rejects with `MissingEngineError` naming the range in `ENGINE_RANGES` when `@modelcontextprotocol/sdk` is not installed. The root `@docture/cli` entry never loads the SDK. See [Connect an MCP host](/docs/cli/mcp) and the [MCP tool reference](/docs/cli/mcp-tools).

### `McpServerOptions`

{/* options: McpServerOptions */}
| Field | Type | Meaning |
| --- | --- | --- |
| `io` | `Io` | Required. `cwd` resolves relative sources and the config. `diagnostic()` receives warnings |
| `signal` | `AbortSignal` | Cancels every call in flight when aborted |
| `configPath` | `string` | Config file to use instead of the nearest `docture.config.*`, like `--config` |
| `noConfig` | `boolean` | Ignore any config file, like `--no-config` |

### `ENGINE_RANGES`

The supported version range of the MCP SDK peer.

```ts
const ENGINE_RANGES: { readonly "@modelcontextprotocol/sdk": "1.32.2" }
```

## Version

### `version`

```ts
version(): string
```

Returns the package version and caches it. Returns `0.0.0` instead of throwing when the package metadata cannot be read.

## Configure named extraction and Paperless mappings

`DoctureConfig.schemas` allowlists named contracts for MCP `extract`, and `schema` stays the default. Model input can select a configured name and source, but cannot replace the schema, model, or server credentials. CLI `paperless` actions and MCP Paperless tools share the library source and sink. See [Paperless workflows](/docs/integrations/paperless-workflow).

### `PaperlessCliConfig`

The `paperless` field of `DoctureConfig`.

{/* options: PaperlessCliConfig */}
| Field | Type | Meaning |
| --- | --- | --- |
| `connection` | `PaperlessConnectionOptions` | Required. The Paperless instance and credentials |
| `schemas` | `Readonly<Record<string, PaperlessSchemaConfig>>` | Required. Named schemas and mappings that actions select with `--schema` or `schemaName` |
| `enableApply` | `boolean` | Allows `apply`. Without it, MCP does not list `paperless_apply` and the CLI rejects apply |
| `maxResults` | `number` | Upper bound on query results, at most 1000. Default: 100 |

`docture paperless apply --dry-run` prints the plan and writes no Paperless metadata.

### `PaperlessSchemaConfig`

One named mapping from an extraction contract to Paperless fields.

{/* options: PaperlessSchemaConfig */}
| Field | Type | Meaning |
| --- | --- | --- |
| `contract` | `ContractLike` | Required. The extraction contract |
| `source` | `{ mode: "content" \| "archive" \| "original"; archiveFallback?: "original" }` | Required. Which Paperless variant to read |
| `mappingId` | `string` | Required. Stable identity of this mapping |
| `fields` | `readonly PaperlessFieldMapping[]` | Required. Existing Paperless custom field IDs for each extracted path |
| `tagIds` | `readonly number[]` | Tags to add |
| `auditNote` | `string` | Note that each plan adds to the document, 1 to 8192 characters |
| `evidence` | `PaperlessEvidencePolicy` | Citation status a value needs before it is written: `"verified"`, `"cited"`, or `"any"`. Default: `"verified"` |
