Install and import from `@docture/cli`. The executable name is `docture`.

## Configuration

```ts
defineConfig(config: DoctureConfig): DoctureConfig
```

`defineConfig()` is an identity helper for `docture.config.ts` type inference. Import it
from `@docture/cli/config`. That entry has no runtime imports, so a tool that reads a
config loads neither the CLI nor `docture`. The root `@docture/cli` entry still exports
`defineConfig` and `DoctureConfig`.

`DoctureConfig` may provide a complete `extractor` or `converter`, or its component parts: `loaders`,
`strategies`, `classifiers`, `classifications`, `policy`, and `stageTimeoutMs`. When a
complete composition root is present, its component fields are ignored. Conversion may
also provide a `layoutAnalyzer`.

`extractor` and `converter` accept the value or a function that returns it, directly or
through a promise. Their types name only the methods the CLI calls: `extract`,
`extractBatch`, `classify`, and `dispose` for an extractor, and `convertBatch` and
`dispose` for a converter, and `@docture/cli/config` exports them as `CliExtractor` and
`CliConverter`. An `Extractor` or `DocumentConverter` built by another installed copy of
`docture` therefore satisfies them.

The CLI disposes what it composes. `docture review` renders pages with the configured
`loaders` and disposes them when it finishes or fails, including when the input or schema
cannot be read and when a complete `extractor` or `converter` is present. A loader in
`loaders` that the config also passes to its own converter or extractor is disposed once.

When explicit strategies are absent, config may provide `model`, `vision`, `pricing`, and
`instructions`. It may also provide a default `schema`, model `cacheDir`, and extraction
`concurrency`. Command-line flags override config defaults.

## Run the CLI in process

```ts
run(argv: readonly string[], options: RunOptions): Promise<ExitCode>
```

The CLI `RunOptions` type contains required `io` and optional abort `signal`. `run()`
returns `0`, `1`, or `2` and writes through the supplied I/O object. It reports user and
document errors as an exit code instead of rejecting in normal operation.

`ExitCode` is `0 | 1 | 2`: success, command or document failure, and usage or
configuration failure. The process executable uses exit code `130` for SIGINT.

## I/O

`Io` has `write()` for stdout data, `diagnostic()` for stderr messages,
`readStdin(signal?)` for the bytes behind a `-` file argument, plus `cwd`, `env`, and color
support. The CLI calls `readStdin()` at most once per run, and never under `--dry-run`. A
host without stdin returns an empty `Uint8Array`. `Style` contains the text styling
functions used by the CLI.

```ts
processIo(): Io
captureIo(overrides?: CaptureOptions): CapturedIo
styleFor(color: boolean): Style
```

`processIo()` binds the interface to the current Node process and honors `NO_COLOR`.
Its `readStdin(signal)` rejects with the signal's reason as soon as the signal aborts,
even while stdin is open and idle, and destroys stdin so the process can exit.
`CaptureOptions` accepts any `Io` field except `readStdin`, plus `stdin`, the bytes its
`readStdin()` returns.
`captureIo()` defaults to the current directory, an empty environment, no color, and empty
stdin. Its
`CapturedIo` result exposes accumulated `stdout` and `stderr`. `styleFor(false)` returns
plain text functions; `true` returns ANSI styling.

## Errors

```ts
new UsageError(message: string, hint?: string)
new CliError(message: string, hint?: string, options?: { cause?: unknown })
explain(error: unknown): Explained
```

`UsageError` has exit code `2`. `CliError` has exit code `1`. `Explained` contains a
required message and code, plus an optional hint. `explain()` preserves core
`DoctureError` codes and adds recovery hints. Other errors use `USAGE`, `CLI`, or
`INTERNAL` and a printable message.

## MCP server

Import from `@docture/cli/mcp`. It needs the optional peer
`@modelcontextprotocol/sdk@1.32.2`; `@docture/cli` itself never loads it.

```ts
createMcpServer(options: McpServerOptions): Promise<McpServer>
ENGINE_RANGES: { "@modelcontextprotocol/sdk": "1.32.2" }
```

`createMcpServer()` returns the SDK's `McpServer` with `convert`, `inspect`, configured `extract`, and configured Paperless tools
that `docture mcp` serves. Connect it to any SDK transport:

```ts
import { processIo } from "@docture/cli";
import { createMcpServer } from "@docture/cli/mcp";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";

const server = await createMcpServer({ io: processIo() });
await server.connect(new StdioServerTransport());
```

`McpServerOptions` contains required `io`, whose `cwd` resolves relative sources and the
config and whose `diagnostic()` receives warnings. Optional `signal` cancels every call in
flight. Optional `configPath` and `noConfig` match `--config` and `--no-config`. The server
never calls `io.write()`. It owns the tools handlers, so register no further tools on it.
Without the SDK, `createMcpServer()` rejects with `MissingEngineError` naming the range in
`ENGINE_RANGES`. See the [CLI guide](/docs/cli/mcp#mcp-server) for tool arguments and
results.

## Version

```ts
version(): string
```

`version()` reads and caches the package version. If package metadata cannot be read, it
returns `0.0.0` instead of throwing.

See the [CLI guide](/docs/cli/quick-start) for commands, flags, streams, configuration files,
and CI use.

Known provider routes and gateway model strings require credentials before document
processing. A cache-enabled run may continue without a key to reuse cached responses.
Configured model strings use the SDK gateway route and its credential checks. A
configured provider instance controls its own credentials and supports keyless compatible
endpoints. Missing dependencies name the failed import and suggest installation or a
corrected path. Invalid config fields and unknown keys are usage errors naming the field.

`Io.stdoutColor` controls stdout styling independently of diagnostic `Io.color`. Both
honor `NO_COLOR` and `--no-color`. JSON and NDJSON error messages and hints strip terminal
control sequences.

Quick-mode `eval --min-f1 <number> --max-cost-usd <number>` gates the run's
`meanDocumentF1` and `costUsd` metrics with the public eval gate. `meanDocumentF1` is the
mean of per-document F1. A failed extraction scores 0, so every document weighs the same.
The JSON summary reports it as `meanF1`, beside the per-document `meanPrecision` and
`meanRecall`. Its `metrics` holds `meanDocumentF1` and `f1`, the field F1 pooled over every
field. Cost includes the usage that failed extractions reported. Cost requires configured
pricing. Unpriced usage is excluded, and a cost gate fails when no price is known.

Failed thresholds exit with code 1, including when extraction itself succeeds. The output
summary contains `passed`, `reasons`, and the configured `minF1` and `maxCostUsd`. A reason
names its flag, such as `Mean F1 0.500 is below the --min-f1 gate of 0.9.` Any other failed
check keeps the gate's message. Verbose output includes the worst fields.

`docture eval run` saves the result even when a reporter fails. It then prints each reporter
failure on stderr, also under `--quiet`, and exits with code 1. `docture eval report <dir>
--rescore` reads the run and its raw outputs from that directory and writes the re-scored
run to the configured store or `--store`. `docture.eval.ts` accepts `sections`, such as
`calibrationSection()`, and `fallbackBranch`, the branch an automatic baseline searches when
the current branch has no complete run.

## Configure named extraction and Paperless mappings

`DoctureConfig.schemas` allowlists named caller contracts for MCP `extract`; `schema` remains the default. Model input can select a configured name and source, but cannot replace schema, model or server credentials. Full extraction envelopes retain citations, native evidenceSources, validation and conflicts.

`PaperlessCliConfig` configures the connection, named schemas, query bound and `enableApply` gate. Each `PaperlessSchemaConfig` supplies a caller contract, source variant, mapping identity, existing field IDs, additive tag IDs and evidence policy. CLI `paperless` actions and MCP Paperless tools share the library source and sink. Apply is absent from default MCP listings and rejected unless enabled in config. CLI `--dry-run` prints the plan and writes no Paperless metadata.

MCP configuration is fixed for the server lifetime. Pipelines stay warm across calls. `server.close()` cancels active calls, waits for settlement, and disposes shared configured resources once. Like the HTTP service, it waits for cancellation-ignoring engines to finish before disposal.
