---
title: Build a Docture container
description: Build the two package artifacts into a Linux PDF service image.
---

The Dockerfile packs `docture` and `@docture/cli` from this checkout and installs those tarballs in a Node 22 Debian runtime. Its selected target is Linux amd64 with PDF.js 6.2.108, native canvas 1.0.10 and its GNU x64 binding. It includes fonts and Zod 4.4.3. OCR engines, OCR models and MuPDF are absent. Model calls require explicit caller configuration and credentials.

```sh
pnpm install --frozen-lockfile
pnpm --filter docture --filter @docture/cli -r build
docker build --platform linux/amd64 --tag docture:local .
node scripts/container-smoke.mjs docture:local
```

The smoke script mounts a generated PDF, converts it through the actual CLI, renders it through the selected native canvas pair, compares HTTP conversion and inspection with the CLI, exercises configured extraction, and checks graceful SIGTERM exit. Run this check before claiming support for the image or platform. `node --test scripts/container-build.test.mjs` runs the recipe check and attempts the real build when a Linux Docker daemon is available. Without a working daemon, it reports the image/native-platform check as skipped. Set `RUN_CONTAINER=1` to require it.

Convert a mounted file with the container command.

```sh
docker run --rm --platform linux/amd64 -v "$PWD:/work" docture:local convert report.pdf --out converted --to txt --no-config
```

The process runs as the image's `node` user. Make the mounted output directory writable by that user. Input filenames are never interpreted as host paths outside the mounted directories.

For a service, mount configuration at `/opt/docture/docture.config.mjs` so its ESM imports resolve beside the installed packages. Supply the token through the environment. The following command reads `DOCTURE_SERVE_TOKEN` from your existing environment.

```sh
docker run --rm --platform linux/amd64 --stop-timeout 45 -p 8787:8787 -e DOCTURE_SERVE_TOKEN -v "$PWD/docture.config.mjs:/opt/docture/docture.config.mjs:ro" docture:local serve --host 0.0.0.0 --port 8787 --config /opt/docture/docture.config.mjs
```

The runtime contains no bundled model files. Provision licensed model assets and install the corresponding exact optional engine in a separate derived image before configuring OCR. Do not treat first-use downloads as offline deployment. The initial recipe has no tested OCR or other-architecture claim.

The manual container-release workflow takes a Git ref and a tag matching the CLI artifact version, builds and runs the smoke check, then publishes only if its `publish` input is true. Tags are `<version>` and `<version>-linux-amd64`; it creates no `latest` tag. `/opt/docture/versions.json` records both package versions, the selected engine versions, Node and platform. Adding the workflow does not publish an image.

See the [HTTP service guide](/docs/cli/http-service) for the byte-only request protocol, authentication, bounds and shutdown behavior.
