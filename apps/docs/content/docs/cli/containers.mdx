The repository's Dockerfile builds a Linux image whose entry point is the `docture` command. It packs `docture` and `@docture/cli` from a checkout and installs those tarballs in a Node 22 Debian runtime.

## Know what the image contains

The image targets Linux amd64 with PDF.js 6.2.108, native canvas 1.0.10 and its GNU x64 binding, fonts, and Zod 4.4.3. OCR engines, OCR models, and MuPDF are absent. Model calls require explicit caller configuration and credentials. `/opt/docture/versions.json` records the Node version, the platform, and the installed package versions.

## Build and check the image

From the repository root:

```sh
pnpm install --frozen-lockfile
pnpm --filter docture --filter @docture/cli -r build
docker build --platform linux/amd64 --tag docture:local .
node scripts/container-smoke.mjs docture:local
```

The smoke script mounts a generated PDF and converts it through the CLI. It renders the PDF with the native canvas package, compares HTTP conversion and inspection with the CLI, runs a configured extraction, and checks that SIGTERM exits cleanly. Run it before you rely on the image on a new platform.

## Convert a mounted file

```sh
docker run --rm --platform linux/amd64 -v "$PWD:/work" docture:local convert report.pdf --out converted --to txt --no-config
```

The process runs as the image's `node` user, so make the mounted output directory writable by that user. The container sees only the directories you mount.

## Run the HTTP service

Mount the configuration at `/opt/docture/docture.config.mjs` so its ESM imports resolve beside the installed packages. Supply the token through the environment. This command passes `DOCTURE_SERVE_TOKEN` from your shell:

```sh
docker run --rm --platform linux/amd64 --stop-timeout 45 -p 8787:8787 -e DOCTURE_SERVE_TOKEN -v "$PWD/docture.config.mjs:/opt/docture/docture.config.mjs:ro" docture:local serve --host 0.0.0.0 --port 8787 --config /opt/docture/docture.config.mjs
```

`--stop-timeout 45` gives the service longer than its 30-second drain deadline. See [Run a local HTTP service](/docs/cli/http-service) for requests, authentication, limits, and shutdown.

## Add OCR to a derived image

The image contains no model files. To use OCR, build a derived image that installs the OCR engine at its exact supported version and provisions licensed model assets. Do not rely on first-use downloads for an offline deployment. The base recipe makes no OCR or other-architecture support claim.
