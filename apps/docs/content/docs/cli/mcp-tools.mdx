`docture mcp` lists three core tools, plus Paperless tools when the config has Paperless settings. To install and register the server, see [Connect an MCP host](/docs/cli/mcp).

## Core tools

| Tool | Arguments | Result |
| --- | --- | --- |
| `convert` | `source`, optional `format` and one-based `pages` | `content`, `format`, `mimeType`, `pageCount`, `loader`, `method`, and `warnings` |
| `inspect` | `source`, optional one-based `pages` | The same fields as `inspect --format json` |
| `extract` | `source`, optional `schemaName` | Full extraction envelope with validation, citations, conflicts, and native evidence when available |

`format` is `markdown`, `html`, `text`, or `json`. The default is `markdown`. Sources are paths or URLs, never `-`. `pages` keeps the original page numbers, and a page the document lacks fails the item with `PAGE_OUT_OF_RANGE`.

`extract` uses the config's `schema`, or the entry of `schemas` that `schemaName` names. An unknown name fails before extraction. Model input cannot replace a schema, model, connection, or credentials.

## Paperless tools

With Paperless configuration, the server also lists:

| Tool | Selection | Behavior |
| --- | --- | --- |
| `paperless_read` | `documentId`, optional `versionId` | Exact stored OCR text and source identity |
| `paperless_search` | Optional `query` and bounded `limit` | Native search results with full content |
| `paperless_extract` | `schemaName` and either document selection or query | Extraction using the configured source and contract |
| `paperless_plan` | Same selection as extraction | A read-only fill-empty update plan |
| `paperless_apply` | `schemaName`, `plan` | Apply after source and current-value checks. Listed only when `enableApply` is true |

A document selection uses `documentId` and optional `versionId`. A query uses `query` and optional `limit`. Do not combine the two forms. The configuration bounds query results. [Paperless workflows](/docs/integrations/paperless-workflow) explain mapping, evidence, and apply outcomes.

## Results, errors, and shutdown

Tools return the version 1 CLI envelope as structured content and JSON text. Failed operations set `isError`. Invalid arguments to `convert`, `inspect`, and `extract` use JSON-RPC invalid-parameter errors. Invalid Paperless tool arguments return a failed envelope with code `USAGE` and set `isError`. Configuration stays fixed and pipelines stay warm until the server closes. Shutdown cancels active calls, waits for them to settle, and disposes shared resources.

To create the server in Node, see the [MCP server API](/docs/cli/reference/cli#mcp-server).
