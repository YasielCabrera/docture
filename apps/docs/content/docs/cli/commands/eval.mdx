---
title: "docture eval"
description: "Evaluate extraction quality: run, report, compare and gate"
---

Runs the evaluation in docture.eval.ts and works with the runs it stores. Every
subcommand is a thin shell over @docture/eval. Files without a subcommand run quick mode.

## Arguments

| Argument | Required | Meaning |
| --- | --- | --- |
| `command` | No | A subcommand. Default: run |

## Flags

| Flag | Default | Meaning |
| --- | --- | --- |
| `--no-color` | Not set | Never emit ANSI colour |
| `--help`, `-h` | Not set | Show this help |

## Examples

```sh
docture eval run
docture eval compare <baseRunId> latest
docture eval corpus/*.pdf -s ./invoice.ts -m openai/gpt-5 --truth corpus/truth --min-f1 0.95
```

## Behavior

- Exit codes: 0 pass, 1 gate failed or a run failed, 2 usage error.
- `docture eval <command> --help` describes one subcommand.

## Subcommands

- [`docture eval run`](/docs/cli/commands/eval-run). Run an evaluation from docture.eval.ts, or score files against ground truth.
- [`docture eval report`](/docs/cli/commands/eval-report). Re-render a stored run in any format, without running anything.
- [`docture eval compare`](/docs/cli/commands/eval-compare). Compare two runs with paired significance tests.
- [`docture eval gate`](/docs/cli/commands/eval-gate). Apply the config's gate to a stored run.
- [`docture eval runs`](/docs/cli/commands/eval-runs). List stored runs, newest first.
- [`docture eval validate`](/docs/cli/commands/eval-validate). Check every case's ground truth against the spec and list all problems.
- [`docture eval sample`](/docs/cli/commands/eval-sample). Print the case ids of a deterministic stratified sample.
- [`docture eval migrate`](/docs/cli/commands/eval-migrate). Preview or apply a ground-truth migration.
- [`docture eval draft`](/docs/cli/commands/eval-draft). Draft ground truth for cases without signed-off truth.
- [`docture eval sign-off`](/docs/cli/commands/eval-sign-off). Mark a case's drafted ground truth as reviewed.

See [CLI configuration](/docs/cli/configuration) and [input and output behavior](/docs/cli/inputs-and-outputs).
