---
title: Run a local HTTP service
description: Reuse configured document engines across byte-based HTTP requests.
---

Start the service with a caller-selected schema and pipeline configuration.

```sh
docture serve --config ./docture.config.ts --schema note=./note.ts --port 8787
```

The CLI prints one version 1 readiness record with the bound address. Use `--port 0` for an ephemeral port. Repeat `--schema name=module` for several schemas. A plain module is named `default`, and an existing config schema also supplies `default`. Requests select a configured name; they cannot upload executable configuration, arbitrary schemas, model settings or credentials. Restart to refresh configuration.

Send JSON with document bytes encoded as canonical base64.

```json
{
  "document": { "data": "SGVsbG8=", "mimeType": "text/plain", "fileName": "note.txt" },
  "schema": "note"
}
```

POST this extraction request to `/extract`. `/convert` accepts the same document with `format` set to `text`, `markdown`, `html` or `json`. `/inspect` accepts the document without schema or format. All routes accept optional one-based `pages`. Unknown fields fail before any document loads. The service accepts document bytes only; local paths and network source URLs are not request inputs.

Successful operations return the same version 1 envelope shape as the CLI. Extraction includes full data, validation, citation/evidence and conflict fields. Inspection has the CLI's default page/fact report. Conversion returns `content`, `format`, MIME, page count, loader, method and warnings. Assets are embedded, so converted content has no unresolved filesystem asset references. CLI conversion writes its content to a file; compare that file with the service content, excluding output locations and timing.

Document failures remain result envelopes with `ok: false`. Transport errors use HTTP 400 for invalid requests, 401 for invalid authentication, 404 for unknown routes, 405 for methods, 408 for body deadlines, 413 for body limits, 415 for content type and 503 for full capacity or shutdown. stdout carries only the readiness record; diagnostics use stderr.

Localhost is the default binding. To bind another interface, set `DOCTURE_SERVE_TOKEN` in the service environment and use `--host`. Clients send `Authorization: Bearer <token>`. There is no command-line token flag. Run behind your deployment's TLS terminator when clients cross a network.

`--concurrency` bounds active work. `--max-queue` bounds accepted waiting requests before bodies are buffered. `--max-body-bytes` caps encoded JSON bytes, and `--body-timeout` includes queue wait and body receipt. A client disconnect cancels its queued or active operation. Configured loaders and clients stay warm after ordinary request failures.

SIGTERM and the CLI's abort signal stop admission and drain accepted requests. After `--shutdown-timeout`, the service aborts outstanding work and waits for it to settle before disposing each shared resource once. A loader that ignores cancellation can delay final exit. Set your container stop grace period above the drain timeout.

Run `pnpm --dir apps/examples exec tsx 22-http-service/index.ts` for a deterministic port-zero example with conversion, inspection, extraction and disposal assertions. See the [service API](/docs/cli/reference/service) for library startup and shutdown, and the [container guide](/docs/cli/containers) for the Linux build recipe.
