These APIs name the source behind converted content: element IDs, positioned line IDs,
and native evidence records. Import them from `docture`. For a task-based introduction,
see [Trace content to source evidence](/docs/conversion/evidence).

## Element IDs

A page break's ID is `p<page>-page-break`. Every other element's ID is `p<page>-` and 12 hex
characters from a SHA-256 digest of these inputs:

- The scheme version.
- The identity class. Headings, paragraphs, code, page headers, and page footers share the
  `text` class, so a heuristic that retypes unchanged text keeps its ID. Lists, tables, and
  figures each have their own class.
- The page number and the left and top position of the element's first page, rounded to
  whole points. Text-only pages use `0, 0`.
- The normalized content. A list contributes its ordered flag and item text, a table every
  cell, including rows on continuation pages, and a figure its alt text, caption, and
  rounded size. Normalization applies NFC, collapses whitespace runs to one space, and
  trims.

Converting the same file with the same loader and options gives the same IDs. An element
keeps its ID when an unrelated element is inserted without moving it, although its
`sourceIds` and `lineIds` change, because loaders count blocks and lines in page order. A
layout analyzer that retypes or reorders an element keeps its ID. A group keeps the ID of
its first member.

An ID is an anchor, not a checksum. The guarantee has these limits:

- Reflow, a different loader, or a segmentation change can move, split, or merge elements,
  which changes their IDs.
- A page inserted earlier changes the page number of every later element and so its ID.
- Furniture and continuation detection compare pages. Under page selection, an element
  keeps its ID only when its own segmentation and continuation decisions do not change.
- Whitespace edits inside code, image bytes, and moves of less than half a point do not
  change an ID. A position close to a half point can round differently in another engine
  version.
- Exact duplicates with the same class, page, position, and content get `-2`, `-3`, and so
  on, in document order. A duplicate has no individual stability promise, and neither has
  the very unlikely case of two different elements whose digests share 12 hex characters.
- Stable element IDs do not stabilize chunk membership or citation line IDs.

`parseDoctureDocument()` keeps IDs as saved. Documents from earlier releases have ordinal
IDs such as `p1-text-4`, which are not mapped to the new scheme. Convert the source again
to get the new IDs.

## Source lines

A line ID names one positioned loader line. The same loader with the same options yields
the same IDs during extraction and conversion. A line split into two columns contributes
its ID to both halves, so an ID resolves to the whole physical line.

### `sourceLines`

List a loaded page's positioned lines with their IDs.

```ts
sourceLines(page: Pick<LoadedPage, "pageNumber" | "lines">): readonly SourceLine[]
```

Returns one `SourceLine` per entry in `page.lines`, in order. Pages without positioned
lines, such as text-only inputs, return none.

### `isLineSourceId`

Check whether a string is a canonical line ID.

```ts
isLineSourceId(id: string): id is LineSourceId
```

Accepts only the canonical form, with page and line numbers from 1 and no leading zeros:
`isLineSourceId("p3-line-12")` is `true`, and `isLineSourceId("p3-text-12")` is `false`.

### `LineSourceId`

```ts check
type LineSourceId = `p${number}-line-${number}`;
```

`p<page>-line-<I>`, where `I` is the 1-based index into `page.lines`.

### `SourceLine`

One positioned line.

{/* options: SourceLine */}
| Field | Type | Meaning |
| --- | --- | --- |
| `id` | `LineSourceId` | The line's canonical ID. |
| `pageNumber` | `number` | One-based page number. |
| `box` | `LayoutBox` | Union of the line's spans. A line without spans has `{ x: 0, y, width: 0, height }`. |
| `text` | `string` | The loader's line text, verbatim. |

## Native element evidence

Native evidence records cite whole elements or table cells when the input has no
positioned lines, as in an [imported Docling document](/docs/integrations/docling-import).
They keep their actual granularity and text and never invent `TextLine` records.

`ConvertedPage.evidence` keeps native element and table-cell records in every output
format. Passing a conversion result directly to `chunkDocument()` keeps the same evidence
as chunking its saved JSON. Mixed native and OCR pages keep each untouched native page's
layout and source identity. Layout grouping keeps source IDs and updates their parent
element references. Field results keep line-only `citationSources` and native
`evidenceSources` separately.

### `SourceEvidence`

One native evidence record: an element record or a table-cell record.

| Field | Type | Meaning |
| --- | --- | --- |
| `granularity` | `"element" \| "table-cell"` | What the record cites. |
| `id` | `ElementSourceId \| CellSourceId` | The record's ID. |
| `pageNumber` | `number` | The display page. Physical placement is described only by `location`. |
| `elementId` | `string` | The element the record belongs to. |
| `text` | `string` | The cited text. |
| `order` | `number` | Stable source reading order, from `0`. |
| `location` | `EvidenceLocation` | Where the record sits. |
| `row`, `column` | `number` | Table-cell records only. Zero-based cell position. |
| `rowSpan`, `colSpan` | `number` | Table-cell records only. Cells covered, at least `1`. |

### `EvidenceSourceId`

```ts
type ElementSourceId = `p${number}-element-${string}`;
type CellSourceId = `p${number}-cell-${string}`;
type EvidenceSourceId = LineSourceId | ElementSourceId | CellSourceId;
```

Element and cell IDs end in 12 lowercase hex characters, such as `p2-cell-0a1b2c3d4e5f`.

### `isEvidenceSourceId`

Check whether a string is a canonical line, element, or cell ID.

```ts
isEvidenceSourceId(id: string): id is EvidenceSourceId
```

### `EvidenceLocation`

Where an evidence record sits.

```ts
type EvidenceLocation =
  | { readonly kind: "physical"; readonly pageNumber: number; readonly box: LayoutBox; readonly sourceDigest: string }
  | { readonly kind: "logical"; readonly pageNumber: number }
  | { readonly kind: "unlocated"; readonly pageNumbers: readonly number[] };
```

A `physical` location is a box on a page of a specific file, and its `sourceDigest` is
`sha256:` and 64 hex characters. A `logical` location names a page without a box. An
`unlocated` record lists the distinct pages it may span.

### `parseSourceEvidence`

Validate one untrusted evidence record, such as a saved extraction source.

```ts
parseSourceEvidence(value: unknown): SourceEvidenceParse
```

Returns a `SourceEvidenceParse`:

```ts
type SourceEvidenceParse =
  | { readonly ok: true; readonly source: SourceEvidence }
  | { readonly ok: false; readonly issues: readonly ValidationIssue[] };
```

Besides the schema, it requires an ID whose page matches `pageNumber`, a `location` page
equal to `pageNumber`, distinct positive pages for an unlocated record, a bound SHA-256
digest and a finite non-negative box for a physical record, and integer cell coordinates.
It does not throw for invalid input.
