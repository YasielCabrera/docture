These types describe the normalized elements that conversion produces and every output
format reads. Import them from `docture`. For a task-based introduction, see
[Preserve layout and tables](/docs/conversion/layout).

## Semantic layout

A `LayoutDocument` contains `LayoutPage` values, and each page contains `DocumentElement`
values in reading order. `ConvertedPage.elements` and `DoctureDocument.pages` hold the same
elements. The detection rules that create them are on separate pages:
[running headers and footers](/docs/conversion/reference/furniture),
[tables and merged cells](/docs/conversion/reference/tables), and
[cross-page continuations](/docs/conversion/reference/continuations).

### `LayoutPage`

One page of the normalized layout.

{/* options: LayoutPage */}
| Field | Type | Meaning |
| --- | --- | --- |
| `pageNumber` | `number` | One-based page number in the original document. |
| `width` | `number` | Page width in PDF points. |
| `height` | `number` | Page height in PDF points. |
| `elements` | `readonly DocumentElement[]` | Every element that starts on this page, in reading order. |
| `evidence` | `readonly SourceEvidence[]` | Native element and table-cell evidence, when the input provides it. See [native element evidence](/docs/conversion/reference/evidence#native-element-evidence). |

A page lists its running headers first and its running footers last, before the page
break.

### `DocumentElement`

The union of every element kind:

```ts
type DocumentElement =
  | HeadingElement
  | ParagraphElement
  | CodeElement
  | ListElement
  | TableElement
  | FigureElement
  | PageBreakElement
  | PageHeaderElement
  | PageFooterElement;
```

Every element has these fields:

- `id`, a string unique within the document. See [Element IDs](/docs/conversion/reference/evidence#element-ids).
- `provenance`, an `ElementProvenance` value for the page where the element starts.
- `kind`, the discriminant.

A switch over `DocumentElement["kind"]` must handle the two furniture kinds,
`page-header` and `page-footer`.

### `ListElement`

An ordered or unordered list.

{/* options: ListElement */}
| Field | Type | Meaning |
| --- | --- | --- |
| `kind` | `"list"` | Discriminant. |
| `id` | `string` | Element ID. |
| `provenance` | `ElementProvenance` | Source location. |

| `items` | `readonly { text; runs; marker? }[]` | One entry per item. `marker` keeps the original presentation marker for exact TXT output. |

### `TableElement`

A table. The [table detection rules](/docs/conversion/reference/tables) describe how rows,
header rows, and spans are found.

{/* options: TableElement */}
| Field | Type | Meaning |
| --- | --- | --- |
| `kind` | `"table"` | Discriminant. |
| `id` | `string` | Element ID. |
| `provenance` | `ElementProvenance` | Source location. A table that continues across a page break has `continuations`. |
| `rows` | `readonly (readonly string[])[]` | Cell text by row. Every row has one slot per column when `spans` is present. |
| `headerRows` | `number` | Leading rows that label columns, from `0` to `rows.length`. |
| `spans` | `readonly TableCellSpan[]` | Merged cells, sorted by row and then column. Absent when every cell is 1x1. |
| `rowProvenance` | `readonly ProvenanceSegment[]` | One segment per row, index-aligned with `rows`, with that row's page, line box, source IDs, and line ID. Present on tables built from positioned lines. |
| `sourceText` | `string` | The original loader lines, kept for exact TXT output. It includes a header row repeated at the top of a continuation page, which `rows` drops. |

`parseDoctureDocument()` rejects a saved table whose spans break the
[`TableCellSpan`](#tablecellspan) rules, and `rowProvenance` whose length differs from
`rows` or whose pages go back or fall outside the table's pages.

### `TableCellSpan`

A merged table cell.

{/* options: TableCellSpan */}
| Field | Type | Meaning |
| --- | --- | --- |
| `row` | `number` | Zero-based anchor row. |
| `col` | `number` | Zero-based anchor column. |
| `rowSpan` | `number` | Rows covered, at least `1`. |
| `colSpan` | `number` | Columns covered, at least `1`. |

The cell's text is in the anchor slot `rows[row][col]`, and every other slot it covers
holds `""`. Spans stay inside the grid, do not overlap, cover more than one cell, and never
cross the `headerRows` boundary. Rows have equal length when spans are present.

### `PageHeaderElement`

A running header. Markdown and HTML omit it. TXT and JSON keep it. The
[furniture detection rules](/docs/conversion/reference/furniture) describe when a line
becomes one.

{/* options: PageHeaderElement */}
| Field | Type | Meaning |
| --- | --- | --- |
| `kind` | `"page-header"` | Discriminant. |
| `id` | `string` | Element ID. |
| `provenance` | `ElementProvenance` | Source location. |
| `text` | `string` | Plain text. |
| `runs` | `readonly InlineText[]` | Text runs with link targets. |
| `evidence` | `FurnitureEvidence` | Why the line is furniture. |

### `PageFooterElement`

A running footer, such as a page number. It has the same fields as `PageHeaderElement`
with `kind: "page-footer"`.

{/* options: PageFooterElement */}
| Field | Type | Meaning |
| --- | --- | --- |
| `kind` | `"page-footer"` | Discriminant. |
| `id` | `string` | Element ID. |
| `provenance` | `ElementProvenance` | Source location. |
| `text` | `string` | Plain text. |
| `runs` | `readonly InlineText[]` | Text runs with link targets. |
| `evidence` | `FurnitureEvidence` | Why the line is furniture. |

### `FurnitureEvidence`

Why a line is page furniture.

```ts check
type FurnitureEvidence = "tagged" | "repeated";
```

`tagged` means the loader's structure tag marked the line. `repeated` means core inferred
it from text that repeats in the top or bottom band of several pages.

## Text and provenance

### `InlineText`

A run of text with an optional link target.

{/* options: InlineText */}
| Field | Type | Meaning |
| --- | --- | --- |
| `text` | `string` | The run's text. |
| `href` | `string` | The link target, when the run is a link. |

### `ElementProvenance`

Where an element came from. It extends [`ProvenanceSegment`](/docs/conversion/reference/chunk#provenancesegment)
with the later pages of a continued element.

{/* options: ElementProvenance */}
| Field | Type | Meaning |
| --- | --- | --- |
| `pageNumber` | `number` | The page where the element starts. |
| `box` | `LayoutBox` | The element's region on that page, in PDF points with a top-left origin. |
| `sourceIds` | `readonly string[]` | Stable IDs of the loader blocks or lines on that page. |
| `lineIds` | `readonly LineSourceId[]` | Canonical IDs of the positioned lines on that page. Absent when the page has no positioned lines. |
| `continuations` | `readonly ProvenanceSegment[]` | One segment per later page of a table or paragraph that continues across a page break, in page order, starting with the next page. Absent when the element is page-local. |

Read every page's share with [`provenanceSegments()`](/docs/conversion/reference/continuations#provenancesegments).
`parseDoctureDocument()` rejects continuations on other element kinds and continuations
that do not name the following pages in order.
