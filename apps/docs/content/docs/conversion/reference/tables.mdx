Conversion groups aligned rows into `table` elements, described in
[`TableElement`](/docs/conversion/reference/layout#tableelement) and
[`TableCellSpan`](/docs/conversion/reference/layout#tablecellspan). This page lists how
rows, header rows, and merged cells are detected and how each format renders them.

## Tables and merged cells

A label over two columns becomes a merged cell:

```ts
const result = await converter.convert(source, { format: "json" });
const table = result.pages[0]?.elements.find((element) => element.kind === "table");
console.log(table?.rows); // [["Item", "Quarters", ""], ["", "Q1", "Q2"], ["Alpha", "10", "20"]]
console.log(table?.headerRows); // 2
console.log(table?.spans); // [{ row: 0, col: 1, rowSpan: 1, colSpan: 2 }]
```

`rows` keeps one slot per column. A merged cell's text is in its anchor slot, and every
slot it covers holds `""`. Each format renders spans differently:

- HTML puts the `headerRows` rows in `<thead>` and writes `colspan` and `rowspan` on the
  anchor cell.
- Markdown has no merged cells. It flattens the header rows into one row and joins each
  column's labels with ` / `, as in `| Item | Quarters / Q1 | Quarters / Q2 |`. Covered
  body cells stay blank, so a value is never copied into another cell.
- TXT keeps the original source lines.
- JSON keeps `rows`, `headerRows`, and `spans`.

## Detection rules

Table detection is a heuristic.

- Rows with the same cell count at matching positions form a plain table without spans,
  with `headerRows: 1`.
- When counts differ, the first two or more matching rows set column bands from their
  horizontal extent. A following row with no more cells joins when each cell overlaps a
  band and no two cells claim one band. A totals row with fewer cells therefore stays with
  its table.
- Under both rules, an untagged row joins only when it starts within three times the
  median row spacing of the table's rows so far, measured from the row above.
- Under the band rule, a row more than 1.5 times that spacing below the row above starts a
  new section when it has fewer cells than the table or a different font weight from the
  row above. An example is `Booking ID` and `Payment Mode` labels under a `Check In`,
  `Check Out`, and `Rooms` table. The section and the rows above it become tables only if
  each is a table on its own.
- A row whose last-column value holds a digit and no letters, when that column's body
  cells hold digits, is a totals row and still joins. Every neighbouring pair of cells in
  such a row is at least one line height apart.

Merged cells and header rows follow these rules:

- A cell gets `colSpan: k` when it covers more than half of each of `k` bands that hold no
  other cell of its row.
- A cell of a bold first row over rows that are not all bold also gets `colSpan: k` when
  all of these hold: it lies within `k` contiguous bands, its centre is within 10% of
  their combined width from theirs, at least two rows follow, and the next row is within
  1.5 times their spacing. It must be neither a caption such as `Table 1` or `Table A` nor
  heading-size text. A bold label such as `Quarters` above `Q1` and `Q2` merges this way
  even when it overlaps neither.
- A lone line in that position leads the table only when the row below it is bold.
- The first row is a header. The next row is also a header while the row above it holds a
  column span and its cells sit under that span or under empty slots. Rows above the band
  rows join only as those header rows.
- `rowSpan` grows when the cell's box covers at least half the height of the next row's
  line and that row's slot is empty. It never crosses the header rows.

## Limits

- A centred line without bold type stays outside the table with a `LAYOUT_DEGRADED`
  warning that names its line, because it could also be a caption.
- A caption such as `Table 1` or `Table A`, heading-size text, or a line more than 1.5 row
  spacings above the table never merges.
- A row span needs a cell box that covers at least half of each row line. OCR or synthetic
  geometry can provide one. PDF text layers rarely do. An empty cell never makes a row
  span.
- Text layers that emit one span per word keep the plain table rule.
- A layout analyzer group that would produce an invalid table is ignored, and the tables
  stay separate.
- A table that runs over a page break follows the
  [continuation rules](/docs/conversion/reference/continuations#continuation-rules).
