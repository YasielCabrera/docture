---
title: Contracts
description: A schema with a document name and prompt guidance.
---

A `Contract` combines a schema with a document name. It may also contain a description
and hints.

```ts
const Invoice = contract({
  name: "invoice",
  description: "A commercial invoice.",
  hints: "Use the amount labelled Grand total.",
  schema: z.object({
    invoiceNumber: z.string(),
    total: z.number(),
  }),
});
```

## Worked examples

`examples` shows the model a piece of document text and the data it should yield. Each
`output` is typed by the schema, and the examples go with every text and vision prompt
for the contract.

```ts
const Invoice = contract({
  name: "invoice",
  schema: z.object({ invoiceNumber: z.string(), total: z.number() }),
  examples: [{ text: "Invoice INV-7. Total due: 1.234,50 EUR", output: { invoiceNumber: "INV-7", total: 1234.5 } }],
});
```

Examples cost input tokens on every request. See the
[contracts API](/docs/reference/api/core-contracts#examples) for serialization and checks.

## When the name is used

The contract name can appear in prompts, classification lists, and reports. When an
extractor has no configured classification list, a named contract is offered to the run
as a single classification candidate.

A bare schema works when no name is needed:

```ts
await extractor.extract("invoice.pdf", Invoice);
await extractor.extract("invoice.pdf", z.object({ total: z.number() }));
```

Both calls infer the result type from the schema.

## Structural contract

Contracts are not branded. Any object with a string `name` and a `schema` is a contract.

```ts
const Invoice: Contract<{ total: number }> = {
  name: "invoice",
  schema: z.object({ total: z.number() }),
};
```

`isContract()` performs this structural check. `schemaOf()` returns the inner schema or a
bare schema unchanged. `contractName()` returns the name when one exists.

## Convert a contract to a classification

```ts
const invoice = classificationOf(Invoice);
```

`classificationOf()` copies the contract name, description, schema, hints, and examples. Overrides
may add a per-kind extractor or a different extraction contract.

See [schemas and types](/docs/concepts/schemas-and-types) for schema support and the
[contracts API](/docs/reference/api/core-contracts) for signatures.
