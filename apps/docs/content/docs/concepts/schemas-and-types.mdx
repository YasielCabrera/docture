---
title: Schemas and types
description: How schemas guide extraction, infer result types, and validate data.
---

The same schema has three jobs:

- It names the fields to extract.
- It supplies the TypeScript type of `result.data`.
- It validates data returned by a strategy when the schema has a validator.

## Supported schemas

docture uses the AI SDK `FlexibleSchema` type. It accepts Zod, Valibot, ArkType, other
Standard Schema implementations, AI SDK schemas, and lazy schemas. To use JSON Schema in
the library API, wrap the object with `jsonSchema()` from `ai`:

```ts
import { jsonSchema } from "ai";

const Invoice = jsonSchema({
  type: "object",
  properties: { total: { type: "number" } },
  required: ["total"],
});
```

```ts
const Invoice = z.object({
  invoiceNumber: z.string(),
  total: z.number(),
});

const result = await extractor.extract("invoice.pdf", Invoice);
result.data.total; // number
```

## Field guidance

Use field names that match the document. Add descriptions for formats, labels, or
normalization rules that are not obvious from the name.

```ts
z.object({
  issuedAt: z.string().describe("Issue date in YYYY-MM-DD format"),
  total: z.number().describe("Grand total including tax"),
  purchaseOrder: z.string().nullable().describe("Null when no PO number is printed"),
});
```

Make a field nullable or optional when valid documents may omit it. Otherwise correct
partial data can fail validation.

## Validation

The pipeline validates each returned value before a strategy wins. Invalid data becomes a
failed strategy attempt. Another eligible strategy may then run.

```ts
result.validation;
// { valid: true, issues: [] }
```

A schema checks shapes, not cross-field facts. Add a validation rule for a fact such as
"the lines add up to the total". Rules report by default: the data comes back with
`validation.valid` set to `false` and the rule's issues. Pass `onRuleFailure: "fail"` to
fail the attempt instead. See [validation rules](/docs/reference/api/core-extraction#validation-rules).

```ts
const result = await extractor.extract("invoice.pdf", Invoice, {
  rules: [(invoice) => invoice.total >= 0 ? [] : [{ path: "total", message: "Negative total" }]],
});
```

If no strategy succeeds and at least one returned invalid data, docture throws the first
`ContractViolationError` with field paths and messages. If every strategy threw before
validation, it throws `ExtractionFailedError`.

The default `jsonSchema()` wrapper describes a shape but does not carry a validator.
docture therefore accepts the returned value unchanged after model generation. Supply a
validator to `jsonSchema()` or use a schema library with runtime validation when the
pipeline must check the result. The CLI wraps `.json` schema files without a validator and
prints a warning before extraction.

## Partial model requests

When long-document or per-page vision modes create more than one request, they remove
`required` from the JSON Schema sent with each fragment. The pipeline merges partial
values and validates the final result against the original schema.

See [long documents](/docs/guides/long-documents) for the merge behavior.
