---
title: Strategies
description: How extraction methods become eligible, run, and return data.
---

An extraction strategy turns a loaded document into unvalidated data. The pipeline
decides whether the strategy can run, validates its output, and records the attempt.

```ts
import { defineStrategy } from "docture";

const invoiceText = defineStrategy({
  name: "invoice-text",
  requires: ["TEXT_LAYER"],
  needsClassification: "none",
  async extract({ document }) {
    const text = document.pages.map((page) => page.text).join("\n");
    return { data: parseInvoice(text) };
  },
});
```

## Eligibility

`requires` lists facts about the loaded document. Core checks these facts at runtime
before calling `extract()`.

Common requirements are `TEXT_LAYER`, `GEOMETRY`, and `RENDERABLE_PAGES`. A model,
OCR engine, or cache is a component dependency, not a document fact. Pass those
dependencies to the strategy when you create it.

## Classification needs

`needsClassification` controls whether a strategy receives a classification result:

| Value | Behavior |
| --- | --- |
| `"required"` | The strategy runs only when classification produced a known name. |
| `"hint"` | The strategy can run with or without a known name. |
| `"none"` | Classification is not needed for this strategy. |

Core classifies only when at least one eligible strategy asks for it.

## Running and validation

Eligible strategies run in configured order. Returning data does not make a strategy
the winner. Core first validates that data against the requested schema.

If validation fails, the attempt is recorded and the next eligible strategy runs. A
strategy wins only when its returned data passes validation.

Throw when a strategy cannot produce an answer. There is no separate abstain value for
extraction because an empty object or array may be a valid result.

## Strategy context and outcome

`StrategyContext` contains the loaded document, computed document features, resolved
schema, optional classification, abort signal, and logger.

`StrategyOutcome` contains `data` and may include usage or a classification result. Core
normalizes usage and performs schema validation after the strategy returns.

See [routing and fallback](/docs/guides/routing-and-fallback) for ordering policies and
the [strategy API](/docs/reference/api/core-components) for signatures.
