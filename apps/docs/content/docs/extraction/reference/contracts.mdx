Contracts name a schema and add the prompt guidance a model uses; schema helpers resolve and validate any supported schema. Import them from `docture` or `docture/node`.

## Contracts

### `contract`

Names a schema and attaches a description, hints, and worked examples.

```ts
function contract<S extends FlexibleSchema>(
  definition: ContractDefinition<S>,
): Contract<InferSchema<S>>
```

```ts
const Invoice = contract({
  name: "invoice",
  description: "A supplier invoice.",
  hints: "Use the amount labelled Total due.",
  schema: z.object({ invoiceNumber: z.string(), total: z.number() }),
});
```

`contract()` copies the examples, so later edits do not reach the contract. Throws `TypeError`, naming the example and the path, when an example output contains a value JSON cannot carry. See [define schemas and contracts](/docs/extraction/schemas).

### `ContractDefinition`

The argument to `contract()`.

{/* options: ContractDefinition */}
| Field | Type | Meaning |
| --- | --- | --- |
| `name` | `string` | Required. Appears in prompts, classification lists, and reports. |
| `description` | `string` | Optional description of the document. |
| `schema` | `S` | Required. Any supported schema. |
| `hints` | `string` | Optional extraction guidance that precedes the examples in the system prompt. |
| `examples` | `readonly ContractExample[]` | Optional worked examples typed by the schema's output. |

### `Contract`

A named output contract. It stores a `FlexibleSchema<T>` with the same metadata as `ContractDefinition`.

```ts
interface Contract<T = unknown> {
  readonly name: string;
  readonly description?: string;
  readonly schema: FlexibleSchema<T>;
  readonly hints?: string;
  readonly examples?: readonly ContractExample<T>[];
}
```

Contracts are structural and are not branded. A hand-written `{ name, schema }` object is a contract.

### `ContractExample`

A worked example: document text and the data it should yield.

```ts check
interface ContractExample<T = unknown> {
  readonly text: string;
  readonly output: T;
}
```

`output` is typed by the schema's output type, so a wrong field or type does not compile, and examples never widen the type that `contract()` infers.

```ts
const Invoice = contract({
  name: "invoice",
  schema: z.object({ invoiceNumber: z.string(), total: z.number() }),
  examples: [
    { text: "Invoice INV-7. Total due: 1.234,50 EUR", output: { invoiceNumber: "INV-7", total: 1234.5 } },
  ],
});
```

#### Examples

Every text and vision extraction prompt for the contract carries its examples, including repairs. A vision prompt gets the text examples only; it sends no example images. Examples go in the system prompt after the hints, each as `<example>` holding `<input>` and `<output>`. An opening or closing `example`, `input`, or `output` tag inside the text or the JSON is escaped with a backslash. The escaping keeps the blocks intact but does not stop an example from reading as an instruction, so use only examples you trust.

Each example adds its text and JSON to every request, so it costs input tokens on every page or chunk. A changed example changes the request and gets its own cache entry.

`output` is sent as JSON. Plain objects, arrays, strings, booleans, `null`, finite numbers, and a valid `Date`, sent as its ISO string, are allowed. An `undefined` property is left out. Any other value, such as `NaN`, a function, a `Map`, or an object that contains itself, makes `contract()` throw a `TypeError`.

When an extraction starts, each example's JSON is checked against the schema as a model answer is. The check runs the schema, discards the transformed value, and sends exactly the JSON. An example that fails rejects the extraction with a `TypeError` before any request. A schema whose transform changes a value's type, such as a `string` to a `Date`, takes an example output of the transformed type, and its JSON must still be a valid input: `new Date("2024-03-05")` is sent as `"2024-03-05T00:00:00.000Z"`.

### `ContractLike`

Anything the extraction API accepts as an output contract.

```ts
type ContractLike = Contract | FlexibleSchema;
```

### `InferContract`

The data type that a contract or bare schema produces.

```ts
type InferContract<C> =
  C extends Contract<infer T> ? T : C extends FlexibleSchema ? InferSchema<C> : never;
```

### `isContract`

Returns `true` when `value` has a string `name` and a `schema`. It does not validate the schema.

```ts
function isContract(value: unknown): value is Contract
```

### `schemaOf`

Returns a contract's schema, or a bare schema unchanged.

```ts
function schemaOf<C extends ContractLike>(source: C): FlexibleSchema<InferContract<C>>
```

### `contractName`

Returns the contract name, or `undefined` for a bare schema.

```ts
function contractName(source: ContractLike): string | undefined
```

`isContract()`, `schemaOf()`, and `contractName()` do not throw for a bare supported schema.

## Schema types

### `FlexibleSchema`

The schema forms the AI SDK supports: Zod, Valibot, ArkType, and other Standard Schema implementations, lazy schemas, and AI SDK `Schema` objects. Re-exported from `@ai-sdk/provider-utils`.

```ts
type FlexibleSchema<T = any> = Schema<T> | LazySchema<T> | ZodSchema<T> | StandardSchema<T>;
```

Wrap a raw JSON Schema object with `jsonSchema()` from `ai` before passing it.

### `InferSchema`

The output type of a `FlexibleSchema`. Re-exported from `@ai-sdk/provider-utils`.

```ts
type InferSchema<S> =
  S extends ZodSchema<infer T> ? T
  : S extends StandardSchema<infer T> ? T
  : S extends LazySchema<infer T> ? T
  : S extends Schema<infer T> ? T
  : never;
```

### `resolveSchema`

Settles a schema once, before extraction, so strategies do not each await its JSON Schema.

```ts
function resolveSchema<T>(schema: FlexibleSchema<T>): Promise<ResolvedSchema<T>>
```

Rejects when a schema adapter cannot produce JSON Schema. A schema without a validator, including a plain JSON Schema wrapped by the AI SDK, accepts the returned value unchanged.

### `ResolvedSchema`

A schema with its JSON Schema and validator ready.

{/* options: ResolvedSchema */}
| Field | Meaning |
| --- | --- |
| `flexible` | Original `FlexibleSchema<T>`, kept for consumers that accept it directly. |
| `jsonSchema` | JSON Schema representation used in prompts and model calls. |
| `validate` | `(value: unknown) => Promise<ValidateResult<T>>`. Validates unknown data. |

### `JsonSchemaObject`

The object form stored in `ResolvedSchema.jsonSchema`.

```ts check
type JsonSchemaObject = Record<string, unknown>;
```

### `ValidateResult`

The result of `ResolvedSchema.validate()`.

```ts
type ValidateResult<T> =
  | { readonly ok: true; readonly data: T }
  | { readonly ok: false; readonly issues: readonly ValidationIssue[] };
```

## Validation in the pipeline

Strategies receive a `ResolvedSchema` and return unknown data. The pipeline calls its validator after each strategy returns. A validation failure records a failed attempt and lets the next strategy run.

The first strategy whose output validates becomes the result. If no strategy succeeds, the first validation failure takes precedence and extraction rejects with `ContractViolationError` and its `ValidationIssue` values. If every strategy threw before validation, extraction rejects with `ExtractionFailedError`. See [validate results and repair answers](/docs/extraction/validation).
