## Low-level pipeline

Most applications use `Extractor`. The following APIs expose the same stages for custom
composition.

```ts
runPipeline<T>(
  components: PipelineComponents,
  source: DocumentSource,
  schema: FlexibleSchema<T>,
  options?: RunOptions,
): Promise<ExtractionResult<T>>
```

`PipelineComponents` requires loader, strategy, classifier, and classification arrays,
a routing `policy`, and a `logger`. It may set `stageTimeoutMs` and classification
options. `RunOptions` is documented in [core extraction](/docs/extraction/reference/extractor).

`runPipeline()` resolves and loads the source, computes runtime features, classifies when
needed, routes strategies, validates returned data, and returns the first validated
result. It throws the typed failures listed in the [error reference](/docs/resources/errors).

```ts
readDocument(
  loaders: readonly DocumentLoader[],
  raw: RawDocument,
  logger: Logger,
  signal: AbortSignal,
  stageTimeoutMs: number | undefined,
  request?: LoadRequest,
): Promise<ReadDocument>
```

`ReadDocument` contains the loaded `document`, winning `loader`, and loader `attempts`.
The first accepting loader that succeeds wins. When all accepting loaders fail,
`LoadFailedError` carries their attempts.


## Share disposal ownership

`createDisposalScope()` returns a structural `DisposalScope`. Its `dispose(...components)` method calls each `ScopedDisposable` once in that scope and aggregates failures. Core pipelines and `withRasterizer` pass the same scope to owned children. Frozen resources are supported without replacing their methods. Create a new scope for a later independent ownership lifetime.

`withOcrFallback` composes a primary loader and explicitly selected OCR loader. `OcrFallbackOptions` requires a caller assessment and threshold. `PageOcrQuality` distinguishes intentional blanks from assessed content. `OcrFallbackWarning` explains per-page failures or rejected replacements. The [selected-page OCR guide](/docs/integrations/selected-page-ocr) defines replacement and warning behavior.

`RasterOptions.maxPages` caps the highest original page number before rasterization. Built-in PDF rasterizers apply it before allocating page images. Both OCR loaders forward their cap and omit total `pageCount` when the cap prevents them from establishing the original count. Selected pages retain their original numbers. A cap above the document length still reads the whole document.
