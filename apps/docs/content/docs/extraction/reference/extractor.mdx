`Extractor` composes loaders, classifiers, and extraction strategies and runs them on a document. Import it from `docture`, or from `docture/node` when you pass local file paths.

## Extractor

### `Extractor`

Owns registered components and defaults, and runs extraction, classification, and batches.

```ts
class Extractor implements DocumentExtractor {
  constructor(options?: ExtractorOptions);
  loadDocumentLoader(...loaders: readonly DocumentLoader[]): this;
  loadStrategy(...strategies: readonly ExtractionStrategy[]): this;
  loadLlm(backend: ModelBackend, options?: LoadLlmOptions): this;
  loadClassifier(...classifiers: readonly Classifier[]): this;
  loadClassifications(...classifications: readonly Classification[]): this;
  loadPolicy(policy: RoutingPolicy): this;
  loadLogger(logger: Logger): this;
  get components(): { loaders; strategies; classifiers; classifications };
  dispose(scope?: DisposalScope): Promise<void>;
  [Symbol.asyncDispose](): Promise<void>;
}
```

Every registration method returns the same extractor, so calls chain.

| Method | Effect |
| --- | --- |
| `loadDocumentLoader()` | Appends loaders. Registration order is the loader fallback order. |
| `loadStrategy()` | Appends strategies. Registration order is the routing order under `declarationOrder`. |
| `loadLlm()` | Registers `backend.extraction()`, plus `backend.vision()` and `backend.classifier()` when `LoadLlmOptions` asks for them. It checks every component before registering any, so a rejected call leaves the extractor unchanged. |
| `loadClassifier()` | Appends classifiers. |
| `loadClassifications()` | Appends default candidate document kinds. A call's `classifications` option overrides them. |
| `loadPolicy()` | Replaces the routing policy. |
| `loadLogger()` | Replaces the pipeline logger. |

`components` returns read-only copies of the current registrations. `dispose()` releases every loader, strategy, and classifier once; later calls return the same promise. See [batches and lifecycle](/docs/extraction/reference/batches) for `extractBatch()` and [classification](/docs/extraction/reference/classification) for `classify()`, `classifyTree()`, and `Extractor.flatten()`.

Throws `DuplicateComponentError` (`DUPLICATE_COMPONENT`) when a name is registered twice. `LLM` names its text strategy after the model id, so a second `loadLlm()` of the same model is a duplicate: pass `{ vision: true, classify: true }` in the first call, or give the second `LLM` a distinct `name`. `loadLlm()` throws `MissingComponentError` (`MISSING_COMPONENT`) when it requests a vision strategy or classifier that the backend does not provide. Used in [extract your first document](/docs/extraction/quick-start).

### `createExtractor`

Builds an `Extractor` from one options object.

```ts
function createExtractor(options: ExtractorOptions): Extractor
```

Equivalent to `new Extractor(options)`, except that it throws `MissingComponentError` when `loaders` is empty.

### `ExtractorOptions`

Constructor options for `Extractor` and `createExtractor()`.

{/* options: ExtractorOptions */}
| Option | Default | Meaning |
| --- | --- | --- |
| `sourceResolver` | portable resolver | Reads a `DocumentSource` into bytes. Use `resolveNodeSource` from `docture/node` for local files. |
| `loaders` | `[]` | Loaders in fallback order. |
| `strategies` | `[]` | Strategies in routing order. |
| `classifiers` | `[]` | Classifiers to run when classification is needed. |
| `classifications` | `[]` | Default document kinds. |
| `policy` | `declarationOrder` | Orders eligible strategies. |
| `logger` | `silentLogger` | Pipeline logger. |
| `stageTimeoutMs` | no deadline | Per-stage deadline. |
| `timeoutMs` | no deadline | Default deadline in milliseconds for each whole call: one extraction, classification, `classifyTree()` or batch item. |
| `classify` | `higherOrder`, threshold `0` | Classifier result selection. |
| `rules` | `[]` | Default `ValidationRule[]` for every call. Rules receive `unknown` data because one extractor serves many contracts. |
| `onRuleFailure` | `"report"` | Default `RuleFailureMode`. |
| `maxRepairs` | `1` | Default repairs per strategy. `0` disables repair. |
| `llm` | none | A `ModelBackend`, or `{ backend, vision?, classify? }`. Registered after `strategies` and `classifiers`, exactly as `loadLlm(backend, { vision, classify })`. |

### `ModelBackend`

The core interface that `loadLlm()` accepts. `LLM` from `docture/llm` implements it.

```ts
interface ModelBackend {
  readonly id: string;
  extraction(): ExtractionStrategy;
  vision?(): ExtractionStrategy;
  classifier?(): Classifier;
  splitter?(): Splitter;
  layout?(): LayoutAnalyzer;
}
```

See [model backend and factory](/docs/extraction/reference/models#model-backend) for `LLM`.

### `LoadLlmOptions`

Selects the extra components that `loadLlm()` registers.

{/* options: LoadLlmOptions */}
| Option | Default | Meaning |
| --- | --- | --- |
| `vision` | `false` | Also registers `backend.vision()`. |
| `classify` | `false` | Also registers `backend.classifier()`. |

### `DocumentExtractor`

The extraction interface that `Extractor` implements. Classifications and test doubles depend on it instead of the class.

```ts
interface DocumentExtractor {
  extractResult<C extends ContractLike>(
    source: DocumentSource,
    contract: C,
    options?: RunOptions<InferContract<C>>,
  ): Promise<ExtractionResult<InferContract<C>>>;
}
```

### `PipelineComponents`

The component collection that `runPipeline()` receives. `loaders`, `strategies`, `classifiers`, `classifications`, `policy`, and `logger` are required. Unlike `ExtractorOptions`, it has no `llm` shortcut or default `timeoutMs`; pass the whole-call deadline in `RunOptions`.

```ts
interface PipelineComponents {
  readonly sourceResolver?: SourceResolver;
  readonly loaders: readonly DocumentLoader[];
  readonly strategies: readonly ExtractionStrategy[];
  readonly classifiers: readonly Classifier[];
  readonly classifications: readonly Classification[];
  readonly policy: RoutingPolicy;
  readonly logger: Logger;
  readonly stageTimeoutMs?: number;
  readonly classify?: ClassifyOptions;
  readonly rules?: readonly ValidationRule[];
  readonly onRuleFailure?: RuleFailureMode;
  readonly maxRepairs?: number;
}
```

See [pipeline and disposal](/docs/extraction/reference/pipeline#low-level-pipeline).

## Extraction methods

### `extract`

Extracts `contract` from `source` and returns the full result.

```ts
extract<C extends ContractLike>(
  source: DocumentSource,
  contract: C,
  options?: RunOptions<InferContract<C>>,
): Promise<ExtractionResult<InferContract<C>>>
```

The type of `result.data` is inferred from the contract or schema. Rejects on source, loading, eligibility, strategy, validation, timeout, or caller abort failures; see the [error reference](/docs/resources/errors). [Inspect results](/docs/extraction/results) shows how to read the returned `ExtractionResult`, and [results API](/docs/extraction/reference/results) lists its fields.

### `extractResult`

An explicit alias of `extract()` with the same parameters and result.

### `extractData`

Returns only the validated data.

```ts
extractData<C extends ContractLike>(
  source: DocumentSource,
  contract: C,
  options?: RunOptions<InferContract<C>>,
): Promise<InferContract<C>>
```

Rejects on the same failures as `extract()`.

### `safeExtract`

Returns failures as values instead of rejecting.

```ts
safeExtract<C extends ContractLike>(
  source: DocumentSource,
  contract: C,
  options?: RunOptions<InferContract<C>>,
): Promise<SafeExtraction<InferContract<C>>>
```

### `SafeExtraction`

The outcome of `safeExtract()` and of each batch item.

```ts
type SafeExtraction<T> =
  | { readonly ok: true; readonly result: ExtractionResult<T> }
  | { readonly ok: false; readonly error: DoctureError | Error };
```

A thrown value that is not an `Error` is wrapped in one.

### `ExtractionResult`

The value that `extract()` returns: `data`, `method`, `loader`, `attempts`, `features`, `usage`, `validation`, and optional classification, conflicts, citations, and source identity. See [results API](/docs/extraction/reference/results#results) for every field.

### `RunOptions`

Per-call options for every extraction and classification method.

{/* options: RunOptions */}
| Option | Default | Meaning |
| --- | --- | --- |
| `signal` | new signal | Caller cancellation. |
| `pages` | all pages | 1-based page numbers to extract from a loaded document. |
| `stageTimeoutMs` | extractor default | Per-call stage deadline. |
| `timeoutMs` | extractor default | Deadline in milliseconds for the whole call. When it passes, every component's signal aborts, no fallback starts, and the call rejects with `TIMEOUT` at stage `"call"`. A caller abort keeps its own reason. |
| `onEvent` | none | A [`PipelineEventListener`](#pipelineevent) that receives `load`, `classify` and each finished `attempt` as they happen. |
| `only` | all strategies | Strategy names to use, in requested order. Unknown names are ignored. |
| `classifications` | extractor default | Per-call candidate kinds. |
| `classify` | extractor default | Per-call classification selection. |
| `logger` | extractor default | Per-call logger. |
| `rules` | extractor default | `ValidationRule<T>[]` typed from the contract. Replaces the extractor's rules. An empty array clears them. |
| `onRuleFailure` | extractor default, then `"report"` | `"report"` keeps the data and lists rule issues in `result.validation`. `"fail"` fails the attempt with `CONTRACT_VIOLATION` and tries the next strategy. |
| `maxRepairs` | extractor default, then `1` | Times to re-ask a strategy that implements `repair()` after its answer failed. Non-negative integer; other values reject with `INVALID_OPTION`. `0` makes one call per strategy. |

### `PipelineEvent`

What `onEvent` receives. Events arrive synchronously, in the order they happen.

```ts
type PipelineEvent =
  | { readonly type: "load"; readonly loader: string; readonly pages: number; readonly ms: number }
  | { readonly type: "classify"; readonly result: ClassificationResult }
  | { readonly type: "attempt"; readonly attempt: Attempt }
  | { readonly type: "page"; readonly pageNumber: number; readonly done: number; readonly total: number };

type PipelineEventListener = (event: PipelineEvent) => void;
```

- `load`: a loader read the document. `ms` covers the whole load stage, including loaders that failed first. A `LoadedSource` skips loading and emits none.
- `classify`: the classifiers reached this verdict. Extraction and classification only.
- `attempt`: an attempt finished. It is the same object that the call's `attempts` list holds, so an extraction reports failed loader attempts and every strategy attempt.
- `page`: layout analysis finished a page. Conversion only.

A listener that throws is logged as a warning and the call continues. Keep the listener
cheap, because the pipeline waits for it to return.

```ts
const result = await extractor.extract("invoice.pdf", Invoice, {
  onEvent(event) {
    if (event.type === "attempt") console.error(`${event.attempt.strategy}: ${event.attempt.status}`);
  },
});
```

### `RuleFailureMode`

How a failed validation rule affects an attempt.

```ts check
type RuleFailureMode = "report" | "fail";
```

`"report"` returns the data with its rule issues. `"fail"` fails the attempt.

### `ValidationRule`

A check that a schema cannot express, such as a total that equals the sum of its lines. It runs on schema-valid data.

```ts
type ValidationRule<T = unknown> = (
  data: T,
) => readonly ValidationIssue[] | Promise<readonly ValidationIssue[]>;
```

A rule that throws rejects the extraction. See [validate results and repair answers](/docs/extraction/validation).

## Check literal capability wiring

### `createCheckedExtractor`

Builds an `Extractor` and rejects, at compile time, literal wiring whose loaders cannot supply what every strategy requires.

```ts
function createCheckedExtractor<
  const L extends readonly DocumentLoader[],
  const S extends readonly ExtractionStrategy[],
>(
  options: Omit<ExtractorOptions, "loaders" | "strategies">
    & { readonly loaders: L; readonly strategies: S }
    & Compatibility<NoInfer<L>, NoInfer<S>>,
): Extractor
```

The check rejects a known nonempty loader tuple when every loader explicitly lacks a known required text, geometry, or image capability. Empty loader tuples are rejected. `withRasterizer` advertises image feasibility. Functional `llm`, `vision`, and `defineStrategy` retain their requirement literals.

The check covers advertised feasibility per fact. Actual document facts and eligible strategy diagnostics remain authoritative at runtime. Widened arrays, unknown booleans, custom facts, and widened requirements stay unchecked. Use the ordinary constructors for preloaded documents or intentional mixed fallback wiring.
