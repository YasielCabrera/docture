## Chunking

Import from `docture/llm/prompt`.

`Chunk` contains text and its 1-based page numbers.

```ts
type ChunkContext = (pageNumber: number) => string | undefined;

chunkByPage(document: LoadedDocument, context?: ChunkContext): Chunk[]
chunkByBudget(document: LoadedDocument, maxChars: number, context?: ChunkContext): Chunk[]
estimateTokens(text: string): number
```

`chunkByPage()` skips empty pages. `chunkByBudget()` splits only at page boundaries and
emits an oversized page whole. It returns no chunks for an empty document. A `context`
function returns text to place, followed by a blank line, before a chunk that starts on
the given page. `chunkByBudget()` counts that text against `maxChars`. `LlmStrategy` uses
it to repeat the header rows of a table continuing from an earlier page.
`estimateTokens()` returns `Math.ceil(text.length / 4)`.


## Partial results

Import from `docture/llm/merge`.

```ts
mergePartials(parts: readonly unknown[]): unknown
```

Arrays concatenate in document order. Plain objects merge recursively. For scalar or
mismatched values, the first non-null, non-undefined, non-blank value wins, except that
a later same-type non-zero value replaces an earlier `0` or `false`. A genuine early
zero can therefore be replaced. No usable parts returns `undefined`.

```ts
mergePartialsWithDiagnostics(parts: readonly MergePart[]): MergeDiagnostics
```

`MergePart` is `{ data, pages }`, with the 1-based pages the part came from.
`MergeDiagnostics` is `{ data, conflicts }`. `data` is exactly what `mergePartials()`
returns for the same data; `mergePartials()` is this fold without the pages.
`conflicts` lists each `ExtractionConflict` in order of first appearance: a field
`path` and every distinct present value with the pages that gave it. Strings compare
after trimming and numbers by value. A `0` or `false` replaced by a later value still
counts as one of the disagreeing values. A path where a scalar met an object or an
array also conflicts, and its values include that object or array. A literal key
`"a.b"` and the nested field `a.b` are separate paths, `` `a.b` `` and `a.b`, so they
never conflict with each other. Objects at one path
merge and arrays concatenate, so they never conflict with each other there. Values
inside arrays are never compared, because concatenated rows are separate records.
Absent values never conflict.


## Schema relaxation

Import from `docture/llm/relax`.

`JsonSchemaLike` is `Record<string, unknown>`.

```ts
relaxJsonSchema(schema: unknown): unknown
```

`relaxJsonSchema()` recursively removes `required` arrays and keeps schema properties
named `required`, including nested properties. It is used for partial model requests.
Core still validates the merged data against the original schema.
