Validation rules check facts a schema cannot express, and repair re-asks a strategy whose answer failed. Import these types from `docture` or `docture/node`. [Validate results and repair answers](/docs/extraction/validation) shows them in use.

## Validation rules

### `ValidationRule`

A check that runs after the schema accepts a strategy's data.

```ts
type ValidationRule<T = unknown> =
  (data: T) => readonly ValidationIssue[] | Promise<readonly ValidationIssue[]>;
```

A rule checks a fact the schema cannot express, such as line amounts adding up to the subtotal. All rules run, and their issues keep rule order. An empty array means the rule passed. Pass rules as `rules` in `ExtractorOptions` or `RunOptions`.

```ts
const result = await extractor.extract("invoice.pdf", Invoice, {
  rules: [(invoice) => invoice.lineItems.reduce((sum, line) => sum + line.amount, 0) === invoice.subtotal
    ? []
    : [{ path: "subtotal", message: "line items do not add up" }]],
});
result.validation; // { valid: false, issues: [...] } when the lines disagree
```

A rule that throws rejects the extraction with that error and does not try another strategy. A rule that returns anything other than an array of `{ path: string, message: string }` issues, such as `undefined`, rejects the extraction with a `TypeError` that names the rule, and does not try another strategy.

`extractBatch()`, `Process.extract()`, and classifications with their own extractor forward `rules`, `onRuleFailure`, and `maxRepairs` like every other run option.

### `RuleFailureMode`

How a rule issue affects the attempt.

```ts check
type RuleFailureMode = "report" | "fail";
```

In `"report"` mode, the default, the extraction returns the data with `validation.valid` set to `false` and the issues listed. In `"fail"` mode the attempt records `CONTRACT_VIOLATION` with the issues, and the next strategy runs. When every strategy fails, the extraction rejects with `ContractViolationError`, whose `failedCheck` is `"rule"` when the first violation came from a rule and `"schema"` when it came from the schema.

An `onRuleFailure` other than `"report"` or `"fail"` throws a `RangeError` from `createExtractor`, or rejects the call before any strategy runs.

### `ValidationIssue`

One problem with a field.

```ts check
interface ValidationIssue {
  readonly path: string;
  readonly message: string;
}
```

`path` is a [field path](/docs/extraction/reference/results#field-paths). Schema issues use `formatFieldPath()`; a rule writes its own paths.

## Repair

When a strategy's answer fails the schema, or a rule in `"fail"` mode, and the strategy implements `repair()`, the pipeline asks it again with the previous answer and the issues. It does so up to `maxRepairs` times per strategy, default `1`, before trying the next strategy. Report-mode rule issues never trigger a repair. A model response that does not parse into the schema (`MODEL_OUTPUT_FAILED`) is repaired from its complete text.

Repair calls are billed model requests, separate from the transport `maxRetries` of an LLM strategy, which only retries a failed request. A repair gets its own stage deadline, labelled `repair:<strategy>`. Caller cancellation during a repair rejects the run without fallback.

### `RepairInput`

What a repair is asked to fix. It is the second argument to `ExtractionStrategy.repair()`.

```ts
type RepairInput =
  | {
    readonly kind: "data";
    readonly data: unknown;
    readonly issues: readonly ValidationIssue[];
    readonly citations?: readonly OutcomeCitation[];
  }
  | { readonly kind: "model-output"; readonly rawOutput: string; readonly issues: readonly ValidationIssue[] };
```

`data` carries an answer the schema or a rule rejected, with the rejected outcome's citations when it had any. `model-output` carries the complete response text that did not parse; it is not truncated like `Attempt.rawOutput`.

### `Attempt`

Each repair is its own `Attempt` with `stage: "repair"` and its own `usage`, and `result.usage` counts every call once. The failed answer that led to it stays in `attempts` as a failed `extract` or `repair` attempt. See [results API](/docs/extraction/reference/results#attempt) for every `Attempt` field.
