These controls stop an extraction, bound how long each stage may run, log pipeline events, and release loaders and models when you finish. A missed stage deadline raises `TimeoutError`; [errors](/docs/resources/errors) lists its fields.

## Stop a run

Pass an `AbortSignal` to stop work owned by the caller:

```ts
const controller = new AbortController();

const pending = extractor.extract("invoice.pdf", Invoice, {
  signal: controller.signal,
});

controller.abort();
await pending;
```

A caller abort propagates and suppresses fallback. The pipeline does not start another
loader or strategy after cancellation.

## Set stage deadlines

During extraction, `stageTimeoutMs` applies to each loader, classifier, and strategy
stage:

```ts
const extractor = new Extractor({
  loaders,
  strategies,
  stageTimeoutMs: 30_000,
});
```

You may override it per extraction through `RunOptions`. A loader or strategy deadline
creates a failed attempt with `TIMEOUT`, then fallback continues. A classifier deadline
becomes an abstaining signal so the remaining classifiers can answer.

## Set a deadline for the whole call

`timeoutMs` bounds one call from start to finish, however many loaders and strategies it
tries. Set it on the extractor as a default, or per call:

```ts
const result = await extractor.extract("invoice.pdf", Invoice, { timeoutMs: 60_000 });
```

When it passes, every component's `signal` aborts, no further fallback starts, and the
call rejects with `TIMEOUT` whose `stage` is `"call"`. It rejects on time even when a
component ignores its signal. Each `extractBatch()` item has its own deadline.

## Report progress

`onEvent` receives a `load` event, a `classify` event, and each finished `attempt` as
they happen. See [`PipelineEvent`](/docs/extraction/reference/extractor#pipelineevent).

```ts
await extractor.extract("invoice.pdf", Invoice, {
  onEvent(event) {
    if (event.type === "load") console.error(`read ${event.pages} pages with ${event.loader}`);
  },
});
```

## Log pipeline events

The default logger is silent. Register `consoleLogger` or implement `Logger`:

```ts
const extractor = new Extractor()
  .loadLogger(consoleLogger());
```

Log fields contain component names, codes, ids, and timing data. Built-in components do
not log document content.

## Release resources

```ts
try {
  await runWork(extractor);
} finally {
  await extractor.dispose();
}
```

`dispose()` releases loaders, strategies, classifiers, workers, and model engines. It is
idempotent. If several components fail during disposal, docture waits for all of them and
throws an `AggregateError` containing every failure.

`Process.dispose()` releases its splitter and directly registered loaders. The extractor
passed to `loadExtractor()` is borrowed, so one extractor can serve several processes.
Dispose it through its owner after its last use.

## Scope disposal

`Extractor`, `DocumentConverter`, `Process`, composed raster loaders, and the OCR loader
classes support `Symbol.asyncDispose`. Node 22 or later can release their resources with
`await using`. Explicit `dispose()` remains available.

```ts
await using extractor = new Extractor({ loaders: [loader], strategies: [parser] });
await extractor.extract(source, schema);
```

Failed lazy page renders and engine initialization are retried on the next request.
Page images retain the eight most recently used successful renders per document.
