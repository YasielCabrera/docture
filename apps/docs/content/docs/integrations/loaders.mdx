A loader reads `RawDocument` bytes and returns a `LoadedDocument` with pages, text, optional line positions, and document facts. This page explains what loaders report and how an extractor picks one.

```ts
interface DocumentLoader {
  readonly name: string;
  readonly capabilities: LoaderCapabilities;
  load(document: RawDocument, ctx: LoadContext): Promise<LoadedDocument>;
  dispose?(): Promise<void>;
}
```

## Built-in loaders

| Loader | Input | Output |
|---|---|---|
| `DocumentLoaderData` | Text, Markdown, CSV, HTML, JSON, XML | Text |
| `DocumentLoaderPdfJs` | PDF | Text and geometry |
| `DocumentLoaderMuPdf` | PDF | Text and geometry |
| `DocumentLoaderTesseract` | PNG, JPEG, multi-page TIFF, and PDF with a rasterizer | OCR text, geometry, confidence, images |
| `DocumentLoaderPaddleOcr` | PNG, JPEG, multi-page TIFF with `utif2`, and PDF with a rasterizer | OCR text, geometry, confidence, images |
| `DocumentLoaderMammoth` | DOCX | Text on one logical page |
| `DocumentLoaderAzureRead` | PDF, PNG, JPEG, TIFF through Azure | Text and geometry |
| `DocumentLoaderDoclingServe` | PDF, DOCX, XLSX, PPTX, EPUB through docling-serve | Text and native element evidence |

`DocumentLoaderData` comes from `docture`. Import each other loader from its own subpath, such as `docture/loaders/pdfjs`. [Installation](/docs/getting-started/installation) lists the engine packages each adapter needs.

## Capabilities

`LoaderCapabilities` reports text, geometry, page-image support, accepted media types,
and optional custom facts.

```ts
new DocumentLoaderPdfJs().capabilities;
// {
//   text: true,
//   geometry: true,
//   images: false,
//   mimeTypes: ["application/pdf"]
// }
```

The boolean properties remain literal types. An API that accepts `GeometryLoader` or
`ImageLoader` can reject an incompatible loader during typechecking.

Strategy eligibility is a runtime decision. It uses facts found on the loaded document,
not only the loader's general capabilities.

## Loaded pages

Each page has a 1-based page number, dimensions in PDF points, and text. Geometry loaders
also return `TextLine` values with positioned `TextSpan` values.

Coordinates use a top-left origin. Lines are sorted from top to bottom and spans from left
to right.

`LoadedDocument.form` reports `digital`, `scanned`, `mixed`, or `unknown`. The loader name
appears in `result.loader`.

## Selection and failures

Docture filters loaders by media type, then tries them in declaration order. A later
loader runs only when an earlier eligible loader throws.

In an extraction result, `result.attempts` starts with the failed loaders, and the
successful loader appears only in `result.loader`. A conversion result also records the
successful load attempt. If every eligible loader fails, `LoadFailedError.attempts` contains all of their failures.

See [sources and inputs](/docs/getting-started/sources) for source forms and
[loader API pages](/docs/integrations/pdfjs) for options.

PDF.js and MuPDF parse and render on the main thread in Node. MuPDF yields between
pages, but individual engine calls still use that thread. Use a worker thread or a
separate process to isolate CPU work from a server request loop.
