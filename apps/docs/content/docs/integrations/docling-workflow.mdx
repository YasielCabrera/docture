Use Docling output as an extraction source. Your schema, validation rules, repair, and conflict reports work as with any other loader, and citations point to native Docling elements and table cells.

## Install

Install `docture` and the engines your extraction strategy uses. The importer and the service adapter need no Docling npm package.

```sh
npm install docture ai zod
```

## Extract from an existing Docling export

If you already have native JSON from Docling in Python or the official client, import it with `importDoclingDocument(nativeJson)` from `docture/import/docling`:

1. Pass the returned `source` to your configured extractor.
2. Pass the returned `document` to `chunkDocument()` from `docture/chunk` for retrieval.
3. Save `provenance` beside the JSON to look up native pointers later.

[Import Docling JSON](/docs/integrations/docling-import) lists the import options and what the import keeps.

## Extract through Docling Serve

Add `DocumentLoaderDoclingServe` from `docture/loaders/docling` to the `loaders` of your extractor or CLI config. Select `llm({ model, citations: true })` to verify field values against native element or table-cell text.

Use `DoclingServeClient` instead when you need the normalized JSON, diagnostics, the native sidecar, or a job reference. `submit()` returns a reference you can save, and `resume(reference).wait()` follows that task without another POST. An interrupted submission can have an unknown outcome, and aborting does not stop the remote job. [Connect to Docling Serve](/docs/integrations/docling-serve) covers the client and loader options.

## Review extractions with native evidence

Save CLI extractions with `--full --citations`. The result keeps `evidenceSources` beside the line-based `citationSources`. Open the review with the original file:

```sh
docture review --extraction result.json --source original.epub
```

The review shows native text and citation status without page images, and states when physical placement or page images are unavailable.

## Highlight evidence on original pages

Element and table-cell highlights need three things: known native units, the original bytes bound at import, and matching page images. Review rejects a source with a different digest before it draws overlays. Logical pages and multipage cells without a location have no physical box. A matching JSON digest does not prove that a PDF supplied separately was the original source.

## Run the example

The repository example in [`apps/examples/18-docling`](https://github.com/YasielCabrera/docture/tree/main/apps/examples/18-docling), `index.ts`, runs against a local mock service. From a clone of the repository, run:

```sh
pnpm --dir apps/examples exec tsx 18-docling/index.ts
```

The example imports real Python export fixtures, extracts two document kinds with different schemas, and saves conversion and provenance files that share one native digest. Its mock service and model need no credentials.

## Choose between Docture and the official client

Docture's service adapter covers a bounded subset of the docling-serve protocol. Keep the official Docling client when you need its other artifacts, storage, or native chunking, and pass its native JSON to `importDoclingDocument`.
